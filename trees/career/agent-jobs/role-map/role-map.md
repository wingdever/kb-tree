# Agent 岗位地图

“Agent 开发工程师”只是入口词。招聘方可能要的是应用交付、平台运行时、后端集成、评测体系或研究型算法；同名岗位的职责差别，往往比不同公司之间的差别更大。

## 常见标题

- **Agent 开发工程师**：最常见的应用侧标题，做循环、工具、记忆、RAG 与产品集成。
- **LLM 应用工程师 / AI 应用工程师**：范围更宽，可能包含 Agent，也可能以单次调用与工作流为主。
- **Agent 平台工程师**：做运行时、工具注册、协议、多租户、可观测与托管。
- **RAG 工程师**：偏知识摄取、检索、重排与评测，Agent 是使用方之一。
- **AI 工程架构师**：跨应用、平台与基础设施，负责边界与长期演进。
- 相邻岗位还有后端工程师、机器学习工程师、AI Infra 工程师；它们可能承担 Agent 的一部分，但考核重点不同。

## 职责矩阵

| 方向 | 主要交付 | 核心能力 |
|---|---|---|
| 应用型 | 可用的 Agent 产品 | 循环、工具、记忆、RAG、产品迭代 |
| 平台型 | 别人用来搭 Agent 的底座 | 运行时、协议、隔离、可观测、规模化 |
| 后端型 | Agent 背后的服务与数据 | API、队列、存储、权限、并发 |
| 评测型 | 可比较的质量与回归 | 黄金集、指标、失败分析、数据标注 |
| 研究型 | 新的规划与自我修正方法 | 实验设计、模型行为、训练与推理 |

## 级别差异

- **初级**：能在既有框架里完成一个明确模块，能复现问题、写清文档。
- **中级**：能独立负责一条链路，能定位工具失败、检索失败与提示退化。
- **高级**：能设计系统边界、评测体系与成本模型，能带人拆解模糊需求。
- **资深/架构**：能跨团队定义接口与治理，能判断什么时候不该做 Agent。

级别不是按年限自动对应；能否独立定义问题、证明效果、控制风险，才是分水岭。

## 真假 Agent 判断

看五个特征：有没有状态、有没有工具调用、有没有多步循环、有没有失败处理、有没有评测。只有“提示词 + 单次模型调用”的岗位，通常不是 Agent 开发；只有框架调用、没有系统设计与评测的岗位，成长空间也有限。

## 一句话主线

先看职责矩阵，再看级别；标题里的“Agent”不如五个特征可靠。
