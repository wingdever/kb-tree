# 选岗与尽调

拿到 Offer 不是终点。同样的“Agent 开发”标题，可能是核心产品团队，也可能是没有数据、没有预算、没有评测的概念项目。选岗要判断需求真假、资源是否到位、成长是否可持续。

## 真需求判断

- 产品有没有真实用户、付费或内部强使用场景。
- Agent 是否解决了单次调用或普通工作流解决不了的问题。
- 团队能不能说清失败模式与验收标准，而不是只说“效果要好”。
- 项目是新增能力，还是把现有功能换个名字。

## 团队与资源

- 有没有后端、数据、评测、运维伙伴；一个人是否要同时做模型、数据、平台和值班。
- 数据是否合法可得，权限与脱敏怎么做。
- 有没有模型预算、向量库、日志与 trace；没有预算的 Agent 项目很难上线。
- 上线后的值班、告警、回滚与人工接管由谁负责。

## 成长与路径

- 你负责的是模块、链路还是系统；能不能接触评测、成本与架构。
- 团队有没有代码评审、技术讨论与复盘；还是只赶项目。
- 晋升路径是技术专家、架构还是管理；公司是否有对应岗位。
- 项目结束后你留下什么可复用的能力与作品。

## 薪酬与合同

- 现金、奖金、股权、补贴、社保与公积金分开看；股权要问归属、行权、回购与税务。
- 试用期长度、转正条件、竞业限制、知识产权归属、保密范围要写清。
- 远程或海外岗位要确认合同主体、支付币种、税务与签证责任。
- 不要只看名义总包；城市成本、加班强度与稳定性都算总回报。

## 红旗

- JD 只有“熟悉大模型/Agent”，没有职责与验收标准。
- 没有数据、没有预算、没有评测，却要求“做出爆款”。
- 面试全程不谈失败，只谈愿景。
- 无偿大作业、试用期过长、股权口径模糊。
- 团队高流动、汇报关系频繁变化、项目没有负责人。

## 反问清单

1. 这个 Agent 现在服务谁，指标是什么？
2. 团队里谁负责数据、评测、后端与运维？
3. 模型与检索的预算大概是什么量级？
4. 上线后出问题谁值班，怎么回滚？
5. 这个岗位半年后最重要的交付是什么？

## 一句话主线

选岗不是选标题，是选“真需求 + 真资源 + 真成长”；三者缺一，薪资很难弥补。
