# Agent 开发能力栈

Agent 开发的门槛不在“会调哪个框架”，而在能不能独立把一条链路搭起来、证明它可用、并在失败时定位原因。核心能力是通用的，框架只是表皮。

## 核心能力

- **语言与后端**：Python 或 TypeScript 熟练；能写 API、异步任务、队列、缓存、数据库与权限。
- **模型接口**：理解 chat completions、流式输出、工具调用、结构化输出、上下文长度与计费口径。
- **提示与上下文**：能把任务、约束、示例、工具说明组织成稳定的上下文，而不是堆一大段咒语。
- **工具调用**：能设计工具 schema、处理参数校验、超时、重试、幂等与失败回退。
- **检索**：理解切块、嵌入、向量索引、BM25、混合检索与重排，能判断什么时候不该用 RAG。
- **评测**：能建黄金集、定义指标、做回归与失败分类；没有评测，调优只是碰运气。
- **调试与可观测**：能看 trace、定位是模型、提示、工具还是数据的问题；能记录成本、延迟与成功率。
- **安全与成本**：知道权限、注入、数据泄露、工具越权与调用预算的边界。

## 加分项

- 框架：LangGraph、LlamaIndex、CrewAI、AutoGen 等，知道它们的边界比会调用更重要。
- 协议：MCP、A2A、OpenAI/Anthropic 工具调用格式的差异。
- 多 Agent：任务分解、角色分工、冲突消解与成本放大。
- 图与结构化检索：知识图谱、Text-to-SQL、语义层。
- 训练：微调、偏好优化、RL 的基本判断；多数岗位不要求，但能帮助你理解模型行为。
- 基础设施：容器、队列、向量库、可观测平台与多租户隔离。

## 证据等级

1. **真实交付过的 Agent**：有用户、有指标、有失败处理。
2. **可复现的评测报告**：同一任务上的对比、失败分类、成本与延迟。
3. **可读的代码与文档**：别人能跑起来，能看懂设计取舍。
4. **课程证书与框架熟练度**：只能证明接触过，不能证明能做。

求职时按这个顺序组织证据，不要把证书放在最前面。

## 学习路径

先做一个最小 Agent：一个目标、两个工具、一个循环、一套失败回退。再补评测：固定任务集、通过率、平均步数、成本与延迟。然后做一次失败分析：哪类问题反复出现，改了哪一处，指标有没有变。最后把过程写成可读的项目文档。

## 一句话主线

核心能力是“搭起来、测出来、修得动”；框架会换，这三件事不会。
