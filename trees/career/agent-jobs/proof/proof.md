# 作品集与简历

作品集回答“你做过什么、怎么证明”，简历回答“为什么这份岗位值得给你面试”。两者都不是经历清单，而是证据的索引。能力栈再熟，没有可核验的交付，也很难通过项目深挖。

## 作品集结构

2–3 个项目足够，不追求数量：

- **旗舰 Agent**：有明确目标、工具调用、多步循环、失败回退与评测。
- **检索或评测项目**：证明你会处理知识、衡量效果，而不是只会调模型。
- **工程或平台项目**：证明你能把东西跑稳，例如工具网关、可观测、成本控制、权限隔离。

每个项目都要能在一页内说清：问题、约束、架构、关键取舍、失败案例、指标与代码位置。

## 每个项目写什么

- **问题与用户**：谁遇到什么问题，为什么需要 Agent，而不是单次调用或普通工作流。
- **约束**：数据权限、延迟、成本、并发、合规边界。
- **架构**：循环、状态、工具、记忆、检索、模型与运行时如何组合。
- **失败与修复**：工具参数错、检索空召回、模型跑偏、成本失控时怎么发现、怎么回退。
- **指标**：任务成功率、平均步数、P95 延迟、单任务成本、人工接管率。
- **证明**：仓库、README、演示、评测脚本；敏感数据要脱敏。

## 简历写法

- 一页优先，按岗位定制；把最相关的项目放最前。
- 每条经历写“做了什么 + 怎么衡量 + 结果”，避免只写“负责 Agent 开发”。
- 关键词要与 JD 对齐：Agent、工具调用、RAG、评测、可观测、成本、权限；但不要堆砌不熟悉的词。
- 不写“精通”，写能证明的边界：用过什么规模、处理过什么失败、指标到什么程度。
- 面试前准备两个失败故事：一个技术失败，一个协作或取舍失败。

## 常见错误

- 只有框架名，没有系统设计与评测。
- 指标没有基线，或者数字无法解释。
- 项目不能运行，代码或 README 缺失。
- 把团队成果写成个人成果，项目深挖时说不清自己做了什么。
- 简历写满关键词，但每个都只能答一句。

## 一句话主线

作品集证明“做过”，简历证明“匹配”；两样都要能经受追问。
