# Agent 开发岗位求职

找 Agent 开发岗位，不是把简历投出去，而是把“我能做 Agent”变成可验证的证据，再找到愿意为这类证据付费的团队。岗位名称、团队阶段与面试重点差异很大，先判断市场，再决定准备什么。

## 市场

先看谁在招、为什么招。模型实验室、AI 应用公司、云与平台厂商、企业 AI 部门、传统行业数字化团队、外包与咨询，对“Agent 开发”的定义并不相同。招聘信号要看产品阶段、团队规模、数据与算力预算，而不是只看标题。

## 岗位地图

常见标题包括 Agent 开发工程师、LLM 应用工程师、AI 应用工程师、Agent 平台工程师、RAG 工程师。同名岗位可能分别偏应用、偏平台、偏后端或偏评测；判断时看职责里有没有状态、工具、循环、失败处理与评测，而不是看有没有“Agent”这个词。

## 能力栈

核心是能独立把一条 Agent 链路搭起来并证明它可用：语言与后端、模型 API、提示与上下文、工具调用、RAG、评测、调试、成本与延迟、安全边界。框架与多 Agent 是加分项，不是替代品。

## 证据

作品集与简历是把能力变成可核验证据的载体。一个可运行的项目、一份评测报告、一段失败分析，比“熟悉 LangChain”更有说服力。简历是证据的索引，不是愿望清单。

## 渠道

官网、内推、招聘平台、GitHub 与社区、猎头、行业活动都能用，但优先级不同。内推提高的是被看见的概率，不替代匹配；平台扩大的是数量，不保证质量。

## 面试

面试通常分筛选、代码、Agent 基础、系统设计、项目深挖与行为面。重点不是背概念，而是能解释你的 Agent 为什么这样设计、失败时怎么发现、成本与延迟怎么控制。

## 选岗

拿到机会后要判断：是真需求还是概念项目，团队有没有数据与算力，评测与文化是否成熟，成长路径与薪酬结构是否匹配。标题相同，风险可能完全不同。

## 计划

求职是一个有漏斗的短周期项目：定目标、补证据、投递、面试、复盘、谈判。用周节奏推进，记录每一轮的转化率与失败原因，而不是无限投递。

## 一句话主线

先证明能做，再找对买家；简历是证据的索引，不是愿望清单。
