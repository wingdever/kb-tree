# 协作办公生态

协作办公平台把即时消息、文档、日历、会议、审批与多维表格放进一个工作台。它们有成熟的开放平台与机器人体系，但产品定位是**企业协作套件**，不是消费级 IM——IM 只是其中一个模块。

## 平台对照

| 平台 | 重心 | 开放能力 | 边界 |
|---|---|---|---|
| 飞书 | 文档、知识与项目协作 | 开放平台提供大量接口与事件，机器人、网页应用、事件订阅，富交互消息卡片 | 以公有云为主；私有化需按版本单独确认 |
| 钉钉 | 组织管理与流程办公 | Stream 模式、群机器人 Webhook、审批与低代码接入 | 标准版公有云；专属版为混合云，不是整套服务端进机房 |
| 企业微信 | 连接微信客户与内部协作 | HTTP 回调、客户联系、通讯录、群与小程序能力 | 价值在微信生态触达；对外沟通不可替代 |
| Notion / Obsidian 类 | 知识组织与个人笔记 | API、插件、本地 Markdown 文件 | 非实时 IM，偏知识与文档沉淀 |

## Agent 接入方式

- **官方开放平台**：创建应用拿凭证（App ID / App Secret、AppKey / AppSecret 等），通过事件订阅或 Webhook 收消息，用发消息 API 回复。
- **机器人形态**：群机器人.Webhook 适合通知类单向推送；完整应用机器人支持私聊、群聊、交互卡片。
- **审批与权限**：企业应用通常需要管理员审核与授权范围配置，个人开发者受限于企业身份。
- **数据边界**：文档、消息与文件默认在平台云上；数据不出内网的需求要单独确认部署方案，不能把 SaaS 版功能表当私有化交付清单。

## 与 IM 子生态的边界

- `../im/` 关注**消费级 IM**：身份是官方机器人或真人号，核心问题是封号风险、开放接口与会话边界。
- 本子生态关注**企业协作套件**：身份是组织内应用，核心问题是审核、权限分级、文档与流程联动、数据落点。
- 两者都可作为 Agent 渠道，但选型前提不同：前者看「人是否在那里」，后者看「组织流程是否在那里」。

## 一句话主线

**协作办公生态提供的是「组织内的合规通道」：开放平台成熟、机器人与事件齐全，但审核、数据边界与套件重量决定它不是消费级 IM 的替代品。**
