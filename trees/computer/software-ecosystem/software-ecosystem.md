# 软件生态

软件生态研究**软件平台如何成为可承载 Agent 与自动化服务的环境**：平台给谁身份、开放什么接口、提供什么扩展机制、数据落在哪里、谁承担治理责任。本域按子生态展开；IM 是其中第一个成形的子生态。

## 为什么独立成顶层域

平台生态的共性问题横跨多个软件：身份怎么来、接口开放到什么程度、扩展机制怎么设计、事件与数据怎么建模、治理责任谁承担。这些不绑定某个 Agent 框架，放在 `ai/agent/` 下会被渠道实现细节遮蔽；放在这里可以按「人、代码、流程、数据」分别成域。

## 观察维度

| 维度 | 要解决什么 |
|---|---|
| 身份体系 | 官方机器人、真人账号、开发者账号；权限、实名、审核与封号风险 |
| 开放接口 | API、SDK、Webhook / 事件订阅、频率限制 |
| 扩展机制 | 插件市场、语言服务器、Skills、Hooks、MCP、配置约定 |
| 数据与制品 | 代码仓库、文档、会话历史、向量索引、消息留存 |
| 部署形态 | 公有云、自托管、混合云、多端同步 |
| 治理与合规 | 审计日志、权限分级、数据边界、平台规则 |

## 子生态全景

| 子生态 | 核心问题 |
|---|---|
| IM | 人、机器人与 Agent 在同一会话中的身份、接口、消息模型与治理 |
| Agent | Agent 作为软件品类：厂商、harness、框架、协议栈、分发与治理 |
| 开发工具与 IDE | 编辑器、扩展市场、语言服务器、编码 Agent 与 Skills / MCP / Hooks 扩展包 |
| 协作办公 | 企业协作套件的开放平台、机器人、事件订阅与数据边界 |
| 代码托管与开源协作 | 仓库、PR / Issue、CI 与 Agent 的代码评审和提交流程 |
| 云原生与 DevOps | 容器、编排、CI/CD、基础设施即代码与可观测性 |
| 浏览器 / Web 平台 | 浏览器扩展与 Web API 作为 Agent 的触达面 |
| 操作系统 / 桌面 | 桌面与移动系统对 Agent 的权限、文件系统与自动化边界 |
| 数据与知识 | 从向量库到 Agent 化知识平台：存储、检索、记忆与交付 |

## 按目标找子生态

- 要**接人**——让 Agent 在聊天窗口里被人使唤 → IM 或协作办公。
- 要**接开发者工作流**——让 Agent 在编辑器与终端里干活 → 开发工具。
- 要**接代码资产**——让 Agent 读仓库、提 PR、跑评审 → 代码托管。
- 要**接运行与部署**——让 Agent 构建、发布、观测 → 云原生与 DevOps（未展开）。
- 要看**Agent 作为软件品类**的版图与治理 → Agent 子生态。

## 一句话主线

**软件生态按「人在哪、代码在哪、流程在哪、数据在哪」划分子生态；每个子生态都用身份、接口、扩展机制与治理四个维度观察。**
