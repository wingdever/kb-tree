# 数据与知识生态

> 来源：各平台官方文档与 2026 年生态资料。能力变化快，以官方文档为准。

数据与知识生态回答「Agent 的记忆和外知落在哪、怎么被取用」。它分两端：**底层**是结构化数据、向量库、检索索引；**应用层**是把知识做成可直接对话与交付的平台。底层机制在 `../../ai/rag/`（尤其 `../../ai/rag/vdb/`、`../../ai/rag/memory/`），本页聚焦平台层。

## 观察维度

| 维度 | 底层问题 | 平台层问题 |
|---|---|---|
| 存储 | 向量索引、结构化表、元数据 | 知识库、收藏、笔记、知识号 |
| 取用 | 相似度检索、混合检索、重排 | 按任务选语义/关键词、限定文件与时间范围 |
| 记忆 | checkpointer、长期记忆文件 | 用户档案、长期记忆、经验积累 |
| 交付 | 检索块拼上下文 | 报告、表格、可下载材料 |
| 治理 | 权限、隔离、新鲜度 | 内部资料 vs 公开网络的来源区分 |

## 平台条目

| 平台 | 形态 | 入口 |
|---|---|---|
| **ima（腾讯）** | AI 知识库工具，2026 年 Agent 化为 copilot；个人知识管理 + 知识号分发 | `ima/ima.md` |

## 竞品与相邻赛道

按「是否同一生态位」分组，避免把不同层的方案拉平比较。

### 直接同类：消费级 AI 知识平台

共同点是「存资料 → 按资料回答 → 交付成果」；差异在 grounding 强度、记忆与分发。

| 产品 | 与 ima 相似 | 差异 |
|---|---|---|
| **NotebookLM**（Google） | 上传 PDF / 网页 / 视频，严格基于来源回答并带引用；Audio Overview 多形态输出 | 偏资料深读与项目研究，不是长期个人知识库；无 Skill 分发 |
| **Perplexity Spaces** | 资料 + 联网混合检索，带引用 | 开放网络为主；ima 联网需显式授权 |
| **Notion AI** | 知识库 + 数据库 + Agent，跨页汇总与自动执行 | 强在团队协作与结构化，引用不如 source-locked 严格 |
| **飞书知识问答 / 智能伙伴** | 企业知识库内问答、总结与信息流转 | 绑组织协作与权限，不是个人知识沉淀 |
| **Mem.ai** | 低摩擦捕获、AI 自动关联与整理 | 偏个人笔记流，缺 Skill 体系 |
| **ChatGPT / Claude Projects** | 项目级知识、长文档分析 | 更通用灵活，引用较松，本身不是知识库产品 |
| **AnythingLLM** | 文档上传 + 检索 + 对话，可自托管 | 面向隐私与自建，不是消费级服务 |
| **Obsidian + AI 插件** | 本地 Markdown + 向量检索（如 Smart Connections） | 给人读的 PKM，需自行配置，数据完全自主 |

ima 的差异化：**四层记忆（设定 / 用户档案 / 长期记忆 / 经验）+ Skill 广场 + 知识号分发**，从存知识走到用知识交付，并带内容生态。

### 相邻层：企业 RAG 框架

这是「搭系统」而非「用产品」，与 ima 不在同一生态位：Dify（可视化编排 + 插件市场 + 知识流水线）、RAGFlow（DeepDoc 复杂文档解析）、FastGPT / MaxKB / Coze（知识问答与 Agent 应用）、WeKnora / Yuxi（国产 MIT 开源、RAG + 图谱 + 私有化）。

### 相邻层：AI 记忆层

给 Agent 加跨会话记忆，供开发者集成而非终端用户直接使用：Mem0（接入最快、框架无关）、Zep（时序事实 + 合规）、Letta（Agent 自编辑记忆块）、LangMem（LangGraph 原生、含程序记忆）。机制见 `../../ai/rag/memory/`。

### 相邻层：个人 PKM

给人读而非给 AI 读：Obsidian（插件生态最繁荣、核心闭源）、Logseq（开源大纲式）、Roam Research（双链鼻祖）、思源笔记（中文块笔记、本地 + 可选云）。与 AI 记忆层范式不同，不要混为一谈。

## 共享维度

「和他人共享」分两种本质不同的形态：**组织内熟人协作**（多人写、有权限）与**陌生人之间的公域订阅**（创作者发布、他人订阅或付费）。两者不要混为一谈，再看面向 Agent 的机器共享。

### 组织内协作共享（多人写、有权限）

| 产品 | 共享与权限 | 适合 |
|---|---|---|
| **Notion** | 页面级共享，高级权限可限制到个人或团队；默认全公司可见、可按需收窄 | 5–100 人初创 / 出海团队，All-in-One |
| **飞书知识库** | 与 IM 打通，权限可精确到单篇只读或打印限制 | 10 人–万人，国内企业首选 |
| **语雀** | 团队分组 + 单篇权限，目录像书一样编排 | 5–500 人技术团队 |
| **Confluence** | 空间 / 页面 / 字段级权限，支持 Data Center 私有化 | 200 人以上中大型研发团队 |
| **SharePoint** | 与 Microsoft 365 绑定，私有化能力强 | 大型企业 / 政企 |

选型核心是**别跨办公生态**：用飞书就飞书、用 M365 就 SharePoint、用 Atlassian 就 Confluence。

### 公域订阅：创作者发布、他人订阅

这是**陌生人之间**的知识共享，不是组织协作。典型是 ima：知识号把整理好的资料发布到「知识库广场」，他人发现、订阅、直接基于库问答，订阅者不占自己空间。

ima 有四种库，意义不同：

| 类型 | 谁建 | 谁能用 |
|---|---|---|
| 个人知识库 | 个人 | 自己 |
| 共享知识库 | 个人 / 团队 | 定向共享，适配协作与项目研究 |
| **订阅知识库** | 知识号 | 公域广场可搜索，公开订阅 |
| **付费订阅** | 知识号（需内测资格） | 付费后 365 天访问全部内容 + AI 问答 |

付费订阅内测期平台抽成 1%；发现路径三种：分享链接 / 二维码、知识库广场搜索、知识号主页。广场已覆盖科技、金融、教育、医疗、法律、政务，入驻方包括巨潮资讯网、杭州海关等机构。本质是**公域知识分发平台**：创作者把知识变成可订阅产品并变现，订阅者获得「不用自己整理就能问答」的库。

同类形态：

| 产品 | 分发什么 | 特点 |
|---|---|---|
| **GPTs / Custom GPTs 商店** | 公开 Agent + 知识包 | 他人直接使用，能力随包分发 |
| **Notion 模板 / 公开页市场** | 模板与页面 | 偏内容分发，不是可问答的知识库 |
| **Coze / Dify Agent 市场** | 可直接调用的 Agent | 能力与知识一起分发 |
| **NotebookLM 分享** | notebook | 可分享，但不是持续协作的内容生态 |

与「组织内协作」的区别：**前者是陌生人之间的公域订阅，后者是组织内的熟人协作**。Notion 公开页、Dify 发布 web app / API 属于「能力对外暴露」，放在面向 Agent 一节更合适。

### 面向 Agent 的共享（不是「人共享文档」）

- **AG-UI shared state**：Agent 与应用之间的类型化共享状态，带事件源 diff 与冲突解决。
- **MCP server**：把工具 / 数据源暴露成标准接口，供多个 Agent 复用。
- **A2A**：跨组织 Agent 之间委派任务、交换结果，不暴露内部状态。
- **对外发布为 web app / API / MCP 工具**（Dify 等）：把能力暴露给外部系统与 Agent 调用，属于机器共享而非人的内容消费。
- **自托管**（Dify Community / RAGFlow / QAnything / AnythingLLM）：数据留在自己基础设施上，是「共享给自己的系统」。

判断顺序：**数据归谁 → 是组织内还是公域 → 给人类还是给 Agent**。组织内协作选第一类，订阅别人的知识选第二类，给 Agent 用选第三类。
