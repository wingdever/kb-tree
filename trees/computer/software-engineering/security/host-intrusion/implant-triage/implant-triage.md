# 植入物判定

植入物会主动选择"看起来正常"的身份。判定依据不是名字，而是归属与行为。

## 命名可信度不等于身份可信度

带 systemd、kernel、worker、agent 一类字样的进程名自带正当性：管理员扫一眼进程列表，很难对它们产生怀疑。攻击者利用的正是这一点。

## 归属核对

- 查询文件属于哪个安装包。系统目录里的可执行文件在包管理器的记录里查不到归属，就是需要解释的对象。
- 系统二进制通常体积小、动态链接、由包管理器校验；一个体积可观的大文件放在系统二进制目录里，本身就是信号。
- 自启单元应随包安装、位于包的安装路径。出现在本地配置目录、却没有任何包归属的单元，必须逐个说明来源。
- 单元与其指向的二进制要互相印证：名字匹配但路径不符、或二进制不在包内，说明单元是手写的。

## 参数与行为

启动参数里出现成串的地址、域名、端口或凭据，说明它在按外部清单工作——正常守护进程不会把目标列表写在命令行里。其余特征：父进程为 1、启动时间与系统启动时间重合、长期占用固定份额的 CPU、以及大量指向同一远端端口的外发连接。

## 持久化点清单

排查按覆盖面从高到低：系统级自启单元及其启用链接、用户级与系统级定时任务、shell 启动脚本、动态链接预加载配置、SSH 授权公钥、开机脚本。任一残留都会让清理失效，而自启单元通常是最先被重建的一个。

## 取证先于删除

删除之前先保留样本与哈希，记录路径、时间戳、归属与进程参数；样本隔离存放并去掉执行权限。清理按"先断自启、再杀进程、后删文件"的顺序执行，避免进程被自启机制重新拉起。
