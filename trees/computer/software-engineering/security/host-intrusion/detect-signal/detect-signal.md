# 入侵检测信号

常规监控看总量，入侵检测看形状。总量大可能只是业务繁忙，形状异常才是线索。

## 出入比

提供服务的机器入多出少：请求小、响应大也只是"入小出大"，但方向仍是双向互动。备份、同步、镜像类是双向流量。持续"出远多于入"、且找不到对应的业务动作，说明本机在主动向外发送内容——这是被当作攻击资源的典型形状。

## 平均包长

用出站字节除以出站包数。搬运文件时平均包长接近链路 MTU；扫描与爆破则是接近协议头的短包，且数量极高。速率与包长交叉判断，比单看速率可靠：小包高频意味着"在敲门"，而不是"在传数据"。

## 连接状态分布

大量半开连接指向同一个远端端口，说明本机在批量尝试连接，而不是在提供服务。已建立连接数远超业务峰值，同样可疑。这类状态持续时间长，说明尝试是持续行为而不是一次性扫描。

## 两类日志的分工

- **失败登录记录**只记失败，体量与时间跨度反映试探强度。
- **认证日志**记录成功与失败的详情，是"是否真的被进入"的直接证据。

只看失败记录，会把"一直被爆破"当作全部事实，从而漏掉"已经被突破"。反过来只看成功记录，又会低估入口被试探的规模。两者需要并列阅读。

## 日志的呈现方式

日志的价值在于被定期阅读。按天生成一行摘要——失败次数、非白名单来源的成功登录、首次出现的来源地址——比堆积原始文件更有效。原始日志保留用于取证，摘要用于发现。

## 落地清单

- **先建形状基线**：按业务类型记录出入比、平均包长、连接状态分布的正常区间，没有基线时"异常"只能靠感觉。
- **三个指标交叉看**：出入方向、包长、连接状态，任意单项都能被业务解释，三项同时偏离才提高置信度。
- **日志并列读**：失败登录记录回答"被试探多少"，认证日志回答"有没有成功进入"；只读一类必然误判。
- **摘要外送**：按天生成一行摘要并发到主机之外的通道，原始日志留在本机备取证。
- **异常按天比较而不是按秒**：入侵行为通常持续数天，秒级抖动会淹没信号。
- **给误报留出口**：备份、镜像、批量同步都会造成短时出站高峰，白名单要写明业务来源，避免长期静音。
- **发现异常先固定现场**：抓取当时的连接表与进程信息，再决定是否处置；顺序反了，后续判断只能靠推断。
