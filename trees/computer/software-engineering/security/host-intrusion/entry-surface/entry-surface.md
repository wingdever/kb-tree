# SSH 认证暴露面

对公网开放的管理入口，防护强度等于认证方式的强度。配置错误不会立刻产生症状，只会在被试探时决定结果。

## 密码认证与 root 直登

公网监听 SSH 且允许密码认证时，安全边界退化为口令本身。两个配置把风险放到最大：允许密码认证，以及允许 root 使用密码登录。任何一次命中都直接是最高权限，攻击者不需要提权、不需要二次利用，也就不会在被发现前留下提权痕迹。

密钥认证把"知道一个字符串"换成"持有一份私钥"。爆破无法遍历私钥空间，因此禁止密码认证、只允许密钥登录（root 也一样）是公网主机的默认配置，而不是加固选项。

## 账户与来源收敛

- 用可登录账户白名单收窄范围，避免"系统里有几个账户就等于几个入口"。
- 业务账户通常不需要交互登录；能通过服务身份完成的操作，不必再开一条 SSH 通道。
- 数据库进程账户不应具备 SSH 登录能力：它的家目录位于数据目录内部，拿到 shell 就能绕过数据库自身的认证与审计。

## 监听面

管理接口、网关与代理端口绑定在回环地址，需要时通过隧道访问。把端口暴露在全部接口上，等于把认证层暴露给整个互联网，也让端口扫描成为低成本的信息来源。

## 失败尝试的处理

失败次数的意义是"入口正在被系统性试探"，而不是"已经被突破"。速率限制、自动封禁能降低噪声与日志体积，但改变不了"密码认证是否应该开启"这个决定——只要开启，剩余的防护就全部压在一个口令上。

## 落地清单

- **先看实际生效配置**，而不是看配置文件里写了什么：用 `sshd -T` 导出运行时参数，确认密码认证、root 登录、允许用户三项的真实值。
- **关闭密码认证与 root 直登**，两者一起改；只改一项时，剩下的那一项仍然是最高权限的入口。
- **可登录账户白名单**：显式列出允许登录的账户与来源网段，其余默认拒绝。
- **监听面收窄**：管理端口绑定回环地址，外部访问走隧道；需要公网时加来源限制与二次认证。
- **审计登录后的动作**：保留 sudo 与关键命令记录，单纯记录"谁登录了"无法回答"登录后做了什么"。
- **变更留痕**：改配置前备份、改后验证生效并记录时间与原因；配置漂移是这类入口最常见的复发原因。
- **定期复扫**：每月确认一次公网暴露端口清单与预期一致，新增端口要能解释来源。
