# 主机入侵与处置

主机入侵是一串可观测的阶段，不是一个瞬间事件。判定是否被入侵、以及处置到什么程度，取决于能否在链条上找到证据，而不取决于这台机器上有没有"重要的数据"。

## 三个阶段

- **进入**：认证面被突破。口令爆破、凭证泄露、暴露的管理端口，都止于"拿到一个可用身份"这一步。
- **驻留**：拿到执行权后建立自启机制，使进程在重启后仍然存活。驻留点是攻击者真正的资产。
- **利用**：把主机当作资源使用——对外扫描、发起连接、代理流量、挖矿。危害往往先体现为出站流量与账单，而不是数据外泄。

三个阶段对应三种不同的清理对象：身份、自启、行为。只清行为不动自启，几分钟后就会复发；只清自启不改身份，攻击者还能再进来一次。

## 判定依据

两条互不替代的线索：

- **认证日志里的成功记录**说明有人真的进来了。来源、身份、时间范围都需要落到具体条目。
- **失败记录的数量与持续性**说明入口长期被试探。它本身不是入侵证据，但是高危状态的前兆。

主机安全告警、异常出站流量、可疑自启单元都算旁证。任一旁证命中，就应按"已入侵"处理，直到能逐条解释清楚为止；解释不了的部分，就是尚未清理的部分。

## 处置顺序

1. **先切断放大器**：改认证方式、限制来源、关掉不需要的入口，让攻击者无法再次登录。
2. **再停用驻留**：停单元、杀进程、删二进制与自启配置，顺序不能颠倒。
3. **后做取证**：隔离样本、记录哈希与时间线，避免一边清理一边丢失证据。
4. **最后评估可信度**：一次清理不等于系统干净，需要能回答"其余部分未被改动"。

## 何时应当重建

判断标准可以收敛成三条：

- root 权限曾被外部持有，且不是一次性会话，而是持续了一段时间。
- 驻留物具备回连能力，或清理过程中发现多个互相独立的自启点。
- 无法给出"其余部分未被改动"的证据。

> 判断：三条里满足任意两条，重建的成本通常低于清理加长期观察。数据价值低并不能豁免重建判断——被入侵主机的价值不在数据，而在算力和带宽。
