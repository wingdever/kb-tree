# 凭证卫生

凭证是攻击者最省力的入口。它的风险不来自"某一个密码太简单"，而来自强度、复用、存放三件事同时失守。

## 口令的三个失效点

- **强度**：可被常见字典覆盖的口令，在自动化爆破面前等于没有。
- **复用**：同一个口令出现在不同账户、不同机器上，把一处失守放大成一片失守。
- **存放**：明文落在可被读取的位置——笔记、代码仓库、部署脚本、聊天记录——等于提前把钥匙交给任何能看到这些位置的人。

单看强度只是评估了一个维度。复用决定"爆开一个之后还能打开多少"，存放决定"别人需不需要爆"。

## 复用的边界

同一口令横跨超级用户、运维账户与业务账户时，最高权限的入口被扩散到了权限最低的位置：最弱的那个账户成了整台机器的入口。判断凭证风险时，资产边界不是"哪台机器"，而是"还有谁能读到它"。

## 私钥不是万能替代

密钥认证消除了口令猜解，但私钥本身仍是凭证：

- 私钥应设置 passphrase，泄露后不至于直接可用。
- 私钥文件权限收紧到仅属主可读，不随备份、同步、网盘扩散。
- 公钥可以公开，私钥一旦进入版本库历史，就等于长期通行证——即便之后删除，历史里仍然存在。

## 轮换的触发条件

轮换应当由暴露面变化驱动，而不是由日历驱动：

- 凭证曾存放在边界之外（代码库、公开仓库、聊天记录、工单截图）。
- 主机曾被外部持有超级用户权限。
- 人员、权限范围或信任关系发生变化。

## 配套的最小化

能不用口令登录的系统就不开口令登录；能不给交互 shell 的服务账户就不给；能拆成"一个账户只做一件事"的就不合并。凭证卫生的终点是"需要被保护的凭证更少"，而不是"把所有凭证都管得更严"。

## 落地清单

- **先盘出凭证清单**：主机上有哪些可登录账户、哪些服务账户持有令牌、哪些脚本里写死了口令或密钥。盘点不完成，后面的收紧都是局部的。
- **关掉不需要的认证通道**：不需要交互登录的服务账户取消 shell；不需要口令登录的系统关闭密码认证；root 一律只允许密钥或禁止直登。
- **私钥三件事**：设 passphrase、权限收到仅属主可读、确认没有随备份或同步工具扩散出去。
- **扫一遍历史**：在代码仓库与部署脚本的历史提交里搜密钥样式字符串；已进入历史的凭证按"已泄露"处理，直接轮换，而不是删掉那行代码。
- **轮换由事件触发**：凭证曾落在公开位置、主机曾被外部持有高权限、人员或权限范围变化——三条任一命中就轮换，并在清单上记录触发原因与时间。
- **拆分权限**：把"一个账户做所有事"拆成按用途的最小账户；合并账户的风险不是权限大，而是无法判断某次操作是谁做的。
- **定期复核**：按固定周期重新过一遍清单，重点看新增账户、权限变更与已离职人员的残留凭证。
