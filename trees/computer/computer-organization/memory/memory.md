# 存储层次（Memory Hierarchy）

CPU 与存储的速度差是当代计算的主导瓶颈。存储层次用"小而快靠近 CPU、大而慢远离 CPU"的多层结构，借助**局部性原理**隐藏这个速度差。

## 层次与典型量级

| 层次 | 典型容量 | 典型访问延迟（相对量级） | 由谁管理 |
|---|---|---|---|
| 寄存器 | 几十~几百个 | ~1 周期 | 编译器 / 硬件 |
| L1 缓存（指令 + 数据） | 32–64 KB | ~3–5 周期 | 硬件 |
| L2 缓存 | 256 KB–1 MB | ~10–15 周期 | 硬件 |
| L3 缓存（多核共享） | 几 MB–几十 MB | ~30–50 周期 | 硬件 |
| 主存 DRAM | GB 级 | ~200 周期 | 操作系统 + 硬件（MMU） |
| 辅存 SSD | TB 级 | ~100 µs | 操作系统 / 文件系统 |
| 磁盘 / 远程存储 | 更大 | ms 级 | 操作系统 / 网络 |

数字随代际变化，量级关系比具体数值更重要：**相邻层速度常差一个数量级**。

## 局部性原理

- **时间局部性**：最近访问的数据很可能再次被访问（循环变量、热点数据）。
- **空间局部性**：访问某地址后，附近地址很可能被访问（数组顺序遍历、指令顺序执行）。

缓存正是靠这两点工作：把访问过的数据及其周围一个缓存行一起保留。

## 缓存机制

按**缓存行（cache line，常见 64B）**加载；命中直接用，失效触发从下一层取数，产生失效惩罚。衡量缓存效果的常用模型。

```
平均内存访问时间 AMAT = 命中时间 + 失效率 × 失效惩罚
```

## 多核一致性

多核各有私有缓存时，同一内存地址可能存在多个副本，写操作必须协调。**MESI / MOESI** 等一致性协议用状态机（Modified / Exclusive / Shared / Invalid）保证所有核看到一致视图。一致性（coherence）关注"同一地址的多份副本"，内存一致性模型（consistency）关注"多个地址操作的可见顺序"。

## 内存墙

CPU-内存带宽与延迟是数据库、科学计算与 AI 负载的主导瓶颈；缓存未命中时 CPU 大量时间空等。**近内存计算（near-memory）**与**存内计算（PIM, processing-in-memory）**试图把计算搬到数据附近，打破冯·诺依曼瓶颈。

## 虚拟内存

操作系统为每个进程构建连续私有地址空间的"幻觉"，由 MMU、页表与 TLB 实现，代价是地址转换开销。

## 常见失败模式

- 忽视空间局部性：链表式随机访问、结构体数组布局不当，导致缓存命中率骤降、性能差数倍。
- 误把一致性问题归因于程序 bug——多核共享数据的可见性需要一致性协议与内存屏障共同保证。
- 只看容量不看延迟与带宽，选错存储层。
