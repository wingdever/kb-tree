# 虚拟内存（Virtual Memory）

操作系统为每个进程构建**连续、私有、从零开始的线性地址空间**的幻觉，让程序无需关心物理内存布局，也实现进程隔离与保护。代价是每次访存都要做地址转换，以及转换失败时的额外开销。

## 地址转换

虚拟地址 →（MMU + 页表）→ 物理地址。地址按**页（page）**划分，常见页大小 4KB。

- **页表**：记录虚拟页到物理页帧的映射，以及权限（读/写/执行）、有效位、脏位、访问位。多级页表节省空间（只为实际使用的区域建表），但增加查询级数。
- **TLB（快表）**：页表项的高速缓存，命中时转换几乎免费。**TLB 失效**时需做 page table walk（查多级页表），代价可达几十至几百周期。
- **ASID / PCID**：进程标识符，避免切换进程时冲刷 TLB。

## 缺页与置换

- **缺页（page fault）**：访问的页不在内存，触发操作系统从磁盘换入；这是最昂贵的事件之一（毫秒级）。
- **按需分页（demand paging）**：只在真正访问时载入页面。
- **页面置换算法**：当内存不足需淘汰页面。最优（OPT）不可实现；实际用 LRU 近似（时钟算法、第二次机会）等。
- **工作集（working set）**：进程近期活跃访问的页面集合。工作集超过可用内存会导致**抖动（thrashing）**——频繁换入换出，系统大部分时间在搬运页面而非执行。

## 大页（Huge Pages）

用 2MB / 1GB 大页减少页表项数量与 TLB 失效，对数据库、虚拟机、大规模内存应用收益显著。代价是内存浪费与分配灵活性下降。

## 保护与共享

页表项中的权限位支撑隔离：代码页只读可执行、数据页不可执行（DEP/NX）、内核页用户态不可访问。共享库通过把同一物理页映射到多个进程地址空间实现节省。

## 常见失败模式

- 访问大规模非连续内存时 TLB 失效激增——"维持抽象的开销"是高性能计算（HPC）的头号杀手之一。
- 工作集过大导致抖动，表现为系统"卡死"而 CPU 利用率并不高。
- 忽略页表与 TLB 成本，在性能敏感路径上频繁跨大范围内存访问。
