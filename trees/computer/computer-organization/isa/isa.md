# 指令集架构（Instruction Set Architecture, ISA）

ISA 是**硬件与软件的契约**：实现同一 ISA 的任何处理器都能跑同一软件，无论内部微架构如何。编译器面向 ISA，处理器实现 ISA。它定义软件可见的设计——指令类型、寻址方式、数据类型、寄存器组、内存模型与调用约定。

## 抽象层次

```
应用软件 → 操作系统 → ISA（软硬件边界）→ 微架构 → 逻辑门 → 晶体管
```

上层只依赖契约，不关心实现；下层可自由优化，只要不破坏契约。这层抽象是软件生态可移植的基础：x86 从 8086 到现代多核乱序处理器， ISA 基本兼容，软件不需重写。

## 体系结构模型

- **冯·诺依曼**（1945）：程序指令与数据共用同一存储空间。CPU（ALU + 控制器 + 寄存器）、内存、I/O、总线。**冯·诺依曼瓶颈**：CPU 与内存间带宽限制整体性能——现代缓存层次正是为缓解它而生。
- **哈佛结构**：指令与数据分开存储，可同时访问，带宽更高但更复杂。用于 DSP、单片机（AVR / PIC），以及现代处理器 L1 缓存的分裂（I-Cache / D-Cache）。

## 指令类型与寻址

- **指令类型**：算术（加减乘除）、逻辑（与或非、移位）、访存（load / store）、I/O、控制（分支、跳转、调用）。
- **寻址方式**：立即数、寄存器、直接、间接、寄存器间接、基址+偏移、PC 相对、栈式。寻址方式决定一条指令能访问多复杂的地址，也影响译码与流水线的复杂度。
- **数据类型**：整数（不同位宽）、浮点（IEEE 754）、向量、地址。

## RISC 与 CISC

| | RISC | CISC |
|---|---|---|
| 指令 | 简单、定长 | 复杂、变长 |
| 访存 | Load/Store 架构，运算只在寄存器 | 可直接操作内存 |
| 流水线 | 易流水化 | 译码复杂 |
| 代码密度 | 较低 | 较高 |
| 例子 | ARM、RISC-V、MIPS、PowerPC | x86-64、VAX |

现代界限已模糊：**x86-64 内部把 CISC 指令解码为类 RISC 微指令（micro-ops）**，后端用类似 RISC 的乱序流水线执行；RISC 也不断增添复杂指令。评价 ISA 要看实现代价与软件生态，而不只看"RISC/CISC"标签。

## RISC-V 作为例子

RISC-V 是开放的模块化 ISA：基础整数指令集（RV32I / RV64I）+ 标准扩展（M 乘除、A 原子、F/D 浮点、V 向量、C 压缩）。指令格式（R/I/S/B/U/J 型）、寄存器约定、size 与对齐都明确定义。其模块化与开放性使其成为教学与新兴硬件的首选。

## 大小端与对齐

- **大端（big-endian）**：高位字节在低地址；**小端（little-endian）**：低位字节在低地址。x86 是小端，网络字节序是大端——跨系统传输需转换。大小端是 ISA 层级的定义，不是软件偏好。
- **字节对齐**：访问地址按数据类型边界对齐可一次完成；未对齐访问可能触发多次访存甚至异常。结构体填充与缓存行边界都与此相关。

## 常见失败模式

- 把 ISA 与微架构混为一谈：讨论"x86 有多少级流水线"是微架构问题，不是 ISA 问题。
- 忽略大小端与对齐，导致跨平台数据解析错误。
- 以为"复杂指令一定更快"——现代性能瓶颈多在访存与并行，而非单条指令功能强弱。
