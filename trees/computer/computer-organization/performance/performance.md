# 计算机性能分析（Computer Performance Analysis）

性能工程把"快不快"变成可计算、可比较、可归因的量。核心是把执行时间分解成可独立优化的因素。

## 基本公式

```
CPU 时间 = 指令数 × CPI × 时钟周期 = 指令数 × CPI / 主频
```

- **指令数（IC）**：取决于 ISA、编译器与算法。
- **CPI**（每指令周期数）：取决于微架构与程序特征（访存、分支、依赖）。其倒数是 **IPC**（每周期指令数）。
- **主频**：由工艺与微架构（流水线深度）决定，但受功耗墙限制。

三者都可优化，但常有取舍：减小指令数可能增加单指令 CPI；加深流水线提高主频却增加冒险停顿。

## 常用指标

- **MIPS**：每秒百万条指令——忽略指令复杂度，跨 ISA 比较意义有限。
- **FLOPS**：每秒浮点运算次数——AI 与科学计算常用，需说明精度（FP64/FP32/FP16/INT8）。
- **吞吐 vs 延迟**：吞吐是单位时间完成量，延迟是单个任务耗时；批处理追求吞吐，交互系统追求延迟，优化方向可能不同。
- **Little's Law**：`并发数 = 吞吐 × 平均延迟`——容量规划与性能分析的基础关系。

## 加速比定律

- **Amdahl 定律**：`Speedup = 1 / ((1-f) + f/s)`，固定问题规模下受串行部分限制（例：40% 可并行 → 最大约 1.67×）。
- **Gustafson 定律**：问题规模可随时扩展时，加速比可近线性。
- 两者提醒：**找对瓶颈比堆资源更重要**——串行段与内存带宽常是隐藏天花板。

## 基准测试

- **SPEC CPU / SPECpower** 等标准化套件用于跨系统比较；AI 领域常用 MLPerf。
- **良好基准的特征**：可复现、负载代表真实场景、结果可归因、避免只报峰值。
- **常见陷阱**：峰值指标（理论 FLOPS）远高于实际；只在理想数据上测试；预热不足/过度；忽略方差与异常值；用微基准推断整体性能。

## Roofline 模型

把性能上界表达为：`可达到性能 = min(峰值算力, 内存带宽 × 算术强度)`。算术强度（每字节内存的浮点运算数）决定程序受**算力**还是**带宽**限制：

- 算术强度低（访存密集）→ 带宽受限，优化数据局部性与缓存。
- 算术强度高（计算密集）→ 算力受限，优化并行与向量化。

Roofline 让"该优化哪里"有图可依，是 HPC 与 AI 性能分析的常用工具。

## 常见失败模式

- 用主频或峰值 FLOPS 代替实际运行时间判断性能。
- 基准负载与真实负载差异巨大，优化后线上无收益。
- 只优化局部热点，忽略 Amdahl 约束下的串行瓶颈。
