# 机器人流程自动化（RPA）

## 定义

RPA（Robotic Process Automation，机器人流程自动化）是**用软件机器人模拟人在图形界面上的操作，按规则在多个既有系统之间读取、录入、搬运和处理数据**的技术。它通常不改造被操作系统的接口，而是在界面层完成跨系统协同；因此常被称为“非侵入式”自动化。

这里的“机器人”是**软件进程**，不是人形机器人或机械臂。RPA 的价值不在于制造硬件，而在于把高重复、强规则、跨系统的桌面工作交给可审计、可调度的软件执行。

## 核心特征

- **界面层操作**：通过控件选择器、坐标、图像识别或浏览器 DOM 操作既有系统，不要求对方提供 API。
- **规则驱动**：分支、循环、校验、重试都由显式规则定义；同一输入应得到同一结果。
- **非侵入**：尽量不改动 ERP、CRM、财务、政务等存量系统，降低集成与合规阻力。
- **跨系统编排**：把邮件、Excel、网页、桌面客户端、PDF、数据库之间的断点串起来。
- **可审计**：每一步操作、输入输出、异常与截图可留痕，适合受监管流程。
- **可调度**：支持定时、队列、人工触发与多机器人协同。

## 系统组成

| 组件 | 作用 |
|---|---|
| **设计器 / Studio** | 流程图式或脚本式编排，定义步骤、变量、异常与子流程 |
| **录制器** | 录制人工操作生成初始流程，降低首版搭建成本 |
| **运行时 / Runner** | 在桌面、虚拟机或容器里执行流程，处理窗口、控件与文件 |
| **编排器 / Control Room** | 排队、分配、定时、权限、日志、监控与版本管理 |
| **队列** | 把待处理事务解耦成工作项，支持重试、优先级与状态流转 |
| **凭证保险库** | 集中保管账号、密钥、证书，避免把密码写进流程 |
| **文档理解 / OCR** | 从发票、合同、扫描件中抽取结构化字段，供后续步骤使用 |
| **连接器 / API** | 在接口可用时走 API，减少纯界面操作带来的脆弱性 |
| **分析审计** | 统计处理量、成功率、例外率、人工干预与节省工时 |

## 运行形态

- **有人值守（Attended）**：由员工触发，在员工桌面上辅助完成一段操作；适合需要即时判断或授权的场景。
- **无人值守（Unattended）**：运行在服务器或虚拟机，按计划或队列自动执行；适合夜间批处理、高吞吐重复任务。
- **混合（Hybrid）**：无人值守先批量处理，遇到例外转人工，人工处理后再交回机器人。

## 与相关概念的区别

| 概念 | 主要做什么 | 与 RPA 的边界 |
|---|---|---|
| **RPA** | 按规则模拟界面操作，跨系统搬运数据 | 强调规则、界面层、可审计执行 |
| **宏 / 脚本** | 单应用内的快捷操作或脚本 | 通常缺编排、队列、权限与审计 |
| **API 集成** | 系统与系统直接交换数据 | 更稳定，但要求对方有接口与改造配合 |
| **BPM** | 业务流程建模、人工审批与流程治理 | RPA 执行具体动作，BPM 管流程与责任 |
| **IDP** | 文档识别与字段抽取 | 常作为 RPA 的前置能力，不负责全流程编排 |
| **低代码平台** | 快速搭建应用与表单 | 可能包含自动化，但不等于界面层机器人 |
| **Agent** | 感知、推理、选择工具并处理开放任务 | RPA 偏确定性执行，Agent 偏动态决策 |

## 适用条件

适合上 RPA 的流程通常同时满足：

- **量大且重复**：人工处理频次高，规则稳定，节省的时间能覆盖建设与维护成本。
- **规则明确**：输入、判断、输出都能写成可执行规则，边界案例可枚举。
- **界面或接口可达**：目标系统能稳定操作；有 API 时优先 API，没有才走界面。
- **输入数字化**：数据在系统、表格、邮件、PDF 中，而不是大量口头或纸质信息。
- **例外率可控**：异常能识别、能转人工，不会让机器人静默做错。
- **需要留痕与合规**：受监管、需审计的流程更能体现 RPA 的价值。
- **存量系统难改**：无法为一次集成改造核心系统，或改造周期远长于自动化收益。

不适合的情况：

- 需要大量判断、谈判、创意或跨部门协调。
- 界面频繁改版、控件选择器极不稳定，维护成本高于人工。
- 输入高度非结构化，且没有可用的文档理解能力。
- 对延迟极敏感，界面操作的秒级开销不可接受。
- 业务量太小，建设、授权与运维成本无法回本。
- 流程本身还没标准化；先把混乱流程固化，只会更快地产生错误。

## 实施流程

1. **流程筛选与评估**：统计频次、耗时、规则清晰度、例外率、系统稳定性与回本周期，排优先级。
2. **现状梳理**：画出实际操作路径、输入输出、系统边界、权限与异常分支，不只画理想流程。
3. **方案设计**：确定有人值守还是无人值守，哪些步骤走 API，异常如何转人工，数据如何校验。
4. **搭建流程**：用选择器、队列、子流程与凭证保险库实现；把等待、重试、超时和日志作为一等公民。
5. **测试**：单元测试每个动作，集成测试跨系统，UAT 覆盖正常与异常路径，做负向与并发测试。
6. **上线与调度**：配置机器人账号、权限、运行环境、计划任务与告警，先小流量再放量。
7. **运营监控**：盯成功率、队列积压、例外率、平均处理时长与人工干预率。
8. **维护治理**：界面升级、系统改版、规则变化都会让流程漂移；建立版本、变更与回归机制。

## 常见失败模式

- **选择器脆弱**：按钮改名、窗口结构变化、分辨率不同就失败；只靠坐标或图像识别更不稳。
- **例外处理缺失**：只写 happy path，遇到弹窗、验证码、网络超时就卡死或静默跳过。
- **把密码写进流程**：凭证散落在脚本与配置文件，离职、轮换与审计都失控。
- **流程未标准化就自动化**：把多种人工习惯固化成一个更快的混乱流程。
- **忽略运维成本**：上线时算建设费，没算授权、虚拟机、监控与每次改版的回归成本。
- **影子机器人**：部门私自搭建、无人管辖，权限过大且没有日志。
- **规模瓶颈**：单机机器人排满、许可证不够、共享文件冲突，吞吐上不去。
- **错误静默传播**：没有校验与对账，错误数据被批量写进财务或生产系统。

## 安全与治理

- 给机器人**独立账号与最小权限**，不要共用员工账号；离职与轮换要能即时吊销。
- 凭证放保险库，流程只引用句柄；日志脱敏，截图与录屏遵守数据分级。
- 关键写操作要有**双人复核、限额、对账与回滚**，尤其是资金、订单、库存与个人数据。
- 建立机器人清单、责任人、版本、变更记录与定期权限复核，避免影子自动化。
- 对个人数据与跨境数据，先确认合规边界，再决定能否读取、落盘与传输。

## 与 Agent 的关系

RPA 与 Agent 不是替代关系，而是**执行层与决策层**的关系：

- RPA 擅长确定性、可枚举、可审计的界面动作；Agent 擅长理解模糊目标、选择工具、处理开放异常。
- 纯 RPA 遇到未枚举的例外容易停；纯 Agent 直接操作界面则可能不稳定、难审计、成本高。
- 更现实的组合是 **Agent 负责规划与异常判断，RPA 负责稳定执行与留痕**；接口可用时，两者都应优先走 API。
- 大模型可以增强 RPA 的文档理解、例外分类与流程生成，但关键写操作仍需要规则、权限与人工兜底。

> 判断：RPA 的长期形态不是“更复杂的点击脚本”，而是**被 Agent 调用的确定性动作层**；界面操作会逐步让位给 API，但在存量系统与受监管流程里仍会长期存在。

## 一句话主线

**RPA 把高重复、强规则、跨系统的界面工作变成可调度、可审计的软件执行；它适合稳定流程，不适合开放判断，未来更像 Agent 的手而不是 Agent 的大脑。**
