# 意图识别（Intent Recognition）

意图识别是把用户自由文本对应到有限意图集合，并抽取执行所需参数（槽位）——所有多工具 Agent、业务智能路由的基石。

## 定义与分类

- **意图分类**：question intent（求知）vs execute intent（执行）。对枚举的意图集合候选匹配——意图是具体情境下的目的结团，情境对目的施加边界与约束。
- **槽位（Slot）**：完成该意图所需关键参数。槽位填充把模糊自然语言转成机器可理解的结构化参数与指令。
- **意图路由**：按识别结果把请求分发到对应处理单元。
- **单意图 vs 复合意图**：一条输入含多个独立诉求时需拆解后分别调度；传统规则方案难处理，大模型方案可天然支持多意图拆分与并行。

## 歧义分类学（NoisyToolBench, 2026）

真实指令常有噪声。四类指令问题：

| 类别 | 含义 | 占比 |
|---|---|---|
| **IMKI** 缺关键信息 | 调用必填参数被省略（"订张机票"无目的地） | 56%，最常见 |
| **IMR** 多重指代 | 模糊词可指多个实体（同名电影） | — |
| **IwE** 含错误 | 拼写错误、无效 ID | — |
| **IBTC** 超出能力 | 现有工具无法满足 | — |

**"helpfulness trap"**：Agent 为强制完成任务而幻觉缺失细节（随便选"纽约"），导致错误执行、浪费算力、隐私/安全风险（arbitrary generation）。

## Ask-when-Needed（AwN）框架

零样本提示策略，在工具调用**之前**插入 reflection 步：评估意图是否清晰、信息是否充分；发现歧义或缺参则先问澄清问题，全部参数 resolve 后才进工具阶段。模块化，可集成进现有 Agent 工作流，无需昂贵微调。

效果：IMKI 任务上 GPT-4o 正确识别歧义（A1）从 52%→90%，后续 API 执行与答案准确率同步提升。高推理模型（DeepSeek-R1、o3-mini）即使不问也可能猜对，但强制 reflection 后可靠性仍提升。且 AwN 不损害清晰指令上的表现。

**"Knowing but Not Showing"（Cornell 2026, arXiv 2605.25284）**：直接问模型"这句有歧义吗"它多半判断得出，但放进实际问答情境压倒性选择直接作答而非回问——给检索上下文后倾向更强。**Ask or Assume**（2026）算清代价：指令完整时解决率 70.8%，刻意留白不许互动时掉到 54.8%——16 个百分点全来自系统拿假设当事实执行。

## 槽位填充工程

典型步骤：**识别意图 → 提取已有槽位 → 追问缺失槽位 → 直至集齐**。

- 槽位定义、few-shot、spec 加载、多意图的依赖分析。
- 槽位填准本身是难题：SpokenWOZ（含语音噪声）上最强对话状态跟踪模型联合目标准确率仅 25.65%——**缺槽检测与槽位验证必须由代码把关，而非让模型自行决定是否跳过必填**。
- 共形预测（conformal prediction）产出"可信意图集合"：集合唯一时直接执行，含多候选才触发澄清。
- 置信度门槛与升级决策表：低置信度/平票 → 澄清或升级人工（见 `../../agent/multi/consensus/` 的同类思想）。

## 分层 Pipeline（三层语义）

1. **望文生义层**：语句在一般语言上的直接近似语义。
2. **用户表达层**：个性化表达带来的潜在语义补充与偏转。
3. **真实世界层**：语句描述和作用于真实世界面临的约束与指定。

## 工程落地

- **三种实现路线**：规则/传统 ML（快、可控、泛化弱）→ 大模型零/少样本（无需标注、支持口语化复合意图、**当前多数项目首选**）→ 函数调用隐式识别（意图封装为工具函数，融入工具选择）。
- **承载架构**：Router + Skills（独立前置模块静态分流）；Orchestrator + Workers（内置于编排器动态执行，支持复合意图）；ReAct 单 Agent（融合于 Thought，隐式判断）。
- **八大准确率策略**：清晰互斥的意图定义（消边界歧义）、few-shot 样本、强约束 JSON 输出、负面约束、意图互斥拆分、统一实体 schema、模型分级选型、置信度阈值+实体黑白名单校验、规则前置、多轮上下文联动、数据迭代闭环。
- **别用 Agent 循环做意图识别**——它是前置路由，不是开放推理任务。
- **测试集**：意图识别测试集 + 意图生成（生成式扩展用户意图）。
