# RAG 基础

RAG（检索增强生成）让模型在查询时从自有数据中检索相关事实，而不是依赖训练时记住的内容。它是"在不重新训练的前提下，降低幻觉、让答案保持最新的最有效杠杆"——从根源解决问题：模型不再猜测，而是引用你的数据。

## 机制五步

1. 把文档切块并嵌入为向量
2. 存入向量索引
3. 嵌入 incoming 查询
4. 检索最相近的块
5. 把这些块作为上下文交给模型

## 为什么需要 RAG（而不是微调或大上下文）

| 方案 | 适合 | 不适合 |
|---|---|---|
| **Prompt** | 无需外部事实、行为微调 | 海量/动态知识 |
| **RAG** | 最新/海量外部事实、需要引用溯源、权限隔离 | 改变模型风格/格式（用 SFT） |
| **SFT** | 改变输出风格、行为、格式、拒答边界 | 动态知识注入（知识会过时） |
| **全量微调** | — | 几乎总是过度 |

**大上下文窗口没有杀死检索**：把整个语料塞进提示词，在四个维度同时失败——

- **成本**：注意力是二次的；一次多百万 token 调用成本约为只检索所需的 1,000 倍。
- **规模**：真实知识库远大于任何窗口；窗口是固定上限，检索可扩展到装不下的语料。
- **延迟**：长上下文调用慢（数十秒 vs 亚秒级检索），在多次检索的 Agent 循环里致命。
- **上下文腐烂**：即便装得下，窗口填满时质量下降。

长上下文是补充而非替代：更大的每步工作集，有意识地使用。

## 生产级 RAG 流水线要点

- **摄入与切块**：按上下文窗口与查询类型切分；切块策略实质影响答案质量。
- **嵌入与向量库**：用嵌入模型把块转为向量存入向量库；源数据变化时监控索引新鲜度。
- **检索质量**：纯向量搜索只是起点；混合搜索（关键词 + 向量）加重排序通常提升相关性。
- **接地与引用**：指示模型只根据检索上下文回答、不知道就说不知道、返回来源引用以便审计。

> 把检索质量当作一等指标，而不是事后补充。

## 工程原则

> 用轻量算法换取召回广度，再用昂贵算法换取排序精度。

这是检索管道的基本经济学：召回阶段要快而广（BM25、向量 ANN），精排阶段要准而贵（cross-encoder）。

## 参考架构（2026 企业栈）

1. 摄入：Unstructured.io（PDF/PPT 解析）
2. 编排：LlamaIndex / LangChain
3. 索引：混合（Pinecone + Elasticsearch）
4. 知识图谱：Neo4j
5. 检索：混合搜索 + Cohere 重排
6. 生成：vLLM 或云端模型
7. 评估：Ragas / Arize Phoenix

> 延迟注意：查询改写增加 200–400ms；用缓存、GPU 加速重排器、ANN 索引（HNSW、IVF-PQ）缓解。
