# 向量数据库成本与运维

## 成本三驱动

1. **存储**：每百万向量/月。
2. **算力**：索引构建与查询。
3. **网络出口**：托管服务。

托管方案月成本在 1000 万向量规模下因副本需求差异 3–5×；若已大规模运行 Postgres，pgvector 最便宜。

## 成本优化手段

- **量化**（PQ/OPQ/标量）：向量缩小 4–32×。
3072→1024 维在 1000 万文档下省 ~80GB。
- **int8/binary 输出**：Cohere Embed v4、Voyage 原生支持。
- **分层存储**：热/温/冷分区（HNSW 热层 + IVF-PQ/DiskANN 冷层）。
- **成本敏感负载换更小嵌入模型**。

## 常见坑

- 文档批量更新后索引没重建，新文档搜不到——靠数据同步流程解决。
- HNSW 插入高效、删除难；生产多用 tombstone + 定期重建。
- 嵌入模型变更必须重嵌，过渡期维护两个索引双写。
- 公开数据集的分数只能粗筛方案；真正的参数要用自己的查询日志回放。

## 版本化与漂移

- 嵌入模型版本写入元数据；换模型时双索引双写，平滑过渡。
- 监控召回漂移（recall drift），不只是 CPU/延迟。
- 稳定 chunk ID 让增量更新不破坏父子关系。

## 上线前成本估算清单

- 向量总数与增长率
- 平均嵌入维度
- 查询量 p50 / p95
- 预期副本数与区域
- 重索引频率与回填开销

> 若 Provider 无法在你的预期规模给出清晰成本，视作风险。
