# 爬虫礼貌与合规

爬虫的“能不能抓”不只看技术，还看站点规则、合同、版权与个人信息。礼貌不是道德装饰：它决定你的 IP 会不会被封、数据能不能用、上线后会不会收到投诉。

## 四个约束层

1. **Robots Exclusion Protocol**。按 RFC 9309 读取 `robots.txt`，按 user-agent 匹配规则；`Disallow` 不是“建议”，而是站点表达的抓取边界。
2. **服务条款与合同**。robots 允许不等于条款允许；批量抓取、再分发、商业使用常被单独限制。
3. **版权与数据库权利**。网页内容有版权，数据库可能有汇编权利；存储、摘录、再发布的范围要按许可证判断。
4. **个人信息与保密**。只取业务必需字段；避免抓取登录后内容、健康/金融/位置等敏感数据；保存期限与访问审计要可说明。

## 限速与礼貌

- **按 host 控制并发**：同一站点的并发与间隔独立设置，不要用全局并发掩盖单站压力。
- **尊重 429 与 Retry-After**：先降速，再考虑暂停；不要换代理、换 UA 继续打。
- **条件请求**：用 `ETag`/`Last-Modified` 换 304，减少重复传输。
- **缓存与去重**：同一页面不重复抓；重定向与规范化后的最终 URL 只保留一份。
- **错峰**：能离峰抓就离峰；对新闻、电商等高峰站点尤其重要。

## 遇到拒绝怎么办

遇到 401/403、验证码、付费墙或明确的“禁止抓取”提示，正确动作是停止并寻找合法入口：

- 使用官方 API 或数据导出；
- 申请授权或合作；
- 采购数据或许可；
- 降低范围，只取明确允许的部分。

> 判断：绕过访问控制、伪造身份或对抗验证码，不是“技术能力强”，而是把合规风险转成业务风险。

## 记录与可审计

保存抓取时间、最终 URL、响应状态、robots 判定、使用的 user-agent 与授权依据。出现投诉或数据删除请求时，能定位到具体来源并停止重抓；没有这些记录，合规只能靠记忆。

## 一句话主线

先读 robots 与条款，再按 host 限速、缓存与错峰；遇到拒绝走授权或 API，不绕过访问控制；抓取行为要能审计、能停止、能删除。
