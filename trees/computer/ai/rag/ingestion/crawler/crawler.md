# 网络爬虫

爬虫是自动发现并获取网页内容的程序。它的工程难点不在“发请求”，而在**在有限预算内，稳定地找到、取到、去重并更新正确的页面**；抓取速度只是其中一个变量。

## 四个组成部分

1. **调度器**。维护待抓 URL 的 frontier，决定先抓谁、多久重抓；负责 URL 去重与优先级。
2. **抓取器**。发 HTTP 请求、维持会话、处理超时与重试；把响应交给解析器。
3. **解析器**。抽取正文、链接与元数据；常用 BeautifulSoup 等库把 HTML 变成可导航的树，再把新发现的 URL 回填给调度器。
4. **存储与监控**。保存原始响应、解析结果与抓取状态；记录成功率、延迟与每站配额。

礼貌与合规是横切约束，不是第四个模块之外的“可选项”：调度、抓取、重试都要服从它。调度、抓取、解析与管道可以由 Scrapy 这类框架统一组织；框架省的是并发与管道管理，不替代抓取规则与合规判断。具体到每一段用什么，属于工程选型问题：先定规模与合规约束，再选组件。

## 两种抓取策略

- **广域抓取**：从一批种子出发，尽量覆盖整个站点或领域；适合建库，但容易抓进大量低价值页面。
- **聚焦抓取**：用主题、链接关系或样例页面判断相关性，只扩展高概率相关的链接；适合垂直知识库。
- **增量抓取**：只重抓可能变化的页面；由更新频率、ETag、Last-Modified 与内容哈希共同决定。

策略选择取决于目标：要覆盖就接受噪声，要精度就接受漏抓；两者都要，就得先做分源与分层。

## 边界

- **robots 与条款**：遵守 Robots Exclusion Protocol 与站点服务条款；robots 允许不等于版权或合同允许。
- **频率**：按站点设置并发与间隔，遇到 429 按 `Retry-After` 退避；不要用代理池对抗限流。
- **个人信息**：只取业务必需字段，避免把个人数据、登录态内容与敏感页面带入索引。
- **访问控制**：不绕过登录、付费墙、验证码与明确的技术限制；需要时走官方 API 或申请授权。

## 常见失败

- **无限 URL 空间**：日历、分页、筛选参数与 session id 组合出无限页面；需要规范化与规则裁剪。
- **软 404**：服务器返回 200 但内容是“未找到”；只看状态码会把空页当有效页。
- **只抓首屏**：正文由 JavaScript 渲染，原始 HTML 里没有内容；需要判断是否上渲染。
- **重复内容**：同一内容多个 URL、打印版、AMP 版与带跟踪参数的版本；需要在 URL 与内容两层去重。
- **抓取预算失控**：低价值页面占满队列，真正需要的页面迟迟抓不到；需要优先级与配额。

## 一句话主线

爬虫是把“发现、抓取、解析、存储、更新”串成闭环，并在礼貌、合规与预算约束下持续运行；先定边界与预算，再谈并发和速度。
