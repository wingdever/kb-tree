# 抓取发现与调度

抓取的第一步不是请求，而是决定“下一批抓什么”。发现与调度决定了覆盖范围、抓取效率和重复率；绝大多数“抓不全”或“抓不完”的问题，根因都在 URL 集合与优先级。

## URL 从哪里来

- **种子**：人工给定的首页、栏目页、详情页与已知站点清单；决定起点与覆盖面。
- **站点地图**：`sitemap.xml` 与 sitemap index，通常带 `lastmod`；发现成本低，适合结构化站点。
- **订阅源**：RSS/Atom、新闻推送与变更通知；更新信号明确，适合时效型内容。
- **链接抽取**：从已抓页面的 `<a href>`、分页、相关推荐与结构化数据里扩展。
- **搜索与站内检索**：用于发现长尾页面，但结果不稳定，最终仍要回到原始页面核对。

## 规范化与去重

同一个页面可能有多个 URL：大小写主机名、默认端口、`index.html`、锚点、跟踪参数、排序参数、打印版与 AMP 版。先把 URL 规范化，再做集合去重；否则同一页会被抓很多次，frontier 很快被垃圾填满。

规范化要保守：去掉明确的跟踪参数与片段，统一主机名与默认端口，解析相对路径；但不要把带业务含义的查询参数一刀切掉，否则会把不同页面合并成一个。

## Frontier 的优先级

调度器通常不是一个简单队列，而是按优先级取出的 frontier：

- **按价值**：详情页优先于列表页，正文页优先于导航页。
- **按新鲜度**：高频更新栏目优先重抓，静态文档降频。
- **按站点配额**：每个 host 有并发与间隔上限，避免一个站点占满全局队列。
- **按深度**：广域建库可 breadth-first；垂直抓取更适合按相关性打分，而不是盲目加深。

## 常见陷阱

- **无限空间**：日历、筛选器、分页参数与 session id 组合出无限 URL；需要规则裁剪与深度上限。
- **软 404**：200 状态但内容是空页或错误提示；需要内容判定，不只看状态码。
- **登录与付费墙**：抓到的只是登录页或摘要；不要绕过访问控制，改用官方接口或授权数据。
- **优先级倒挂**：列表页与重复页占满队列，真正的详情页长期饥饿；需要按价值与站点配额调度。

## 一句话主线

先把 URL 来源分层、规范化并保守去重，再用价值、新鲜度与站点配额排优先级；发现与调度做对，抓取器才不会被无效 URL 淹没。
