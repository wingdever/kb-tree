# RAG 数据摄取

RAG 的质量上限，首先由“进来的数据”决定。检索与生成只能放大已有文本的质量：源选错、抓取残缺、解析脏乱、去重不净，后面的切块、嵌入与重排都只是在噪声上做优化。

## 摄取链的六段

1. **选源**。官方 API、批量导出、站点地图/RSS、页面抓取、搜索发现，按覆盖、时效、成本与合规逐层降级。
2. **发现**。从种子、站点地图、链接、搜索与变更通知里得到候选 URL，去重并排优先级。
3. **抓取**。处理 HTTP 语义、会话、超时、重试、限速与渲染；静态页优先，动态页再上无头浏览器。
4. **解析**。把 HTML、PDF、Office、图片转成正文、标题、作者、时间、语言与结构。
5. **清洗与去重**。去导航、广告与页脚，按 URL 与内容指纹合并重复，保留来源与版本。
6. **增量与质量**。按变化频率调度重抓，监控覆盖率、成功率、新鲜度与正文比例。

## 先选源，再写爬虫

> 判断：能用官方 API 或导出，就不要抓页面；能用站点地图或 RSS，就不要猜 URL；能增量更新，就不要全量重抓。

爬虫只是“取”的一段，不是摄取层的全部。只把抓取做快，解析与去重不做，最终进索引的仍是重复、残缺、过期的文本。

## 三个常见失败

- **只追数量**。页面越多不等于知识越多；低质量页面会稀释检索结果，还会让评估失真。
- **没有版本与时间**。同一页面反复抓取却不记录抓取时间、ETag 与内容哈希，无法判断新鲜度。
- **把反爬当技术对抗**。遇到访问限制，优先走官方 API、申请授权、降低频率；绕过访问控制不是工程方案。

## 一句话主线

先把数据源、抓取、解析、去重、增量与质量串成一条可观测的链，再谈切块与检索；摄取层的噪声会一路传到答案。
