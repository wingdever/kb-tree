# 上下文增强切块：Contextual / Late / Agentic

这些方法攻击同一个问题：**一个块脱离它的文档就失去意义**——代词、交叉引用、隐含主语让独立块成为无法理解的碎片。

## Contextual Retrieval（Anthropic 2024）

嵌入前，用 LLM 从整篇父文档派生每个块专属的简短上下文并前置，让块"自描述"。例如"revenue grew 3%"加上"这是 Q3 财报中北美区的收入"。

- 检索失败率相对标准分块降低最多 **67%**：单独上下文嵌入降 35%，上下文嵌入 + 上下文 BM25 降 49%，再加 reranker 降 67%。
- 显著改善代词与交叉引用查询。
- 成本：每块一次 LLM 调用。1 万文档的一次性成本约 **$25–50**（Haiku/GPT-4o-mini），ROI 优秀。注意这只是索引期一次性成本，不是每查询成本。
- 文档变化时注释需重写；错误注释会误导检索，需抽查。

## Late Chunking（Jina 2024）

反转标准顺序：先用长上下文嵌入模型嵌入整篇文档，再切分 token 嵌入。每个块的向量都携带文档级上下文——"它增长了 12%"这样的块仍保留"它"指代什么的痕迹。

- 无需每块一次 LLM 调用，但需要长输入嵌入模型。
- 适合：引用密集、后文依赖前文的长文档（合同、手册、论文）。
- 与 Contextual 理论上可叠加，但两者解决同一问题（context loss），实践收益不显著。

## Agentic / Propositions 切块

LLM 通读文档，按语义逻辑决定切分点——真正的语义理解，而非启发式。

- 质量最高，但每文档需 LLM 推理，比固定大小贵 **10–50×**。
- Propositions 方法：把文档拆成原子命题（fact-checking 场景最大精度）。
- 适合：高价值关键文档（合同、规格、小集合）。

## 三者的取舍

| 方法 | 上下文从哪来 | 成本 | 对哪类问题最有效 |
|---|---|---|---|
| Contextual | LLM 生成的文本注释 | 每块一次 LLM 调用，索引期一次性 | 代词、跨引用、需溯源的查询 |
| Late | 长上下文嵌入的隐藏状态 | 一次整篇前向（注意力二次），需长输入嵌入模型 | 局部引用密集（论文、合同、手册） |
| Agentic / Propositions | LLM 对语义的理解 | 10–50×，最高 | 高价值关键文档、事实核查 |

Contextual 与 Late 解决的是同一个问题（块脱离文档丢失上下文），原理不同但目标一致，实测叠加收益不显著——选一个即可。Agentic 是另一维度：它连"边界在哪"都交给 LLM 判断，成本最高。

## 与其它策略的组合

三者都是**叠加层**，可作用于任意基础/语义切块之上：

- **Contextual + Parent-Child**（生产推荐）：结构感知切父块，语义切子块，再给子块加上下文。报告 recall@5 **90.5%**、答案质量 **88.3%**，优于任一单独使用（`Contextual alone` 88.2%、`Parent-child alone` 84.1%）。
- Contextual 尤其适合与混合检索配合——它让同一个块同时携带语义信号和可被 BM25 命中的关键词（公司名、季度、主题）。
