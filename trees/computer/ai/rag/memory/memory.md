# 记忆系统：让 Agent 跨步骤、跨会话携带状态

没有记忆的 Agent 像金鱼，会无限重复同样的错误。记忆决定它是否重复检索、忘记用户上下文，或跨会话学到东西。向量库记忆只是实现语义召回，**不会训练模型**。

## 短期记忆（工作记忆）

- 当前会话、草稿纸、即时任务状态、中间推理。
- 存在于上下文窗口内。
- **危险**：上下文很快被填满。若工具返回 10,000 行 JSON，Agent 会"迷失在中间"、忘记原始目标。必须在把工具输出作为 Observation 反馈前积极截断或摘要。
- 保持精简，用摘要控制 token 与成本。

## 长期记忆

- 持久化事实、过往决策、用户偏好、稳定属性（如客户套餐等级）。
- 存数据库或向量存储，相关时检索出来，而不是全塞进提示词。
- Mem0 等框架把 RAG 重构为"Agent 的记忆"——API 极简（add / query），擅长跨会话存储用户偏好与上下文，自动相关性打分。

## 记忆层级（类似缓存层级）

| 层级 | 内容 | 存放 |
|---|---|---|
| 热 | 任务内即时状态 | 留在窗口 |
| 温 | 近期上下文 | 可压缩摘要 |
| 冷 | 持久事实 | 长期存储，按需检索 |

## 状态与检查点

对长运行或多步骤 Agent，持久化状态使运行可以：失败后恢复、人工交接后继续、不必从头开始。LangGraph 用 checkpointer + `thread_id` 实现。

## 记忆治理

> 无边界的记忆会变成成本问题、相关性问题和隐私问题。

- 只存储能改善结果的最少内容。
- 明确留存策略与删除策略。
- 谨慎处理个人数据。
- 记忆投毒：错误内容进入共享记忆，下游 Agent 当作事实，准确率逐渐衰减且根因难查。

## 与上下文工程的关系

记忆系统与上下文工程是同一问题的两面：前者管跨会话持久化，后者管单会话内窗口管理。
