# 语义层（Semantic Layer）

对结构化数据与 KPI，向量搜索得分接近零——"上季度各地区收入"应走 SQL/语义层，不是向量检索。语义层把指标定义一次、集中治理，让 LLM 查询的是**定义**而非原始表，由定义编译出精确 SQL 交给数据库执行。

## 子知识点

- **Text-to-SQL**：生成技术本身——五阶段管线、schema linking、基准、失败模式、安全护栏与工具。

语义层与 Text-to-SQL 是"约束 vs 生成"的互补：本页讲如何**治理定义**（让模型从封闭指标集选），子页讲如何**把自然语言生成 SQL**（以及为什么裸生成在企业 schema 上会失败）。2026 更强的模式是 text-to-semantic——让 Agent 输出结构化请求给语义层编译，而非直接写 SQL。

## 核心思想：模型查定义，定义查数据

LLM 不直接写 SQL 查原始表，而是把用户问题映射到一个**封闭的、受治理的指标集合**（gross profit、按季度、筛选 West 区），语义层把该请求编译成 SQL，数据库执行。

- **hub-and-spoke**：hub 集中定义指标（dbt 模型旁的代码，如 "Average Order Value"、"Customer Lifetime Value"）；spoke 自动把定义编译成各端点所需 SQL，供 BI、数据科学、LLM/GenAI 消费。
- 一处定义变更，所有 spoke 同步生效。
- 这就是**确定性 AI**：执行是确定的（同一问题同一 SQL 同一结果），不确定的只是意图映射。

## 为什么对 AI 关键

- **消除指标歧义**："Revenue" 在销售部指 gross bookings、在财务部指 ASC 606 确认收入。无治理层时 LLM 同时检索两者，合成自信但错误的答案。治理型业务术语表给每个术语一个 owner、验证过的定义、明确适用范围。
- **失败会"响"**：向原始 text-to-SQL 问一个它不懂的指标，返回自信的错误数字；向语义层问，返回错误——因为该指标未定义。**用"响亮的未答"换掉"静默的错答"**，在财务报告中这是决定性差异。
- **权限按 grant 而非提示**：层只暴露发布的指标与维度，行级规则在查询期应用；敏感列不在模型的词汇表里，而非靠提示词请求它别看。
- **编译出的查询即审计轨迹**，透明性是架构属性，不是事后日志项目。

## 准确率证据

- dbt Labs 2026-04 厂商基准（11 个问题）：语义层 98–100% vs 原始 text-to-SQL 84–90%。基准小、厂商自测，方向一致且差距不小。
- 另一 2026 dbt 基准：某模型 90.0%→98.2%，另一 84.1%→100%。
- 生产系统（维护良好的 YAML 语义模型）text-to-SQL 准确率可达九成上下：Snowflake Cortex Analyst、Databricks Genie、Vanna AI + Defog SQLCoder 在复杂比率查询上均报告相近水平。
- **无语义层时**裸 LLM 对原始 schema 约 57%（Spider 2.0 真实企业任务最佳 Agent 仅 21.3%）——瓶颈是 **schema 误解，不是语言理解**。
- data.world 基准：GPT-4 在原始 SQL 上答对企业问题的比例很低，在同一数据的事实图谱上大幅提高。

## 构建五步（从业务问题出发）

1. **能力问题（competency questions）先行**：写下模型必须回答的问题，它们成为验收测试。
2. **定义指标一次**：每个 measure 声明公式、粒度（grain）、过滤、允许维度，作为版本化定义（代码中的 YAML/DBT，改动走 PR）。
3. **建模实体**：定义实体、关系、粒度。
4. **加约束**：命名规则、治理策略、图约束；用 SHACL 或约束校验。
5. **验证并治理**：用财务/运营已信任的数字校验输出；分配 owner、血缘到术语表、变更控制下演进。

实践建议：**给模型指标 API，而不是 SQL 提示**——把认证指标暴露为可调用函数，模型输出结构化请求，从封闭列表选，无法编造列或误读 join。先用少量核心指标起步，拿历史数据回测，与人工报告基本一致再上线。

## 与向量/图的分工

| 存储 | 装着什么 | 回答什么 |
|---|---|---|
| 向量库 | 文档语义 | "找那段话" |
| 语义层 | 指标、维度、join、过滤、访问规则 | "精确、受治理的数字" |
| 知识图谱 | 实体与类型化关系 | "为什么/关系路径" |

经验法则：**向量找文档、语义层算数字、知识图谱解释关系**。本体让三者说同一种语言。像"为什么 West 区利润率下降？"这样的 Agent 问题，需要语义层的利润率指标 + 图谱的供应商/工厂关系 + 向量检索到的合同条款，三者组合。
