# 自检型 RAG（Self-Correcting RAG）

经典 RAG 检索到错文档仍照单全收，模型会自信地给出错误答案——它无从知道检索上下文无关。自检型 RAG 加一个反馈循环：评估检索上下文，决定原样使用、精炼搜索、还是换源，再生成。到 2026 年，这已是处理非平凡问题的生产 RAG 的标准配置。

## 三大参考模式

### Self-RAG（评答案）

Asai et al. 2023（ICLR 2024）。**微调单个模型**发射特殊反射 token，把整个 RAG 循环放进一个模型内部：

- **Retrieve token**：是否调用检索器——可自适应按需检索（生成中多次检索，或完全跳过）。
- **ISREL**（Is Relevant）：检索段落是否回应查询。
- **ISSUP**（Is Supported）：生成论断是否被段落支撑。
- **ISUSE**（Is Useful）：回复段的整体效用。

推理时通过 token 概率做软约束（控制检索频率）和树解码（segment 级 beam search 选最佳延续）。7B/13B 模型在开放域 QA、推理、事实验证上超过 ChatGPT 与检索增强 Llama2-chat，长文本生成的 factuality 与引用准确性显著提升。

- 优点：紧集成、自适应决定是否检索、细粒度段级核验。
- 缺点：需微调底层模型（控制权重）、不够开箱即用；闭源 API 模型不可用；模型自评能力差时（比厂商承认的更常见）会自信批准错答。

### CRAG（评文档）

Yan et al. 2024（arXiv:2401.15884）。在检索与生成间加一个**独立的轻量检索评估器**（Haiku 4.5、GPT-5-mini、Llama-3-8B 或微调 T5），对每篇文档打分，三分支：

- **Correct**（相关）→ 直接生成。
- **Ambiguous**（部分相关）→ 改写查询再检索，然后生成。
- **Incorrect**（无关）→ 丢弃上下文，走兜底源（web 搜索、另一个向量索引）。

关键设计选择：**不烧一次完整 LLM 前向去检查检索质量**——评估器小而快。生成前还有 decompose-then-recompose 步骤滤掉无关材料。

- 优点：简单、便宜、生产友好；2026 部署最广的自检模式。
- 缺点：评估器校准差会误拒好上下文或误收坏上下文；web 兜底至少多一次网络往返 + 重组计算，是最慢分支。

### Adaptive-RAG（评问题）

在管道前放一个**复杂度分类器**：简单事实问题完全跳过检索，中等走单跳向量检索，复杂多步问题走完整 agentic 循环。由于 60–70% 生产查询是简单的，这能大幅省成本而不牺牲难题质量——**对混合负载是事实上的架构决策**。2026 起部分托管搜索服务（如 Azure AI Search 的 `retrievalReasoningEffort: auto`）把自适应做成配置：先跑轻量检索，接地不足才升级到 LLM 查询规划。

- 优点：可为净负成本（一次轻量分类省掉下游检索与生成）。
- 缺点：误分类——复杂查询走廉价路径，错答且无恢复。

## 成本与质量实测

| 模式 | 单次成本 | 准确率 |
|---|---|---|
| Naive RAG | $0.012 | 73% |
| CRAG | $0.018（+50%） | 86%（+13 点） |
| Self-RAG | $0.024（+100%） | 88%（+15 点） |

成本质量的账几乎总是偏向 CRAG。Self-RAG 留给"多出的两点确实重要且有微调预算"的场景。注意 Agentic RAG 整体 token 成本是简单 RAG 的 3–10×、延迟从 1–2s 升到 4–15s（p95）。

## 评估器该查什么

2026 最佳实践：**查三样而非只查相关性**——相关性（是否切题）、具体性（是否含问题要的具体事实）、时效性（是否来自匹配问题的时间窗）。一篇文档可能相关又具体但已过时——不查时效性的 CRAG 会用去年的事实回答今年的问题。

生产 CRAG 的评估器通常在领域样本上微调（通用网络内容训练的评估器在专业词汇上校准差），并用生产运行的反馈做持续再训练。

## 组合与层叠

三种模式正交，**按真实存在的失败叠加而非默认全上**：

- Adaptive-RAG 路由 + CRAG 评估器跑在实际检索的分支上 = 最稳健生产架构之一。
- CRAG 粗粒度质量门（快而便宜捕捉大失败）+ Self-RAG 段级 ISSUP（细粒度抓事实错）。代价是要同时维护外部评估器与微调生成器。
- 三者都有 LangGraph 官方参考实现，是上手感知差异的最快方式。

## 何时自检会表现不佳

- 平凡问题（任何检索都行）——评估器纯属开销。
- 单文档语料（有检索就命中正确文档）。
- 延迟敏感场景（额外评估往返不可接受）。

**更便宜的第一步**：语料干净时，重排器 + 相关性阈值就够——自检只在它不够时才加。
