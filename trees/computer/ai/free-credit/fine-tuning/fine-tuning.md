# 微调学习的免费算力

学微调最先卡住的不是算法，而是显存：7B 模型全参训练要上百 GB，但用 LoRA/QLoRA 把可训练参数压到千分之一、把权重压到 4 bit，一张 16–24GB 的消费级卡就能跑通。所以"免费能不能学微调"的答案取决于两件事：**额度是按周刷新还是一次性给完**，以及**单次会话能不能撑到存下 checkpoint**。

## 三种免费来源

| 类型 | 典型形态 | 对学习的意义 |
|---|---|---|
| 周期性定额 | 每周固定 GPU 小时，用不完清零 | 唯一能长期排计划的类型，适合当主线 |
| 一次性初始额度 | 新用户注册送若干小时，用完即止 | 适合集中跑一次完整实验，不适合反复调参 |
| 签到 / 积分制 | 每日登录领算力点，兑换实例时长 | 额度碎，适合保持手感，不适合长训练 |
| 厂商试用金 | API 或托管训练平台送一笔金额 | 多为一次性，且数据要上传到对方平台 |

> 判断：把"一次性额度"当"每周额度"来排期，是新手最常见的浪费——第一周跑完，第二周才发现没有额度可用。

## 显存门槛

训练方式决定了门槛，模型规模只是其中一半：

| 模型规模 | 4-bit QLoRA | LoRA（bf16 权重） | 全参微调 |
|---|---|---|---|
| 0.5B–1.5B | 8GB 可跑 | 16GB 左右 | 单卡 24GB 勉强 |
| 7B–8B | 16GB 可跑（batch 压到 1–2） | 24–48GB | 多卡 80GB 级 |
| 13B–14B | 24GB 可跑 | 48GB 以上 | 多卡 |
| 32B | 48GB 以上 | 80GB 级 | 多机 |
| 70B | 80GB 以上或 192GB 单卡 | 多卡 | 集群 |

显存之外还有两个隐性开销：**激活值与梯度检查点**（开 checkpointing 省显存但慢 20–30%）、**序列长度**（长度翻倍，注意力部分的显存增长更快）。所以同一张卡跑 7B，序列 512 和 4096 是两个难度。

## 会白烧时长的四个细节

1. **实例从启动就开始计时**：环境没装好、数据没上传就开机，等于花钱等 pip。
2. **断线即重置**：非持久目录里的权重、日志、已装包全部丢失，训练脚本必须每 N 步存一次 checkpoint 到持久目录。
3. **数据集体积常被忽略**：几十 GB 的语料上传本身就要几小时，免费额度还没开始训练就消耗了一半。
4. **自动关停不等于保存**：闲置超时是直接停机，不会替你落盘。

> 判断：先用 CPU 环境把数据管线、tokenizer、评测脚本全部跑通，再开 GPU 只跑训练——同样的额度能多跑两三轮实验。

## 学习路线

1. **0.5B–1.5B 跑通全流程**：数据格式化 → LoRA → 合并权重 → 基线与微调模型对比评测。一张 T4 一天够，目的是把流程和坑踩完。
2. **7B QLoRA 做一次真实实验**：24GB 档最舒服；16GB 档把 batch 设为 1、用梯度累积补等效 batch，序列长度先压到 1024。
3. **固定随机种子与评测集**：免费额度少，必须让每次实验可比，否则跑完也不知道是数据变了还是超参变了。
4. **把产物外置**：权重推到 Hugging Face 或魔搭，指标写进本地表格；不要指望平台替你长期保存。

## 一句话主线

免费算力足够"学会微调"，但不够"调好模型"：**周期性额度用来排主线，一次性额度用来跑完整实验，显存门槛按 QLoRA 折算，所有产物必须落到持久目录**——真正的成本不是钱，是断线重来的那几小时。
