# 云电脑 Agent 的额度与计价

云电脑 Agent 的免费额度有两个口袋：**模型调用的 token** 和 **云机的机时**。前者常有赠送，后者极少先送。把两者混为一谈，就会出现"额度还剩很多却跑不动任务"的错觉。

## 为什么云机不长期免费

token 是边际成本，云机是固定成本：一台实例要占 CPU、内存、磁盘与 IP，闲置也在计费。所以厂商的常见做法是"送调用、不送机时"，或者把机时打包进订阅，用月费覆盖闲置成本。

判断一笔额度是否覆盖云机，只需问：**它扣的是积分/次数，还是扣的机时？** 扣积分的产品里，积分往往同时折算模型与机时，任务越长消耗越快。

## 五种计价模型

| 模型 | 计费对象 | 适合谁 | 风险 |
|---|---|---|---|
| 纯免费额度 | 每日/每月固定积分或次数 | 试用、验证 | 超额即停，无法做稳定服务 |
| 订阅含机时 | 月费打包云机与用量 | 个人常驻、轻中度使用 | 闲置也付费，超额降速或加购 |
| 积分制 | 模型调用 + 机时统一折算 | 任务型产品 | 长任务消耗不透明，易超支 |
| 按量计费 | 小时 × 配置 | 开发者、企业自建 | 闲置时间也进账单 |
| 席位制 | 人头 × 档位 | 团队采购 | 额度共享，个人感知弱 |

## 免费额度的三个真实边界

1. **限时免费期**。TeleAgent 网页端明确处于限时免费体验期，正式收费方案会另行公告；这类"免费"是推广期，不是长期定价。
2. **积分会过期**。订阅套餐的剩余积分按月清零，加油包各有有效期；囤积分等于给自己制造到期日。
3. **超额不是降级而是停**。多数产品在额度耗尽后直接暂停任务，而不是自动降速；对连续服务来说，这比涨价更致命。

## 每天跑多久：按量与订阅的分界

- **任务零散、每天一两小时**：按量更省。以每小时低个位数美元估算，一个月几十小时的总价通常低于主流订阅门槛。
- **任务需要随时待命、7×24 在线**：订阅更省。按量计费会把闲置时间全额计入，订阅把闲置成本摊平。
- **任务重、单次调用多**：积分制最危险。它把模型与机时混算，长任务的实际消耗往往是短任务的数倍。

一个可执行的算法：先记录一周的真实机时与 token 消耗，按两条曲线分别估算月成本，再和订阅价比较；不要用"感觉免费够用"来做决定。

## 压成本的六种做法

1. 把长任务拆成短任务，减少云机常驻时间。
2. 能用本地执行完成的步骤留在本地，只把必须隔离或必须常驻的部分放上云。
3. 优先选带定时任务的产品，让 Agent 在夜间低价时段跑（部分平台错峰有折扣）。
4. 用免费额度做能力验证，用付费档跑对外服务，两者不要混用同一账号策略。
5. 给积分设余额告警，低于一周用量时决定续费还是降级。
6. 团队采购走席位制，避免每人各买一份高配订阅。

## 一句话主线

云机的免费额度几乎不存在，能免费的通常是 token：**先问扣的是调用还是机时，再按真实用量算按量与订阅的交叉点**，别把限时免费当成长期定价。
