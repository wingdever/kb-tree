# 免费额度台账

一个人用一家的免费额度不需要台账；同时用三四家、额度类型各不相同、到期日各不相同，就需要。台账解决三个具体问题：**还剩多少、什么时候没、没了换哪家**。

## 台账记什么

| 字段 | 为什么要记 |
|---|---|
| 平台与账号 | 同一平台可能有个人号与企业号，额度不通用 |
| 模型 | 额度按模型算的多，不写模型等于没记 |
| 额度类型 | 注册赠送 / 活动返还 / 每日领取 / 限时免费模型，用法不同 |
| 剩余量 | 以控制台为准，每周更新，不靠记忆 |
| 到期日 | 赠送额度多为一年期，返还有效期更短 |
| 并发限制 | QPS/TPM 决定能不能承接现场演示或多人群聊 |
| 抵扣范围 | 是否覆盖插件、知识库、批量推理、缓存存储 |
| 绑定项目 | 额度被哪个服务消耗，出问题时能立刻定位 |
| 续用方案 | 到期后付费、换供应商、降级到本地模型 |

## 把额度换算成"能跑多少次"

只记 token 数没有意义，要换算成业务单位：

1. 选一条**代表性任务**，跑十次取平均 token 消耗（含系统提示、工具定义、检索结果）。
2. 算出"额度 / 单任务消耗 = 可完成任务数"。
3. 再乘上并发限制下的可用比例：QPS 低时，任务数够但排队会让体验崩。
4. 按任务数决定用途：几十次用于联调，几千次可用于灰度，上万次才能谈小规模运营。

换算表要随任务形态更新——提示词一变，单任务消耗就变。

## 到期与预警

- **两级预警**：到期前一个月提醒决策，到期前一周提醒切换。
- **余量预警**：剩余量低于两周用量时触发，不要等到失败才发现。
- **活动类单独标记**：活动额度不设"续用方案"，只设"结束日期"，到期即从规划里移除。
- **自动降级**：接近上限时切到便宜模型或本地模型，比直接报错体验好。

## 账号与共享

- 企业账号下的子账号共享额度，团队共用时指定"谁可以消耗哪份"，否则一个实验会把线上额度吃掉。
- 基础模型与精调模型共享额度，精调实验要单独留预算。
- 不要把个人额度混入公司服务：条款、数据归属与账单都对不上。

## 切换方案

额度到期前先准备替代，而不是到期再找：

- **同平台升级**：确认付费套餐单价、QPS 与是否仍优先消耗剩余额度。
- **换平台**：把提示词、工具 schema、评测集按可迁移方式组织，切换时只换调用层。
- **降级本地**：小模型自部署能兜住分类、摘要、格式校验这类高频低难度任务，把付费额度留给难任务。
- **混合路由**：按任务难度分流，便宜模型处理大多数请求，贵模型只处理少数。

## 月度核对

每月做一次三行核对：账单金额与台账剩余是否一致、到期日是否更新、绑定项目是否变更。发现偏差先查"是否有未记录的调用方"，再查"额度是否被共享账号消耗"。

## 常见失败模式

| 现象 | 原因 | 修法 |
|---|---|---|
| 演示当天调用失败 | 额度在演示前耗尽或到期 | 演示前一周核对余量与到期日 |
| 账单出现"免费期仍扣费" | 调用了不抵扣的项（插件、批量、缓存存储） | 台账单列不抵扣项，预算里留出 |
| 团队互相吃额度 | 主账号共享未做分配 | 按项目分配子账号与模型 |
| 换平台后效果下降 | 提示词与工具 schema 绑死原厂商 | 调用层抽象，评测集先在两家跑通 |

## 一句话主线

台账的价值是**把"免费的幻觉"变成可核对的数字**：剩多少、能跑多少次、什么时候没、没了换谁——四件事写清楚，薅羊毛才不至于在关键节点翻车。
