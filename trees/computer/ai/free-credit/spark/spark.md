# 星火免费额度

星火（iFlytek Spark）给开发者的免费资源分三处，容易混在一起：**开放平台的能力套餐、星辰 MaaS 平台的活动额度、以及限时免费的小模型**。三处的开通入口、有效期、并发限制都不同，先分清再申请。

## 三处额度

| 位置 | 给什么 | 关键限制 |
|---|---|---|
| 开放平台星火套餐 | 个人免费包：200 万 tokens；企业免费包：500 万 tokens | QPS 2、有效期 1 年、需实名/企业认证 |
| 星辰 MaaS 平台 | 活动期可领取大额 token（首页活动位标注"零门槛领取 10 亿 tokens"） | 以活动页规则为准，通常绑定新模型与限时窗口 |
| 模型定价页 | 部分小模型限时免费（如 4B 级端侧模型） | 免费期随定价页调整，能力与上下文受限 |

免费包按 token 计，抵扣的是模型推理调用；语音、OCR、知识库等能力各有独立礼包，不共用同一份额度。

## 免费包能干什么

200 万 tokens 在开发阶段的真实容量，取决于任务形态：

- **单轮问答/分类**：每次几千 token 以内，能支撑较长时间的联调与回归测试。
- **多轮 Agent 任务**：一轮完整任务含系统提示、工具定义、观察结果，几千到几万 token 很常见；跑几十到上百条完整轨迹就会接近上限。
- **群聊机器人常驻**：真正的瓶颈不是 token 而是 QPS 2——同一时刻只能处理个位数请求，多人同时 @ 会排队。

因此免费包的正确用法是**开发联调 + 小流量灰度**，不是对外承诺服务质量。

## 申请与开通

1. 注册讯飞开放平台账号，完成实名认证（个人）或企业认证（企业），认证等级决定拿哪一档额度。
2. 创建应用，拿到 AppID 与 APIKey/APISecret，按文档做鉴权（星火走 WebSocket 与 HTTP 两种接入形态）。
3. 在控制台确认免费包已到账，并核对 QPS、有效期与可用模型列表。
4. 先跑一条最小调用验证鉴权与计费口径，再接入业务代码。

## 消耗策略

- **把系统提示与工具定义压短**：它们按每次调用重复计费，是免费额度最大的隐形消耗。
- **能用小模型先用小模型**：限时免费的小模型适合做格式校验、分类、摘要，把旗舰模型留给真正需要的推理步骤。
- **缓存相同前缀**：支持上下文缓存的接口优先用，重复前缀不必每次重算。
- **限制最大输出**：输出 token 通常比输入贵，给每个调用设上限，避免模型啰嗦把额度写光。
- **按任务记账**：记录每类任务的 token 消耗，找出最贵的一类先优化。

## 容易踩的坑

- **把 QPS 2 当并发能力**：免费包不承诺吞吐，群聊高峰会被限流，错误表现为超时而不是额度不足。
- **以为额度永久有效**：有效期一年，到期未用完作废；项目周期长要先算到期日。
- **忽略模型切换的计费差异**：不同模型单价与上下文长度不同，同一份提示词换模型后消耗可能翻倍。
- **把活动额度当稳定供给**：MaaS 活动额度有窗口与条件，活动结束就没了，不能写进容量规划。
- **免费包与付费套餐混用账单**：开通付费套餐后仍优先消耗剩余免费额度，但超出部分按套餐/后付费计价，对账时要分开看。

## 落地清单

1. 先确认自己拿的是个人包还是企业包，记录额度、QPS、到期日。
2. 用一条真实任务测出"单次任务 token 消耗"，再算免费包能跑多少次。
3. 把提示词与工具定义做一次瘦身，通常能省下可观比例。
4. 给免费额度设一个内部预警线，接近时自动降级到小模型或转付费。
5. 活动额度单独记一行，标注活动结束时间，不进长期规划。
6. 到期前一个月决定：续费、换供应商、还是迁到本地开源模型。

## 一句话主线

星火的免费额度适合**把想法跑通**：200 万/500 万 tokens 配 QPS 2 足够联调与小流量验证，但撑不起对外服务；把它当开发预算，不当生产容量。
