# 模型蒸馏

知识蒸馏（Hinton、Vinyals、Dean 2015 形式化）：训练一个小**学生**模型模仿大**教师**模型的行为——学习教师的输出或输出概率，而非只用真实标签。学生用远低的推理成本达到接近教师的质量。

## 两种核心范式

### 1. Logit 级蒸馏（白盒）

学生匹配教师**每个 token 的完整输出分布**，loss 通常是教师 softmax 与学生 softmax 的 KL 散度，配温度参数软化分布、暴露尾部的"暗知识"。

- 需要跑教师并**存 logits**：70B 教师为 1B token 训练数据产 logits ≈ 1B×32000×2B = **64TB** 存储。只有资金充足的实验室可行。
- 质量最高——每个样本携带完整分布信息（不只是 argmax），收敛更快、同参数下质量更高。
- 需要教师权重（开源/自有）。

### 2. Response 级蒸馏（黑盒）

在教师生成**文本**上训练学生复现，包括推理轨迹。教师输出只是文本、不是概率分布，便宜得多；教师仅 API 可达时**这是唯一选择**。

- 每样本信息密度低，达到同等质量需更多学生训练算力。
- 但生产上经济性好，质量差距小到通常值得选便宜路径。

### 其他变体

- **Feature 蒸馏**：匹配中间层激活，传递更丰富表示，更复杂。
- **Reasoning 蒸馏**：教师生成 CoT，学生学习相似推理（DeepSeek-R1-Distill 采用）。
- **On-policy 蒸馏**：学生自己生成答案，教师给其 token 选择打分——学生从自己的错误中学，而非只模仿教师写的文本。

## 蒸馏数据怎么造

蒸馏数据不是教师答案的堆砌，而是把教师行为转成学生能学的样本：种子任务 → 教师多次采样 → 拒绝采样与验证 → 难例与课程 → 去重配比 → 学生训练。教师信号可以是 logits、最终答案、推理链或 Agent 轨迹；信号越完整，构造与存储成本越高。

## DeepSeek-R1-Distill：工业级案例

DeepSeek 把 R1（671B）的推理行为蒸馏到 1.5B、7B、8B、14B、32B、70B 六个基于 Qwen/Llama 的稠密模型，**用 R1 生成的 80 万条推理数据做 SFT**（response/推理蒸馏，非 logit）。小模型展现出教师的长链推理行为，推理成本大幅下降。

蒸馏版显存与质量（MATH-500）：

| 版本 | 显存 | MATH-500 |
|---|---|---|
| 原生 671B | ~1543GB | 97.3 |
| 70B 蒸馏版 | ~45GB（单 A100） | 94.5 |
| 32B 蒸馏版 | ~22GB（RTX 4090/5090） | 90.1 |
| 7B 蒸馏版 | — | — |
| 1.5B 蒸馏版 | ~3.9GB（笔记本/移动端） | 83.9 |

行业取舍：金融/科研/精密代码用 70B+；智能客服/企业知识库用 32B 性价比最优；个人工具/嵌入式用 1.5B–7B。

> 蒸馏方案细节（来自公开资料整理，说法不一）：常见描述为多阶段——先教师生成高质量 CoT 数据（含拒绝采样：教师生成多条推理路径选最优），课程学习从易到难，再做 SFT；部分方案后续叠加白盒 logit 蒸馏。核心是**不只蒸馏答案，还蒸馏推理过程**。

## 蒸馏与其他优化的叠加效应

蒸馏是训练时决策，但直接决定推理成本，不该被当成"推理团队不管的事"。叠加效果显著：

一个蒸馏 7B 再经 int4 量化（4× 内存降）、PagedAttention + 连续批处理（2–4× 吞吐）、1B draft 投机解码（2–3× 加速）：

- 70B fp16 朴素服务：~50 tok/s，$14/Mtok
- 蒸馏 7B int4 全优化：~500 tok/s，$0.30/Mtok
- ≈ **50× 成本下降 + 10× 延迟改善**，质量在多数任务上为原始的 90–95%。

> 观点：蒸馏是最被低估的推理优化，因为"它需要训练"，而多数推理团队不做训练。赢在推理经济性的团队会闭环：测量推理成本 → 找到满足质量目标的模型尺寸 → 训练或定制该尺寸的蒸馏模型。

## 同行案例

- Gemini 1.5 Flash 由 1.5 Pro 蒸馏而来；Gemma 3 技术报告称每个 Gemma 3 模型都用知识蒸馏训练。
- Llama 4 Maverick 由更大的 Behemoth 共同蒸馏（codistillation）。
- Qwen3 小模型用"强到弱蒸馏"。

## 局限

- 学生**很少超过教师**。
- 在教师靠通用推理处理的分布外输入上，蒸馏会退化；创意/开放任务上差距比结构化任务更大。
- 蒸馏**继承教师的弱点**（偏见、错误倾向）。
- 蒸馏针对特定能力效果最好，宽泛复制效果差。

## 条款与合规

- 未经许可蒸馏商业模型通常违反服务条款。OpenAI 条款禁止用输出"开发与 OpenAI 竞争的模型"；Anthropic 商业条款禁止"构建竞争产品/服务，包括训练竞争模型"；Google Gemini API 条款禁止"开发竞争模型"或"反向工程、提取、复制任何组件"。
- 2026 年争议升级：2 月 Anthropic 称 DeepSeek、Moonshot、MiniMax 通过约 2.4 万个欺诈账户与 Claude 产生 1600 万+ 次交互；9 月 NSA/CISA/FBI 联合 advisory 指控多家公司针对美国 AI 公司进行工业规模蒸馏活动。相关公司未证实、未经法庭检验。

## 工具套件

蒸馏工具已经分层：黑盒响应蒸馏可直接用 SFT 工具加教师数据；白盒 logit 蒸馏有 TRL、DistillKit、torchtune、ms-swift 等训练器；on-policy 蒸馏与 Agent 轨迹蒸馏还在快速演进。选工具前先确定教师信号与训练范式，不要拿普通 SFT 工具硬做 logit 蒸馏。

## 实践选择

| 场景 | 方案 |
|---|---|
| 有教师权重 + 充足 GPU | 白盒 logit 蒸馏，质量最高 |
| 有教师权重 + GPU 有限 | 灰盒两阶段，知识保留 ~80% |
| 仅有 API | 黑盒 response 蒸馏 + 数据增强，大部分能力可保留 |
| 推理任务 | Reasoning 蒸馏（CoT + 拒绝采样） |
| 多任务 | 混合策略 + EWC/Replay 防灾难性遗忘 |

先确认能否拿到教师权重，再决定白盒还是黑盒；没有权重时，预算应更多投在数据质量与增强上，而不是调蒸馏温度。
