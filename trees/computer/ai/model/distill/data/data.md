# 蒸馏数据构造

蒸馏数据不是把教师答案原样抄下来，而是把教师的行为转成学生能学的样本。教师越强，越要筛；不筛，学生学到的只是教师的错误与模板。

## 四种教师信号

| 信号 | 学生学到什么 | 获取条件 | 成本 |
| --- | --- | --- | --- |
| Logits | 每个 token 的完整分布 | 教师权重与推理权限 | 最高，需存分布 |
| 最终答案 | 输入到输出的映射 | 教师 API 或本地推理 | 低 |
| 推理链 | 中间步骤与解题策略 | 教师能产出可读 CoT | 中 |
| Agent 轨迹 | 工具调用、状态变化、恢复动作 | 可执行环境与轨迹记录 | 高，需环境 |

信号越完整，学生越容易学，但存储、清洗与许可成本也越高。只有 API 时，通常只能做最终答案或推理链蒸馏。

## 构造流程

1. **定义能力边界与种子任务**：先确定要教什么、不教什么；种子任务覆盖真实分布与边界。
2. **教师多次采样**：同一输入采样多条，保留多样性；温度太低会得到一堆近似答案。
3. **验证与拒绝采样**：用单元测试、答案检查器或规则验证，只保留通过且自洽的轨迹。
4. **难例与课程**：把失败、近失败、边界样本单独收集，按易到难安排，不要只喂简单题。
5. **去重与配比**：去掉模板化与近重复样本，混入通用数据，防止学生只会一种题型。
6. **学生训练与评测**：以 SFT 或参数高效微调落地，用独立留出集验证，不用教师评分代替上线评测。

## 难例从哪来

- 教师多次 rollout 里“偶尔成功”的样本：这是最有价值的学习信号。
- 给种子任务加约束、干扰项、错误工具返回，逼出恢复行为。
- 构造“看起来对但实际错”的 hard negative，教学生辨别。
- 反事实与边界改写：换数字、换权限、换失败模式，保留同一能力。
- 不只留最终答案，保留推理链或工具轨迹；只留答案会丢掉“怎么做对的”。

## 质量检查

- **教师错误会被继承**：教师的事实错误、偏见与坏习惯，学生会照学。
- **许可**：教师输出能不能用于训练、能不能商用、能不能训练竞争模型，要先看条款。
- **污染**：评测题与答案不能混进蒸馏数据；教师可能“记得”公开评测题。
- **长度与风格偏见**：教师偏爱长答案，学生会学啰嗦；要控制长度与格式。
- **容量差**：太难或太长的轨迹，小学生学不动；要按学生容量筛难度。
- **多样性**：同一模板生成十万条，不如多任务、多难度、多失败模式的一万条。

## 一句话主线

蒸馏数据的质量不取决于教师有多强，而取决于你从教师那里筛出了多少可学、可验证、可授权的行为。
