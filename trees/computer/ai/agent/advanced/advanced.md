# Agent 专项

这一组回答「通用骨架之上还能往哪深挖」。专项不是另一套理论，而是同一套 harness 在极端约束下的变体：编码 Agent 的约束是**可验证**（测试能判定对错），RL 训练的约束是**可打分**（奖励信号要稳定），云端 Agent 的约束是**可远程接入**。

## 三个专项的差异在哪

| 专项 | 核心约束 | 与其他方向的关系 |
|---|---|---|
| 编码 / 电脑操作 | 结果可被外部工具判定真伪 | 是行动面与 ACI 原则的极限测试场，也是评测最成熟的一类 |
| 强化学习训练 | 需要可重复的环境与稳定的奖励 | 把「提示工程」换成「策略优化」，其余仍是 harness 问题 |
| 云端运行 | 会话、工作区、连接三层必须解耦 | 把本地 harness 搬到远端，新增的是接入与隔离问题 |

## 一个有价值的观察

编码 Agent 之所以成为 Agent 研究的主战场，不是因为程序员多，而是因为**它是少数「对错能被廉价验证」的领域**：跑一遍测试就知道答案对不对，于是可以大规模自动评测、自动改进、自动回归。把这条经验搬到其他领域时，第一件事是找「这个领域的测试」——找不到，就先造一个判定器，否则所有优化都缺反馈。

## 什么时候该进这一组

- 通用模式与评测都搭起来了，任务仍不够好 → 看编码 Agent 的脚手架设计（架构差距常大于模型差距）。
- 想用训练而不是提示来提升 → 看 RL 那一支，先确认环境可复现。
- 要把 Agent 放到云端供多端接入 → 看运维与云端运行形态，别在客户端硬拼传输。

## 一句话主线

通用骨架之上按场景选专项：编码与电脑操作靠可验证性换取质量，RL 训练靠可复现环境换取稳定收益，云端运行靠三层解耦换取可接入性，学习资源则用来补齐体系而不是替代实践。
