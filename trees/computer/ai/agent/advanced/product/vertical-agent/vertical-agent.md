# 垂直领域 Agent 三要素

一个垂直领域 Agent 要真正可用，至少同时具备三样东西：

1. **确定的业务流程**：任务有边界、步骤可列、成功可判定。
2. **私有的领域数据**：模型拿不到、公开网页搜不到、且你有权使用的数据。
3. **可控的执行工具**：Agent 能真正读写业务系统，但权限、幂等、审计与回滚都在掌控内。

这三样不是“加分项”，而是**乘法关系**：任何一项为零，整体就退化为演示。通用模型再强，也只能让演示更顺滑，不能替代流程、数据与执行。

## 三要素关系

流程决定“做什么、按什么顺序”，数据决定“依据什么事实”，工具决定“能改变什么状态”。三者不是并列清单，而是同一条任务链上的三个必要条件；缺一个，链条就断。

## 一、确定的业务流程

“确定”不是“固定不变”，而是**可描述、可复现、可验收**：

- 有明确起点：什么输入触发任务；
- 有明确步骤：先做什么、后做什么、哪些可并行；
- 有明确分支：什么条件走哪条路，异常怎么办；
- 有明确终点：什么状态算完成，谁来确认；
- 有稳定接口：每一步的输入输出能被系统承接。

反例是“帮我处理一下这个客户的问题”。这句话没有边界：可能是查资料、改合同、退款、升级工单，也可能是安抚情绪。流程不确定，Agent 的每一步都在猜，失败也无法归因。

垂直 Agent 的流程通常来自这个行业已经存在的 SOP、工单流、审批流或操作手册。先把流程写成流程图与节点契约，再谈模型；流程越清楚，Agent 越像一个可靠的工具，而不是一个会说话的赌徒。

## 二、私有的领域数据

私有领域数据是垂直 Agent 的**信息差**。它包括：

- 内部文档、制度、SOP、产品手册；
- 工单、客服记录、销售记录、CRM 字段；
- 业务数据库、日志、监控指标；
- 行业特有的非公开语料、案例、标注集；
- 带权限与版本的业务事实。

它和公开数据的区别不在“格式”，而在三件事：**别人拿不到、你有权用、它随业务更新**。只用公开网页做检索，做出来的是通用问答，不是垂直 Agent。

私有数据要过四道关：

- **权利**：采集、存储、使用、跨境是否有授权；客户数据能否进模型上下文。
- **质量**：重复、过期、冲突、缺失；同一问题在三个文档里有三种答案时，Agent 该信谁。
- **更新**：业务变了，索引与向量是否同步；旧版本能否删除。
- **可评测**：有没有一组“标准问题 + 标准答案 + 出处”，能证明数据真的被用上。

数据的使用方式不止 RAG。事实查询、引用与权限过滤优先用检索；稳定风格、固定分类或领域语言可以微调；高频重复的判断可以做成规则或小模型。**选哪种，取决于数据形态与任务，而不是追新。**

## 三、可控的执行工具

只有“会说”的 Agent 是顾问，能“写入”的 Agent 才是执行者。垂直领域的价值往往发生在动作上：建工单、改状态、发通知、下单、退款、排期、生成报表。

但执行工具必须可控：

- **权限最小**：只允许调用完成任务所需的接口，不能拿管理员令牌到处写。
- **输入校验**：参数类型、范围、必填项在工具层校验，不靠模型自觉。
- **幂等**：重复调用不会重复扣款、重复建单、重复发消息。
- **可审计**：谁在什么时间、用什么参数、调了什么接口、结果如何，都能追。
- **可回滚**：写错了能撤销或补偿，而不是只能道歉。
- **有人工门**：高风险动作（付款、删除、对外发布、权限变更）必须确认或审批。
- **失败可解释**：超时、限流、权限不足、业务规则冲突，要返回可处理的错误，而不是一句“调用失败”。

“可控”还包括**不让 Agent 自由上网、自由执行代码、自由安装工具**。开放的工具面越大，提示注入、越权与数据泄露的路径越多。垂直 Agent 的工具集应该是白名单，不是应用商店。

## 为什么是乘法，不是加法

- 有流程、有数据、没工具：它是一个很懂业务的问答助手，只能建议，不能办事。
- 有流程、有工具、没数据：它能操作，但不知道业务事实，容易“正确地做错事”。
- 有数据、有工具、没流程：它有很多能力和资料，但不知道先做什么，输出不稳定。
- 三样都有、模型一般：它可能不好看，但能把事做完；换更强模型是优化，不是从零开始。

所以顺序应该是：**先定流程，再盘数据，再接工具，最后选模型**。模型是发动机，三要素是路、油和方向盘；发动机再强，没有路也跑不起来。

## 三要素自检

做垂直 Agent 前，按这组问题自检：

1. 这个任务能否用一句话说清起点、终点与完成标准？
2. 流程中的异常分支是否有人负责，是否画得出来？
3. 关键事实来自哪里，是否私有、是否有权使用、是否最新？
4. 有没有一组标准问题能证明 Agent 用对了数据？
5. Agent 需要写哪些系统，每个接口的权限是否最小？
6. 重复执行会不会造成重复副作用？
7. 出错能否回滚，能否追溯到具体调用？
8. 哪些动作必须人工确认，确认人是谁？
9. 如果模型换掉，这套流程、数据与工具是否仍然成立？

九个问题里，第 1、3、5 个答不上来，通常还不适合做 Agent；先把流程、数据与接口补齐，再谈智能。

## 常见伪垂直

- **公开数据套壳**：抓公开网页 + 通用提示词，没有私有数据，也没有业务流程。
- **提示词模板**：把行业术语写进系统提示，但没有工具，不能改变任何业务状态。
- **万能助手**：声称什么都能做，实际没有一条流程能被稳定验收。
- **只读顾问**：能查能说，但不能建单、改状态、发通知，价值停在“建议”。
- **无权限工具**：为了跑通，直接给管理员令牌，短期可用，长期不可审计、不可交付。
- **无评测上线**：只有 demo 案例，没有失败样例与回归集，无法证明稳定性。

## 边界

- 不是所有垂直任务都值得做 Agent。流程固定、输入稳定、规则明确的任务，工作流或 RPA 更便宜、更稳。
- 三要素都具备也不等于可商用；还要补评测、成本、SLA、合规与责任边界。
- 私有数据有合规红线：不能因为“模型需要”就绕过授权、脱敏与最小必要。
- 工具可控不等于工具好用；接口设计、错误语义与业务规则同样决定体验。
- 垂直 Agent 的护城河通常不在模型，而在流程沉淀、数据资产与系统集成；模型会趋同，这三样不会自动趋同。

## 一句话主线

**垂直领域 Agent 的价值 = 确定的业务流程 × 私有的领域数据 × 可控的执行工具；模型只是把这些资产组织起来，任何一项缺失，产品都会退回演示。**
