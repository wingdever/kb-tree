# 工作流（Workflow）

工作流是确定性 DAG——节点、分支、转移在开发期固定，LLM 只是其中一个处理节点，**不控制流程**。可配置节点如 text2sql（自然语言转数据库查询）、translate（翻译）等。

## 本质分界线：谁决定下一步

- **Workflow**：流程由开发者/代码预写 → 固定 DAG、分支预配置、结果可复现、易审计。
- **Agent（ReAct）**：运行时控制权交给 LLM → 动态生成路径、目标驱动自主探索、不可预测。

标签滥用是 2026 的普遍问题："用了 LLM 的多步工具链"未必是 Agent。用**确定性光谱**思考更清晰：

| 阶段 | 形态 | 特点 |
|---|---|---|
| 1 | 确定性代码 | 无 LLM，路径固定、输出可复现、成本有界 |
| 2 | AI 增强工作流 | 固定管线 + 若干 LLM 节点，LLM 做窄而受限的工作 |
| 3 | 含 Agent 节点的工作流 | 编排仍确定性（人画图），某些节点有能动性——**多数生产"多 Agent"实在此阶段** |
| 4 | 自主 Agent | 模型自己决定编排，路径运行时涌现 |
| 5 | 多智能体系统 | 多个自主 Agent 协调，交接、共享状态、涌现行为 |

》 阶段 1/2 易治理，阶段 4/5 易扩展；没有全局正确答案，只有针对具体问题的答案。

## 何时用工作流

流程标准化、步骤可完全列出、要求高稳定性：简历筛选、批量文档解析、数据清洗、审批流、固定格式报告、固定 RAG 问答链、标准客服回复管线。优势：成本稳定、易灰度、异常监控简单、适合正式 ToB 生产。

**"多步陷阱"**：5 步 ETL 永远是工作流，绝不应该是 Agent——Agent 用于中间步骤无法预先确定的任务。

每次调用成本：工作流比 Agent 便宜约 5–10×（不需要每步重复 LLM 调用），所以**即使多步任务也先从工作流起步，遇到需要适应的边缘情况再加 Agent**。

## 何时用 Agent

只能定义最终目标、无法预先预测完整步骤：市场调研、多维数据分析、旅行规划、代码排障、开放式研究、需自由组合多工具持续收集信息推理。

## 企业最佳实践：混合架构

**Workflow 做骨架，Agent 做局部节点的大脑**：

- 外层 Workflow 建立业务边界、主流程、异常捕获、人工兜底，保证全局可控。
- 把 Agent 嵌入流程内需要灵活推理的复杂子节点；Agent 只在指定范围自主探索，不突破整体框架。
- 例：智能竞品分析——外层固定流程"拉数据 → [Agent 竞品挖掘分析节点] → 报告模板填充 → 推送"，仅在"信息挖掘"子节点允许 Agent 自由调用搜索与统计工具，任务的起止、输出规范、超时都由外层控制。

多数业务流程 80% 是固定管线、20% 是开放推理——只在那 20% 嵌入 Agent 是落地实战路径。

## 温度与架构协同

- Workflow 场景（严谨业务）低温 0.1–0.3，稳定统一输出、减少随机波动。
- Agent 场景谨慎升温——Agent 本就动态决策，过高随机性易诱发幻觉与无效循环。

## 工程要点

- **先画图再写提示**：每个流程在 LLM 介入前先映射为节点与边的有向图。节点是固定 schema 的 LLM 调用、固定契约的工具调用、或人工门；边是上游输出的 condition。图是代码、进版本控制、有测试覆盖。
- **每个 LLM 节点约束输出**：绑定 JSON Schema 的结构化输出；下游分支读 schema 字段而非自然语言句子。输出畸形时同一节点带 repair 提示重试。
- **风险边界设人工检查点**：写客户记录、发外部消息、转账、改权限的边默认人工门。门是 UI（承载模型提议动作、所用证据、变更 diff），工作流阻塞直到授权人批准/拒绝。
- **像支付系统一样埋点**：图确定性 → 每次运行可复现，存精确提示、响应、工具调用、分支；失败可端到端重放，成本可归因到具体节点，延迟可定位到具体边。
- **LLM 真正挣得价值的场景**：流程本身开放、设计图成本高于运行 Agent 成本（研究、探索式数据分析、一次性信息收集）。
