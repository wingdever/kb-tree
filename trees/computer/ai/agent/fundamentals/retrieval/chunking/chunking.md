# 切分与索引粒度

切分决定索引里最小可检索单位的大小。它是个被低估的决定：切得太大，一次召回塞进太多无关内容；切得太小，一句结论被拆成几段，谁都不完整。改切分往往比换嵌入模型更能改善检索。

## 切分要同时满足四件事

| 目标 | 具体含义 | 切错了的表现 |
|---|---|---|
| **可检索** | 一段话能独立表达一个完整的意思，脱离上下文也说得通 | 召回命中，但读起来是半句话 |
| **可引用** | 引用时能定位到确切的一段，读者能核对 | 只能引到整篇文档 |
| **可更新** | 文档改一处，只重建相关片段 | 改一个字要重建整个索引 |
| **不割裂语义** | 表格、步骤、代码块不被从中间切开 | 表格只剩表头，步骤只剩前半 |

四个目标会互相拉扯：段越小越精确，但越容易割裂。取舍依据是**查询形态**——查条款、查字段的，切小；要综述、要解释的，切大。

## 三种切法

| 切法 | 怎么做 | 适合 | 风险 |
|---|---|---|---|
| **固定窗口** | 按字符/token 数切，带重叠 | 结构混乱的纯文本、日志 | 切断句子、切断表格 |
| **结构切** | 按标题层级、段落、列表、表格边界切 | 有明确结构的文档（规范、手册、代码） | 层级太浅时片段过大 |
| **语义切** | 按主题转折切，或用模型判断边界 | 长文、访谈、没有小标题的报告 | 成本高、边界不稳定 |

实践顺序：**先看结构**。多数文档的结构（标题、编号、表格）比任何模型判断都可靠，优先用它；结构确实缺失时才上语义切。

## 父子块：小块检索、大块供给

一个常见做法是双层索引：

- **子块**（一两句、几十 token）用来做向量匹配，精度高；
- **父块**（所在小节）作为实际喂给模型的上下文，语义完整；
- 命中子块时向上取父块，必要时再补相邻子块。

代价是索引变大（父子两份），收益是"检索要精确、阅读要完整"这对矛盾被分开处理。适合问答型场景；纯摘要场景直接用大块更省事。

## 重叠与元数据

- **重叠**：固定窗口切法要给 10%–20% 的重叠，避免跨界的句子两边都不完整。结构切通常不需要重叠。
- **元数据比正文更重要**：文档标题、版本、生效日期、适用范围、章节路径都该随片段存。过滤与排序靠它们，冲突时也靠它们判断谁更新。
- **章节路径写进片段头**：把"第三章 > 3.2 > 退款条件"拼在片段前，能显著提升语义完整度，也让引用更可读。
- **给片段补上下文**：把整篇文档的摘要拼到每个片段前再索引，是常见的低成本改善手段（Anthropic 的 Contextual Retrieval 走的正是这条路）。

## 增量更新与失效

索引最容易腐烂的地方不是切分，是更新：

- **按文档指纹判断重建范围**：文档内容哈希变了才重建该文档的片段，别全量重跑。
- **删除要传播**：文档下线、条款废止时，对应片段必须从索引里删掉，否则会一直"检索到已废止的规定"。
- **版本元数据是兜底**：同一主题多个版本共存时，靠生效日期与版本号排序，而不是靠相似度。
- **重建期间可读**：双写或别名切换，避免重建时检索直接不可用。

## 特殊内容怎么切

| 内容 | 切法 | 理由 |
|---|---|---|
| **表格** | 整表一段，必要时按行组切并重复表头 | 切掉表头后每一行都读不懂 |
| **代码块** | 按函数或类边界切，保留缩进与文件路径 | 半段代码无法判断用途，也无法复现 |
| **步骤列表** | 整组保留，或按阶段分组并保留阶段标题 | 步骤被拆散后顺序信息丢失 |
| **FAQ / 条目** | 一条一片段，问题作标题 | 天然自足，检索命中最准 |
| **多语言** | 按语言分索引，或保留原文 + 译文对齐 | 混合编码会让跨语言召回变差 |
| **扫描件 OCR** | 按版面块切（标题、正文、表格） | OCR 文本无段落结构，硬切会串行 |

## 失败模式

| 症状 | 根因 | 对策 |
|---|---|---|
| 命中了但读不懂 | 片段被切断 | 结构切 + 父子块回取 |
| 表格变成乱码 | 表格被按行切开 | 表格整体作为一个片段，或转成结构化表示 |
| 同一段反复命中 | 切分过碎且重叠过多 | 减少重叠、合并相邻短块 |
| 改一个字要重建全库 | 没有按文档粒度的指纹 | 文档级哈希 + 局部重建 |
| 检索到已废止内容 | 删除未传播 | 删除流程纳入索引生命周期 |
| 版本混在一起 | 无版本元数据 | 片段带版本与生效日期，检索时过滤 |

## 什么时候不必细切

- 语料只有几十页：整篇塞进提示，切分是多余工序。
- 文档本身就是短条目（FAQ、字典条目、错误码表）：一条一个片段，天然可检索。
- 主要用途是全文阅读而非问答：按章节切即可，不需要父子块。

## 一句话主线

切分的判断标准只有一句：**这一段被单独拿出来，能不能既说得清、又能被引用、还能单独更新**；三者都成立时，粒度就对了。
