# QQ 渠道接入（dsh 生态）

dsh 核心**没有内置 QQ 通道**。所谓「QQ 号 agent」是第三方插件把 QQ 接成 Agent 的前端：QQ 号、群号用于寻址与身份白名单，Agent 循环仍跑在 dsh 里。

## 实现链路

```
QQ 用户 ↔ QQ 客户端 + 协议端（NapCat / Lagrange / LLOneBot / go-cqhttp / SnowLuma）
       ↔ OneBot 11 HTTP / WebSocket
       ↔ dsh QQ 渠道插件（Cordis 插件）
       ↔ dsh Agent 会话（私聊、群聊通常各一个）
```

插件把 OneBot 事件转成 Agent 上下文：解析 CQ 码、下载图片、语音转文字（STT）、展开引用与合并转发；出站则调用 `qq_*` 工具发送文本、图片、语音或 TTS。常见工具包括 `qq_status`、`qq_send_private`、`qq_send_group`、`qq_history` 等。

## 两类身份：官方 Bot 号 vs 真人 QQ 号

QQ 渠道的第一处分叉不是插件选型，而是 **Agent 以什么身份出现**。

| 维度 | 官方 Bot 账号 | 真人 QQ 账号（协议端接管） |
|---|---|---|
| 身份来源 | QQ 开放平台的 AppID + AppSecret，机器人/服务号 | 一个具体的个人 QQ 号（通常用小号） |
| 登录方式 | 填凭证，不扫码、不碰个人号 | 协议端扫码登录个人 QQ，需保活 |
| 能力边界 | 官方接口开放范围；未开放的能力（如踢人）拿不到 | 接近真人客户端全功能：私聊/群聊/图片/语音/文件/资料/群管理 |
| 主动消息 | 受严格频控，用户可在客户端关闭接收 | 等同真人账号行为，但触发风控 |
| 账号风险 | 无个人号封号风险 | 违反腾讯用户协议，风控、掉线、验证、封禁 |
| 稳定性 / 资源 | 官方接口，纯 HTTP + WS，资源极低 | 协议端常驻，内存几百 MB 起，协议变更即挂 |
| 适合 | 个人助理、受控服务号 | 需要「像个真人」的深度玩法 |

**「官方机器人只能和自己通信」是不准确的。** 官方文档写明机器人可在单聊、群聊、频道三种场景收发消息；个人开发者、沙箱或未过审阶段常表现为只有创建人/授权测试账号能聊，那是**权限状态**而非协议限制。正式进群服务多人需要相应权限与发布流程。

官方消息分主动与被动：

- 被动回复要带 `msg_id`：单聊有效 60 分钟、每条消息最多回 4 次；群聊有效 5 分钟、最多 5 次。
- 用户可在 QQ 客户端关闭「允许主动发送」，关闭后主动消息一律失败。
- 主动消息频控：认证账号 10 QPS，未认证 5 QPS 且 30 QPM；单关系 20 QPM，每个好友每天最多 1000 条。
- 互动召回：用户主动对话后，机器人可在 4 个周期内各下发 1 条（当天、1–3 天、3–7 天、7–30 天）。

还有**混合做法**：官方 API 做主体，自己的号补官方没开放的能力（例如用面板扫码补踢人）。两类身份不是绝对互斥。

## 关键设计点

- **会话映射**：QQ 号 / 群号决定进哪个 dsh 会话；复杂插件按房间隔离记忆与技能可见范围。
- **准入**：被 @ 或叫昵称才进队列，其它群消息按概率判断，避免无关群聊挤占上下文。
- **拟人化与限流**：回复有随机延迟、长度上限、按群串行与每小时次数上限。
- **管理面**：人格 prompt、QQ 号白名单、监听群、回复概率、冷却时间、用量统计，多在 Web 面板配置。
- **记忆与技能**：复杂插件自带日记 → 结构化记录 → 检索的长期记忆。

## 插件生态对照

以下来自各插件 hub / README 摘要，不是 dsh 官方能力清单；收录不代表背书。

| 插件 | 定位 |
|---|---|
| `dsh-qq-onebot` | 通用 OneBot 11 通道；私聊/群聊、语音、图片、戳一戳、表情、点赞 |
| `dsh-napcat-bot` | 内置 NapCat 二进制，自动开 OneBot HTTP/WS、扫码登录；带人格、记忆、TTS、主动发言 |
| `dsh-qq` | 六个 `qq_*` 工具 + 群自动回复概率 + Web 面板 + 限流，纯 Node 内置模块 |
| `dsh-qq-bridge` | 保守方案：DSH→QQ 单向转发 + 轮询 QQ 历史反向收信；总开关默认关、试运行默认开 |
| `dsh-channel-qq` | 深集成：细粒度工具合并为动作组，长期记忆夜间整理，技能按房间可见，可选向量检索 |
| `dsh-qq-bot` | 支持 OneBot 11/12、Satori、Milky 与 QQ 官方机器人接口；拥有者留空时默认拒绝驱动会话 |

## 合规与安全

- NapCat 这类是**QQ 协议端**，跑在你自己登录的 QQ 客户端上，**不符合腾讯用户协议**，存在风控与封号风险。
- 能用 QQ 官方机器人接口就优先用官方；用协议端时建议小号、隔离设备、不发垃圾消息。
- 安装的是第三方代码，装前审源码；token、真实 QQ 号、本机路径不要贴到公开 issue。
- dsh 仍是开发者预览，插件会声明兼容范围；安装前核对 `dsh --version` 与插件要求的版本。

## 落地顺序

1. 先明确是否需要 QQ 渠道——能官方机器人解决就不要上协议端。
2. 选一个**最小通道插件**跑通链路：私聊写入 → 群聊 @ 回复 → 图片/语音。
3. 再加人格、白名单、限流、记忆与技能，逐项验证。
4. 用唯一非敏感测试值验证跨会话召回与房间隔离，确认记忆 boundary 没串。

## 一句话主线

**dsh 的 QQ agent 是「协议端 + OneBot 11 + 渠道插件」把 QQ 桥进 Agent 会话；能力很强但合规风险由使用者承担，先用最小通道跑通再叠人格与记忆。**
