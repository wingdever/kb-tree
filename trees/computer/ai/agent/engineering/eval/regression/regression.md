# 回归评估与门禁

单次评估告诉你"现在大概多好"，回归评估回答另一个问题：**这次改动有没有把已经做对的事弄坏**。Agent 的行为由提示词、工具、检索、模型共同决定，任何一处微调都可能带来静默退化——没有回归门禁，退化会以"用户投诉"的形式被发现。

## 评估集怎么组

一套能用的回归集由四类样本拼成，缺哪类都会留下盲区：

- **黄金集**（30–100 条）：手工挑的关键路径与历史事故用例，覆盖主流程、边界输入、曾经出过问题的场景。每条都要有明确判据，不靠"看起来不错"。
- **合成集**：用模板与生成器造变体（换措辞、换顺序、加噪声），覆盖黄金集没穷举的表达方式。注意合成样本只能证明鲁棒性，不能代替真实分布。
- **线上采样集**：按周或按月从真实流量抽样，标注后并入。它负责发现"用户实际在问但评估集里没有"的分布漂移。
- **对抗集**：提示注入、越权请求、超长输入、空输入、恶意文件。这类样本不需要多，但必须每次跑，且关键用例要求零退化。

## 判据分三层

1. **硬断言**：schema 是否合法、必需字段在不在、工具调用序列是否符合契约、是否越权访问。可机器判定，失败即拦。
2. **软判据**：答案质量、引用是否支持结论、步骤是否合理。用带 rubric 的判分器打分，并抽样人审校准——判分器本身也会漂移。
3. **人工抽检**：按周抽固定比例复核，用于发现判分器与人的系统性分歧。

三层缺一不可：只有硬断言会漏掉"格式正确但答错"，只有软判据则门槛模糊、无法作为门禁。

## 门禁怎么设

变更分级不同，门槛不同：

- **每次变更**跑黄金集 + 对抗集。通过率不得低于基线，**历史事故用例要求 100% 通过**——这是回归门禁的核心。
- **结构性变更**（换模型、换检索、改工具集）加跑线上采样集，并做新旧版本配对比较：同一输入下，退化条数不能超过改进条数（净改进为正）。
- **成本与延迟**也是门禁项：每成功任务成本上升超过阈值要显式批准，而不是默认接受。
- 门禁失败的处理是"定位到具体用例"，不是"重跑到通过"。重跑至绿是评估体系腐化的开始。

## 失败归因：先分类再改

把失败按环节归类，比看总分有用得多：

| 类别 | 典型表现 |
|---|---|
| 检索缺失 | 需要的资料没被召回，或召回了无关片段 |
| 工具选择错 | 该用的工具没调、调了不该调的 |
| 参数错误 | 工具调用参数缺字段、类型错、目标不存在 |
| 推理错误 | 证据齐了但结论错、步骤跳步 |
| 格式错误 | 输出不合 schema、必填内容缺失 |
| 越界 | 越权动作、越范围调用、拒答失败 |

按类统计通过率，才能回答"这次改提示词到底是修好了推理，还是弄坏了工具选择"。只看总分会出现"总通过率没变，但两类都退化了"的错觉。

## 数据卫生

- **评估集不能被喂进提示词或微调集**：一旦泄漏，分数虚高且不可逆。
- **定期去重**：同一问题换措辞的重复样本会放大它的权重。
- **版本化与冻结**：评估集本身要有版本；改动评估集要单独记录，否则分数变化说不清是哪边引起的。
- **失败样本归档**：每次失败的输入、轨迹、判定理由存档，既是回归样本来源，也是排障证据。
- **可复现**：固定温度与随机种子、固定工具桩（mock）、记录本轮使用的模型快照与工具集版本。

## 常见失败模式

- 只跑总量分，不锁定关键用例，退化被平均掉。
- 评估集半年不更新，测的是过时的用户分布。
- 判分器与被测模型同源同版本，自评偏乐观。
- 用"重跑到通过"代替定位，门禁形同虚设。
- 评估集与少样本示例混用，模型在评估集上过拟合。
- 只评答案不评轨迹，工具越权、额外调用这类问题被漏掉。
- 成本与延迟不进评估，质量提升以 3 倍成本为代价却无人察觉。

## 什么时候需要

需要：已上线、有真实用户、会持续改提示词/工具/模型。几乎所有长期维护的 Agent 都符合。

不需要：原型期的探索阶段（此时应该先建黄金集，而不是先建门禁）、一次性的离线批处理任务。
