# 模型选型与路由

Agent 里「用哪个模型」不是一个决定，而是**一组决定**：每个步骤用什么能力、失败时怎么换、预算超了怎么办。选错的代价不是报错，而是**静默的质量下降**——不抛异常、不告警，只是答案慢慢变差。

## 三层决策，别混在一起做

| 层次 | 问题 | 决策依据 |
|---|---|---|
| 单点选型 | 这个步骤需要什么能力 | 工具遵循、结构化输出、上下文长度、领域知识、延迟上限 |
| 分步分配 | 一次 run 里各步骤各用什么 | 每步的难度与失败代价，通常不是同一个模型 |
| 运行时切换 | 失败、限流、超预算时怎么办 | 错误类型 + 剩余预算 + 质量下限 |

多数团队只做了第一层，把「最强模型」铺到所有步骤；真正省钱的杠杆在第二层——规划用强模型、执行与格式化用便宜模型，往往能砍掉一半成本而质量不变。

## 三种路由策略

- **预路由（分类器 / 向量）**。请求进来前判断难度，直接分发。延迟低、无额外生成成本，但**判断错就没机会纠正**，所以分类器校准比准确率更重要。
- **级联（先便宜后升级）**。先跑便宜模型，用验证器打分，不够好才升级。绝大多数请求止步第一层，因此通常比预路由更省；代价是升级时付两次生成，而且**整个效果取决于那个打分器**。
- **混合**。明显简单的直接走便宜模型，边界模糊的走级联。ETHz 的 cascade-routing 工作证明纯路由与纯级联是同一最优策略的两个特例，二者结合通常优于任一单独使用。<RichMediaReference>["https://github.com/eth-sri/cascade-routing"]</RichMediaReference>

## 关键不是路由器，是置信信号

预路由与级联都依赖「这个答案够不够好」的判断，而这恰恰是最容易做坏的一环：

- **模型自报置信不可靠**。模型经常自信地错、犹豫地对，用它当升级信号会同时浪费钱和丢质量。
- **可用信号**：校准过的小分类器、独立验证器（跑测试、查引用、规则校验）、多次采样的一致性投票、conformal prediction 设定阈值。
- **打分器是系统本身，不是附加件**。一个未校准的置信信号，会让级联退化成「更贵的弱模型，偶尔付前沿模型的钱」。

没有可靠事后信号时，**宁可选预路由**——它至少不会因为一个坏信号而把已对的答案升级掉。

## 论文数字与现实预算

文献里的节省幅度很诱人：RouteLLM 在 MT-Bench 上以 95% 的 GPT-4 质量水平节省约 85% 成本（仅 14%–26% 请求走强模型）；FrugalGPT 的级联在部分数据集上接近匹配最强模型而成本下降最高 98%。<RichMediaReference>["https://arxiv.org/abs/2406.18665","https://arxiv.org/abs/2305.05176"]</RichMediaReference>

但这些是**特定数据分布 + 特定模型对**的上限。公平统一评测（RouterArena，8,400 条查询、44 类任务）里，最好的研究型路由器大约只做到 **35% 成本削减、<2% 精度损失**，商业路由器未必胜过开源。<RichMediaReference>["https://arxiv.org/abs/2510.00202"]</RichMediaReference>

> 判断：做预算时按保守的节省比例而不是乐观值。省下来的差额来自你自己的流量分布，不来自论文。

节省幅度还强烈依赖任务类型：结构化抽取、分类、改写这类任务上，便宜模型与前沿模型的差距很小；多步推理、长代码、需要工具编排的任务上，差距会直接变成失败率。

## 选型要评的六件事

榜单分数几乎不覆盖 Agent 真正在意的东西，选型应该按自己的任务集实测：

1. **工具遵循**：给的 schema 会不会被忽略、会不会编参数、并行调用是否稳定。
2. **结构化输出**：是否支持严格模式、复杂 schema 是否被拒。
3. **上下文与缓存**：有效上下文长度、提示缓存是否可用（多轮 Agent 里缓存命中直接决定成本）。
4. **延迟分布**：看 P95 而不是均值，Agent 一轮多次调用会把尾延迟放大。
5. **失败模式**：限流阈值、超时行为、内容拒绝的粒度。
6. **版本稳定性**：同一模型名在小版本间行为可能变化，必须钉版本。

## 兜底与降级

- **按错误类型分流**：参数错不该重试；429/5xx/超时应退避后换供应商；内容拒绝应改路径而不是换模型硬刷。
- **跨供应商兜底**：单一供应商的限流会直接变成产品不可用；至少准备一条异厂商链路，并定期演练切换。
- **降级要显式**。超预算时应该明确告知「本次用了轻量模型、质量可能下降」，而不是悄悄换掉；用户对降级的容忍度远高于对"变笨了"的困惑。
- **配额与预算**：按租户 / 任务设上限，超限中止或转人工，而不是无限重试。

## 上线方式：路由改动必须过门禁

路由策略是最容易"看起来省钱、实际变差"的改动，因为它不改变接口也不报错。正确流程与版本灰度一致：**离线评测 → 影子流量对比 → 小流量灰度 → 自动回滚**。跳过门禁直接全量，等于把质量风险交给运气。

配套需要两个指标：**每任务成本**与**质量下限**（例如关键任务的通过率）。只看总成本会鼓励把难任务也塞给便宜模型，最终省下的钱由客服和返工支付。

## 常见误判

- **按榜单选模型**。榜单测的是通用能力，不是你的工具集与提示。
- **只看单价**。Agent 的成本由「轮次 × 上下文长度 × 输出长度」决定，单价低但输出啰嗦的模型可能更贵。
- **把 LLM-as-judge 当路由器**。判断一次要一次完整生成，延迟与成本都吃掉收益；它适合做离线评估，不适合在线分流。
- **一次上五层路由**。没有埋点就无法判断哪一层在起作用；从两层（便宜默认 + 前沿兜底）起步。
- **路由改了不测**。这是静默退化最常见的入口。
