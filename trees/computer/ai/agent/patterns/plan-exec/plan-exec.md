# Plan-and-Execute：规划与执行分离

如果 ReAct 是"微观管理"，Plan-and-Solve 就是"授权"。它把规划器（Planner）与执行器（Executor）分离。

## 结构

- **规划器**：能力强的大模型（如 GPT-5 级别）读取用户宏观目标，生成一个由子任务组成的有向无环图（DAG）。
- **执行器**：更小、更快、更便宜的模型（如轻量模型）领取子任务，用特定工具执行并返回结果。

示例：用户要求"研究竞品价格并写一份对比报告"。

- 规划器输出：`[任务1: 抓取竞品A], [任务2: 抓取竞品B], [任务3: 对比数据], [任务4: 写报告]`
- 执行器并行运行任务 1 和 2。

## 优势

- 更快：执行阶段可并行。
- 更稳：不像 ReAct 那样容易陷入死循环。
- 更省：把昂贵的规划集中在一次，执行用便宜模型。
- 适用：步骤有依赖、需要事先布局、执行路径可预测的任务。

## 局限

- 规划器一次性定好计划，**执行中看到意外数据不会调整**。
- 如果任务依赖观察结果逐步决定（每步都改变策略），不适合——此时用 ReAct / Reflexion / 混合方法。
- 规划器失败没有重试逻辑时不可恢复。

## 与其他模式的关系

- **vs ReAct**：ReAct 交错推理与行动、每步重读历史；Plan-and-Execute 先全盘规划再批量执行。
- **vs ReWOO**：ReWOO（`../rewoo/`）是 Plan-and-Execute 的特化——用占位变量构成 DAG，规划器完全看不到观察结果，更省 token。
- **vs 编排器-执行器**：编排器-执行器（多智能体模式）是 Plan-and-Execute 在多 Agent 层的动态版本——子任务不是预先固定，由编排器根据输入决定。见 `../../multi/orchestrator/`。
- **vs 层次分解**：层次分解用轻量模型做高层分解、把昂贵模型留给真正需要推理的步骤；有报告称 90% 规划查询路由到小模型可降 87% 成本。

## 规划税（Planning Tax）

规划本身有成本，且存在任务复杂度阈值：低于阈值，规划是浪费；高于阈值，规划有帮助但收益递减。降低规划税的模式包括 ReWOO（前置单次规划）、计划缓存（APC，复用相似任务的计划结构，约降 50% 成本）、层次分解、思考预算（限制推理 token）。
