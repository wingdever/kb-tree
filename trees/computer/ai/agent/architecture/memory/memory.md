# Agent 记忆：让跨会话的「同一个人」成立

记忆常被当成一个存储问题——找个向量库，把对话塞进去。真正难的是四个决策：**写什么、什么时候写、记在谁的账上、什么时候删**。这四个决策错了，向量库越大，系统越糟：检索出的是某次随口说的话，覆盖掉的是用户明确改过的偏好。

这一页按这四个决策组织，不讨论具体数据库选型。

## 一、按功能分四层，不按存储分

| 层 | 装什么 | 典型载体 | 失效方式 |
|---|---|---|---|
| 工作记忆 | 当前任务的目标、计划、中间结果 | 上下文窗口、运行状态 | 窗口满，目标被挤掉 |
| 情节记忆 | 发生过什么：任务、决策、失败、用户当时的要求 | 事件日志、trace | 只追加不提炼，检索出噪音 |
| 语义记忆 | 提炼出的稳定事实与偏好 | 结构化表、三元组、向量 | 事实过期仍被当作现状 |
| 程序记忆 | 做事的套路：技能、工具用法、成功路径 | 提示、技能库、代码 | 环境变了仍照旧执行 |

四层的写入时机、更新方式、失效条件都不同。**最常见的错误是把四层全塞进一个向量库**：情节和事实混在一起，检索时无法区分「用户上周说过一句」和「用户长期偏好」，于是模型把一次性发言当成稳定设定。

> 判断：需要「按时间回看」的进情节层，需要「当事实用」的进语义层。一条内容同时属于两层时，存两份，且语义那份必须带来源指针。

## 二、写：三个触发点，三种形态

触发点决定信噪比：

- **回合末抽取**：一次对话结束，抽取值得留下的内容。稳定但滞后，且容易把整轮都抽进去。
- **事件驱动**：用户纠正、任务完成、出现异常时立刻写。信噪比最高——纠正和失败天然是「值得记住」的信号。
- **被动追加**：全量记录对话。只在需要审计或回放时做，不能直接当记忆用。

形态决定后续能不能改：

| 形态 | 成本 | 可追溯 | 可更新 | 适用 |
|---|---|---|---|---|
| 原文逐字 | 高（token 与存储双高） | 强 | 差（改一处要重写整段） | 审计、争议复盘 |
| 摘要 | 中 | 中（需回指原文） | 中 | 长对话的情节压缩 |
| 结构化事实 | 低 | 需显式带来源 | 强（按 key 覆盖） | 偏好、属性、约束 |

> 判断：写入门槛必须高于读取门槛。宁可不记，也不要记错——错误记忆一旦进入检索池，会被反复召回、反复强化，最后变成系统自己相信的「事实」。

写入时必须带三样东西，否则日后无法判断该不该信：**来源**（哪次运行、哪条 trace）、**时间**（何时成立）、**置信**（用户明说，还是模型推断）。

## 三、读：推还是拉

- **推**（每轮预取固定 k 条）：实现简单，但不管用不用得上都占上下文，成本固定且会稀释当前任务。
- **拉**（把记忆当工具，由 Agent 主动查）：精准，但依赖模型意识到「我该去查」，冷启动任务容易漏。
- **混合**：少量高置信摘要常驻（用户是谁、硬约束、长期偏好），其余走检索工具按需取。

两条硬约束：

1. 注入时必须标明**这是记忆，不是事实**——记忆会过期、会错，模型需要知道它可以被推翻。
2. 记忆与实时状态冲突时，**以实时为准**。用户三个月前说「用中文回复」，这次用英文提问，就该跟英文。

## 四、改与删：覆盖，不是追加

用户说「这个邮箱不用了」，正确做法是：把旧条目标记为 superseded，写一条带生效时间的新条目。错误做法是并存两条，让检索随机命中——模型会时对时错，且没人能解释为什么。

冲突处理按优先级：

1. **来源优先**：用户明说 > 系统观测 > 模型推断。模型推断出来的偏好不得覆盖用户明说的偏好。
2. **时间优先**：同来源下，新的覆盖旧的，但旧条保留可追溯。
3. **显式确认**：两条都可信、时间接近时，向用户确认一次，而不是自行裁决。

遗忘有三种机制，作用不同：

- **TTL**：时效性内容到期即失效（「这周在出差」）。
- **置信衰减**：长期未被验证的推断逐步降权，但不删除。
- **容量淘汰**：按「最近使用 + 价值」双维度淘汰，纯 LRU 会误删罕见但关键的记忆（过敏、禁令、法务约束）。

> 判断：不可删除的记忆系统在合规上等于不可上线。而且删除必须能定位到派生内容——原文删了、摘要和向量还在，等于没删。

## 五、作用域与隔离

| 作用域 | 谁能读 | 谁能写 | 泄漏后果 |
|---|---|---|---|
| 线程内 | 该次运行 | 该次运行 | 低 |
| 用户级 | 同一用户的所有会话 | 该用户 + 系统 | 高（隐私） |
| 租户级 | 同租户内共享 | 经审批的服务 | 高（跨客户污染） |
| 全局共享 | 所有 Agent | 严格审核 | 极高（投毒放大器） |

默认取最小作用域，跨作用域提升要显式审批。共享记忆里只能放**事实**，不能放**推测**——推测进入共享层后会被下游当作前提，错误以指数方式传播，且根因极难定位。

## 六、跨会话的「同一个人」

身份锚点用稳定标识（账号 id），不要用昵称、设备指纹或头像。昵称会改，设备会换，指纹会漂移；一旦锚点漂移，记忆就记到了别人账上。会话内的临时身份（这次以什么角色说话）与会话外的持久身份分开存。

必须有一个 **do-not-remember 名单**，优先级高于任何自动抽取。用户说过「别记这个」，后续所有抽取路径都要先过这张表，包括摘要和向量化。

## 七、成本

记忆的成本在三个环节，任一失控都会让账单翻倍：

- **写**：每次抽取都是一次模型调用。按回合抽还是按事件抽，差一个数量级。
- **存**：向量 + 元数据 + 原文副本。常见膨胀原因是摘要反复再生（每次压缩都新增一条，旧的不删）。
- **读**：每轮注入的 token。预取 20 条、每条 200 token，就是每轮 4000 token 的固定开销。

四个该看的指标：**命中率**（召回的记忆被模型实际引用的比例）、**污染率**（错误或过期条目占比）、**过期率**、**平均注入 token**。命中率低说明写得太多，污染率高说明写得太松。

## 八、五类失败

| 失败 | 症状 | 防线 |
|---|---|---|
| 记错 | 模型把猜测写成事实 | 写入分「观测/推断」两栏，推断不得当事实注入 |
| 记过 | 无关细节全存，检索全是噪音 | 写入门槛 + 命中率监控，命中率低于阈值就收紧 |
| 记重 | 同一事实多条版本并存 | 结构化 key + supersede，禁止同 key 多活跃值 |
| 记串 | A 用户的记忆进了 B 的上下文 | 作用域隔离 + 写入时校验 owner，读取时按 owner 过滤 |
| 删不掉 | 原文删了，摘要与向量仍在 | 派生关系图 + 级联删除 + 删除后探针查询验证 |

## 九、怎么评

四个问题，各自要有可测的指标：

1. 有记忆后任务成功率是否提升（同批任务、同模型、只切记忆开关）。
2. 注入的记忆有没有被误用（把过期的当现状）。
3. 跨会话一致性：同一用户第二次来，是否需要重复交代同样的事。
4. 删除是否彻底：删一条后，用会命中它的查询做探针，确认检索不返回。

> 判断：记忆的效果必须用「关掉它」做对照。没有对照的提升，通常只是提示词变长了。

## 十、落地顺序

1. **先做线程内状态持久化**：让同一次任务能中断后继续。这一步不涉及长期记忆，但解决了 80% 的「忘了刚才做什么」。
2. **再做用户级偏好**：少而准，只存用户明确说过的硬约束，写入时向用户确认一次。
3. **最后做自动抽取的语义记忆**：等前两步稳定、命中率可测之后再开。

跳过前两步直接做自动抽取，得到的通常不是记忆，而是一个会自我强化的谣言库。
