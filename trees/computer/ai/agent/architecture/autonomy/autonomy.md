# 自主性分级：什么时候可以不问人

「这个 Agent 有多自主」常被答成一个等级数字。但等级本身不构成设计：两个都叫 L3 的系统，一个可以自己下单、一个只能改草稿，风险差三个数量级。真正需要定义的是三个维度：**能探索多远、能做多大的副作用、什么条件下必须停下来问人**。

这一页讲怎么把这三件事定成可执行的策略。

## 一、三个维度，而不是一个分数

| 维度 | 取值范围 | 决定什么 |
|---|---|---|
| 探索自由度 | 固定流程 → 自由规划 | 走错路的机会有多少 |
| 副作用权限 | 只读 → 可逆写 → 不可逆写 → 对外发声/动用资金 | 走错路时能造成多大伤害 |
| 打断阈值 | 每步确认 → 只在高风险确认 → 只在异常上报 → 不打断 | 人需要投入多少注意力 |

只看第一个维度会得到「很聪明的助手，但不敢让它动手」；只看第二个会得到「权限很大，但路径不可控」。**级别应是三个维度的组合，不是单一刻度。**

## 二、级别对照

| 级别 | 谁执行 | 副作用范围 | 何时打断人 | 适用域 |
|---|---|---|---|---|
| L0 建议 | 人 | 无 | 始终（输出即建议） | 决策支持、诊断 |
| L1 辅助 | Agent 执行，人确认 | 只读 | 每个动作前 | 检索、分析、审查 |
| L2 限定自主 | Agent | 白名单内的可逆操作 | 出白名单时 | 改草稿、打标签、生成文件 |
| L3 条件自主 | Agent | 含不可逆操作 | 不可逆或超额度时 | 下单、发通知、提交代码 |
| L4 高度自主 | Agent | 广 | 只在异常或超阈值 | 运维处置、批量迁移 |
| L5 全自主 | Agent | 无限制 | 不打断 | 仅封闭域且错误可完全回滚 |

L5 在开放域里基本不成立：不是模型不够强，而是**错误无法被事前发现**。凡是错误只能事后知道的场景，L5 都缺一个兜底。

> 判断：级别由「错误可逆性 + 影响半径 + 可验证性 + 单次错误成本」四项决定，不由开发者偏好决定。这四项里只要有一项是「不可逆、影响外部、无法事前验证、成本高」，上限就是 L3。

## 三、把级别落成策略，而不是提示词

写在系统提示里的「请谨慎操作」不构成约束。自主性必须落成三样可执行的东西：

- **工具白名单**：当前级别允许调用的工具集合，越权调用直接拒绝，不靠模型自觉。
- **额度上限**：次数、金额、影响对象数量、时间窗。额度是分级的真正载体——「可自主退款」若没有金额上限等于 L5。
- **升级条件**：明确列举哪些情况必须转人工（超额度、跨租户、涉及个人信息、外部不可撤回的沟通）。

每个副作用工具要预先标注风险等级，策略按等级而不是按工具名生效：

| 风险级 | 例子 | 默认处理 |
|---|---|---|
| read | 查询、读文件、搜索 | 全自主，记审计 |
| reversible-write | 改草稿、写临时文件、加标签 | 自主 + 事后告知 |
| irreversible-write | 提交、删除、覆盖、部署 | 事前确认或双人复核 |
| external-communication | 发邮件、发消息、发帖 | 事前确认，且显示完整原文 |
| money / legal | 支付、签约、报税 | 强制确认 + 额度 + 留痕 |

## 四、确认的粒度

同一个「确认」有四种粒度，混用会造成两种失败：太粗导致人无法判断，太细导致确认疲劳。

- **会话级**：本次会话内允许这类操作（适合低风险、高频）。
- **动作级**：每次执行前确认（适合不可逆）。
- **参数级**：确认具体参数（金额、收件人、目标路径），适合钱与对外沟通。
- **一次性**：仅此一次，不记忆（适合异常场景）。

授权必须带三个边界，缺一个都会变成永久全权：**作用域**（哪些对象）、**有效期**（到什么时候）、**次数上限**（能用几次）。授权不能自我扩张——Agent 不能给自己或下游 Agent 授予自己都没有的权限。

## 五、升降级

自主性应当是动态的，但两个方向的节奏不同：

**升级要渐进**：连续 N 次同类操作无拒绝、无回滚、无用户纠正，才升一级；且每次升级都显式记录理由。用户显式授权可以跳级，但要有到期时间。

**降级要即时**：出现以下任一信号立刻降级，不需要人工确认——
- 用户拒绝了一次确认（同类操作短期内不再自动）
- 工具失败率或校验失败率上升
- 行为偏离原始目标（例如开始操作与任务无关的对象）
- 输入异常（提示注入特征、越权指令）
- 连续多次需要人工纠正

> 判断：升级靠统计，降级靠事件。用统计决定降级会太慢，用事件决定升级会太激进。

## 六、人在环的三种形态

「有人看着」不是一个状态，是三种成本完全不同的机制：

| 形态 | 机制 | 成本 | 适用 |
|---|---|---|---|
| 事前审批 | 执行前等人点确认 | 高（阻塞） | 不可逆、对外、涉钱 |
| 事中监督 | 实时可见 + 可随时打断 | 中（需在线） | 长任务、影响面大的批处理 |
| 事后审计 | 抽样回看 trace | 低（离线） | 高频低风险，如只读与可逆写 |

高风险场景不能只靠事后审计——事后发现时钱已经付了。反过来，低风险场景用事前审批会让人在第五次点击后开始盲点通过，等于没有确认。

## 七、五类事故

| 事故 | 怎么发生 | 防线 |
|---|---|---|
| 权限蠕变 | 每次「这次特殊一下」，累积成永久宽权限 | 临时授权必须带有效期，到期自动失效 |
| 确认疲劳 | 确认太多，人开始无脑点通过 | 按风险分级确认，低风险改事后告知 |
| 越权代理 | 下游 Agent 拿到上游没有的权限 | 委托链逐级收窄，不可扩张 |
| 静默降级 | 模型自行判断「这个应该没问题」就跳过确认 | 确认由运行时强制执行，模型无权豁免 |
| 审计盲区 | 只记录最终结果，不记录谁授权、授权范围 | 每次副作用记录授权来源与策略版本 |

## 八、指标

只报「自主完成率」会激励系统冒险。至少要成对看：

- **自主完成率**：无人工干预完成的任务占比。
- **确认拦截率**：确认环节拦下了多少本会出错的操作——这个数字高说明分级在起作用，不是坏事。
- **误升级率**：升级后发生回滚或纠正的比例，超过阈值就该降回去。
- **人均干预次数**：衡量注意力成本，不是越低越好。
- **副作用事故率**：按风险级分别统计，钱与对外沟通要单独看。

## 九、落地顺序

1. **只读全自主**：先把检索、分析、审查做到无人工确认，建立信任与审计基线。
2. **可逆写自动 + 事后告知**：改草稿、生成文件，让人知道发生了什么但不阻塞。
3. **不可逆操作走事前确认**：确认界面必须显示具体参数，而不是「是否继续」。
4. **高风险双人复核或额度硬限**：钱、对外发声、删除类操作。
5. **再谈 L4**：只有在事故率、回滚率、审计覆盖都稳定之后。

从 L5 起步的系统通常活不过第一次真实事故——不是因为它错得多，而是因为没有人知道它错在哪一步。
