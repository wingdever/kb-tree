# 多模态 Agent

多模态不是「给模型加个图片输入」这么简单，它改变的是**上下文里放什么**：文字是离散、可压缩、可检索的；图像是高密度、按块计费、难以 diff 的。这个差别决定了多模态 Agent 的成本结构、失败模式和评测方式。

## 三个位置，别混为一谈

| 位置 | 典型场景 | 关键约束 |
|---|---|---|
| 输入 | 用户发来的截图、合同、语音、视频 | 分辨率与数量直接决定 token 成本 |
| 观察 | 工具返回的页面截图、渲染结果、摄像头画面 | 会随轮次累积，撑爆上下文 |
| 输出 | 生成图片、图表、语音 | 需额外的生成服务与审核链路 |

多数团队只规划了「输入」，结果被「观察」拖垮：计算机操作类 Agent 每步一张截图，二十轮之后历史里塞了几十张图，成本和延迟同时失控。

## 第一条判断：能转文本就转文本

同一份信息，用文本表达通常更便宜、更可检索、更好 diff：

- **文档**：PDF 里的正文、表格优先走解析（文本层），保留页码锚点用于回溯；只有扫描件、复杂版式、图表才走原生视觉。
- **音频**：会议纪要、指令类优先走转写（ASR），把文字给模型；只有当语气、情绪、说话人特征本身是信息时才用原生音频。
- **视频**：按时间抽帧 + 转写，而不是把整段视频塞进去；帧率由「变化速度」决定，不是越高越好。
- **截图**：优先取可访问性树 / DOM 文本，截图作为补充证据。

反过来，有些任务必须原生视觉：界面布局判断、图表趋势、印章签名、手写内容、物理世界的状态。这时转文本会把关键信息丢掉。

## 分辨率与成本

图像按「块」计费，尺寸越大块越多，价格与延迟一起涨。可操作的做法：

- **先降采样再发送**。多数界面截图在 1.5 倍缩放下细节仍然够用，原图往往只是浪费。
- **裁剪而不是缩小**。需要看清某个区域时，裁出该区域比整图高分辨率更省。
- **限制单轮张数**。多图会互相稀释注意力，且成本线性叠加；能拼成一张对比图时优先拼图。
- **给截图加元信息**。标明尺寸、缩放比例与坐标系，否则模型给出的坐标无法映射回真实屏幕——这是点击类任务的常见误差源。

同一张图在不同厂商的计费与切块规则不同，选型时必须实测，不能直接套用别家的经验值。

## 工具返回多模态怎么处理

观察类的多模态结果要当成**易失数据**：

- 只保留最近若干张，旧的替换成文字摘要（「第 3 步：登录页，已填邮箱」）。
- 每张图附带结构化描述（页面标题、关键控件、当前状态），便于后续轮次不依赖图像。
- 返回前压缩与裁剪，别把整屏原图回灌。
- 需要精确操作时，用「截图 + 元素坐标表」双通道，让模型不必从像素里猜位置。

## 五类典型失败

- **看不清就编**。模型倾向补全细节而不是承认模糊；提示里要明确允许「看不清，请求更清晰图像或转人工」。
- **坐标漂移**。缩放比例与偏移没有对齐，点击落到错误位置。
- **表格错位**。跨页表格、合并单元格在视觉解析下容易串行。
- **多图顺序混淆**。多张图之间的对应关系（before / after）需要在提示里显式标注，不能靠顺序暗示。
- **模态竞争**。图文同时给时，文字描述可能压过图中真实状态；关键判断应以图像为准并明确写出。

## 评测要按模态分桶

多模态任务的整体准确率没有意义，必须拆开看：

- **抽取类**：字段级准确率 + 幻觉率（图中不存在的字段被填出来的比例）。
- **定位类**：点击命中率、坐标误差分布（像素级），而不是「大致对了」。
- **判断类**：与人工标注的一致率，尤其看「模糊样本」上的表现。
- **成本**：每任务图像 token 占比，以及随轮次的增长曲线。

> 判断：多模态的上限由「输入质量」决定，不由模型决定。先把降采样、裁剪、锚点、元信息做对，再谈换更强的模型。

## 常见反模式

- 把所有 PDF 当图片喂，成本翻十倍、准确率还下降。
- 每轮都回灌全屏截图，上下文被图像挤满。
- 用原生音频做本可以转写的任务。
- 视频按固定高帧率抽帧，绝大多数帧是重复信息。
- 没有「看不清」的出口，模型只能编。
- 只测端到端成功率，不测坐标误差与幻觉率。
