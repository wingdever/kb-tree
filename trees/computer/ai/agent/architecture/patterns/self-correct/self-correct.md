# 自我修正族：Reflexion / Self-Refine / CRITIC

2024–2026 的前沿模型准确率提升，来自推理时修正不亚于原始预训练。同一个模型有无修正循环，在困难任务上相差 8–15 分。2026 的问题不是"要不要加修正循环"，而是"用哪一种"。

核心洞察：**自我修正是一个架构选择——你希望错误信号来自哪里，以及愿意为循环付出多少成本**。

## 五种原型（按错误信号来源）

| 原型 | 增加什么 | 错误信号来源 | 特点 |
|---|---|---|---|
| **Self-Refine** | 单输出的 critique→rewrite 循环 | 同一模型评判自己的草稿 | 最简单、最便宜；相关错误、可能"幻觉式修正" |
| **Reflexion** | 写下的自我批评存入记忆，跨尝试复用 |  agent 自己"上次为何失败"的笔记 | 语言式强化学习，无梯度更新；HumanEval pass@1 91.0（GPT-4 基线 80.1） |
| **Judge-Writer** | 生成者 + 独立评估者分离 | 独立模型的判断 | 部分独立性；评判者有位置偏差等 |
| **CRITIC** | 修订前用外部工具核验 | 搜索结果、代码运行、schema 校验 | 最"生产形状"；工具给硬信号；QA +7.7 F1、数学 +7%、毒性概率降 79.2% |
| **搜索型（ToT/LATS）** | 把问题当搜索空间，回溯内建于推理 | 搜索级价值估计与回溯 | 贵；需可信的价值函数，否则搜索放大噪声 |

## 逐个说明

### Self-Refine（Madaan et al., arXiv:2303.17651）

一个模型产出草稿、批评草稿、重写，无额外训练。适合一次性任务（客户回复只有一次机会）、摘要、对话、数学。弱点：同一盲点在迭代间持续，可能自信地改错。

### Reflexion（Shinn et al., arXiv:2303.11366）

任务失败后，agent 写第一人称自我反思，追加到经验缓冲；下次尝试以此为条件。把反思当作"语言式强化学习"。适合有多次尝试机会的编码、决策、序列推理。弱点：不可重置的任务（发出去的邮件收不回）、反思本身可能幻觉。跨任务尝试的循环，记忆持久化。

### CRITIC（Gou et al., arXiv:2305.11738）

不让模型自我批评，而是让工具批评：搜索、代码执行、打分器。gap 是一个结构化对象：声明、验证动作、返回的证据、把证据绑定到修法的批评。适合事实幻觉是主要失败模式的场景（问答、摘要、研究 agent）。弱点：证据源本身错误或不可用时失效；评判者与提出者是同一模型时自评不可靠。

### Judge-Writer（生成者与评判者分离）

写与判拆给两个角色：一个模型只负责产出，另一个模型（或同一模型在独立会话、换一套提示）只负责评判，输出结构化评分与失败类别，写者按评语改。它没有单一论文出处，是 2024 年后评测实践里自然收敛出来的做法。

- **为什么有效**：同一模型既写又判时，同一条错误信念会同时驱动答案与其批评（下文"内在自我修正很弱"讲的就是这件事）。换模型、换上下文、换提示，能把这种相关性切断。
- **代价**：调用成本从一次变两次起；判官自身带位置偏差、冗长偏差与家族偏好，需要明确量表与标注集校准，否则只是把偏差换了个位置。
- **适用**：开放式写作、方案评审、代码 review——没有硬信号、但需要第二双眼睛的任务。
- **典型失败**：谄媚型判官一律回"看起来不错"，写者在噪声里反复重写。对策是给失败类别清单与打分标尺，并规定分数不达标必须给出可执行的修改点。

### 搜索型：ToT 与 LATS（Yao et al., arXiv:2305.10601；Zhou et al., arXiv:2310.04406）

把推理本身当搜索空间：生成多个候选推理步构成树，用价值函数给节点打分，保留高分分支、剪掉低分分支，必要时回溯。ToT 的价值估计多来自模型自评；LATS 用 MCTS 加反思，并把环境反馈（代码是否通过测试、动作是否成功）作为终值。

- **错误信号来源**：搜索级的节点评估与回溯，而不是单条批评——这让它能纠正"整条推理路走错"，而不只是润色措辞。
- **代价**：调用量随分支因子与深度乘性增长，是这一族里最贵的一种；价值函数不可信时，搜索会放大噪声、把错误分支搜得更"确信"。
- **适用**：目标可判定、步骤可分解、单次失败代价高的任务——数学证明、规划、复杂代码修复。
- **前提**：必须有明确的评分维度与剪枝阈值，否则退化成昂贵的多次采样。

## 重要警告：内在自我修正很弱

论文《Large Language Models Cannot Self-Correct Reasoning Yet》直言：在无外部信号的推理任务上，让模型复查修订自己的工作帮助甚微，甚至降低性能。同一错误信念既驱动原答案，也驱动批评。

**可用信号排序**：
- 工具接地验证（测试、schema、检索引用）最好。
- 重采样一致性检查（多条 CoT 聚合，分歧标记错误）是"修正相邻"的可用不确定性信号。
- 过程监督（逐步评估而非只查最终答案）比结果检查增益大。
- 纯叙述性自我批评最弱。

##  Detect-then-Patch 拆分

所有严肃的 Reflector 都分解为两个函数：

1. **检测与定位**（"错误在哪"）：失败的单元测试（Reflexion）、低 PRM 步骤分（MAGICORE）、与检索证据不一致（CRITIC）、低终值（LATS）。
2. **生成并规划补丁**（"怎么改"）：自然语言反思作为下次提示（Reflexion/LATS）、基于批评的修订草稿（Self-Refine）、基于工具批评的答案重生成（CRITIC）、只重写低分片段（MAGICORE）。

## 生产模式

- **级联修正（cascade reflection）**：先跑生成器 + 快速检查器（尽量确定性）；检查器标记了才跑 critic-then-refiner。多数输出一次通过，平均成本降 50–80%。
- **确定性 critic 优先**：有单元测试/JSON schema/regex/类型检查/数学检查器就用它，信号更锐、成本低一个数量级、无相关偏差。
- **有停止规则的有界循环**：封顶 1–3 轮；每轮前后打分，若修订后更差则回滚。
- **生成者与 critic 用不同模型**：同模型共享盲点。
- **span 附加修正分数**：把 (draft, critique, refined) 作为三 span 记录，附加前后分数，用于漂移检测。

## 常见错误

- 谄媚型 critic：弱提示的 LLM critic 返回"看起来很好"，refiner 在噪声下重写 → 用带明确失败类别的量表式批评 + 标注集校准。
- 无停止规则：第 2、3 轮过度修正。
- 两端用同一模型。
