# Agent 交互设计

协议解决「事件怎么传」，交互设计解决「什么时候该打扰人、什么时候该安静」。同一个 Agent，确认弹得太勤会被盲点通过，弹得太少会让人不敢用；进度做得假会让人失去信任，做得太细会变成噪音。这一页讲的是这些取舍的判据。

## 三条时间尺度

人对等待的容忍度分三段，处理方式完全不同：

| 时长 | 用户感知 | 该给什么 |
|---|---|---|
| 0–1 秒 | 即时响应 | 立刻回显输入已被接收（气泡、光标、按钮态） |
| 1 秒–1 分钟 | 仍在等待 | 阶段名 + 当前动作的人话描述（「正在读第 3 个文件」） |
| 分钟以上 | 已经离开 | 后台继续 + 完成通知 + 可放弃入口 |

三条通用规则来自可用性研究：0.1 秒内算「即时」，1 秒内算「思路不中断」，10 秒是注意力的分界线；超过 10 秒必须有进度反馈，否则用户会转去做别的事。

## 确认：只在关键处打断

每次都确认等于没有确认——用户会形成「一路点同意」的肌肉记忆，真正的风险提示也被一起点掉。该确认的只有四类：

1. **不可逆**：删除、发布、转账、对外发消息。
2. **爆炸半径大**：影响多条数据、多个用户、生产环境。
3. **偏离意图**：Agent 要做的事与用户说的不是一回事（例如用户说「看看」，它准备「改掉」）。
4. **成本突增**：预计花费明显超出常规（批量任务、长循环）。

确认卡片要能让人在三秒内做决定，必须包含：**将要做什么（具体对象）**、**影响范围**、**能否回滚**。缺任何一项，用户只能靠猜。

减少确认疲劳的三种手段：批量确认（把同类动作合并成一次）、本会话授权（「这类操作本次会话内不再问」）、把可逆操作改为「先做后告知 + 一键撤销」。

## 打断与恢复

- **取消要真停**。断开连接常常只断开订阅，任务还在烧钱；取消必须传达给执行端并终止副作用。
- **恢复不能重放副作用**。中断后继续时，已完成的写操作要记在检查点里，否则「继续」会变成「重做一遍」。
- **打断要给缓冲**。人在打字时突然弹窗会被当成干扰；异步任务用通知，同步任务用可取消的进度条。

## 进度与可观测

- **阶段名用人话**。「调用 search_api」不如「正在检索近三年的财报」；技术细节收进展开项。
- **不要假进度**。不知道总步数时用「已完成的工作清单」而不是百分比；假进度条一旦被发现，后面所有提示都会被怀疑。
- **把工具调用摘要化**。展示「查了什么、拿到几条、下一步做什么」，而不是原始 JSON。
- **保留可回看的记录**。出问题时用户要能翻到「第几步开始不对」，这决定了他们敢不敢再试一次。

## 错误与信任

- **错误信息要可行动**：说清哪一步失败、是重试有用还是需要人处理、有没有备选路径。「出错了，请稍后再试」是最差的文案。
- **区分「查到的」与「猜的」**。有来源的结论给出来源；推断给标注。用户对「明说不确定」的容忍度，远高于「一本正经地错」。
- **不要假装确定性**。模型语气自信不代表结论可靠；产品语气应该是「我查到 / 我推测 / 我不确定」三分。
- **失败要可见**。静默降级（悄悄换便宜模型、悄悄丢掉一个来源）是最伤信任的一类问题：用户以为看到了全貌。

## 长任务：给出口

超过一分钟的任务，界面上必须同时存在三样东西：**当前进度**、**后台继续**、**放弃**。只能等不能停的任务，用户会在第二次使用时避开它。

后台化之后还需要「回来时能看到变化」：任务完成通知、结果摘要、以及「这期间发生了什么」的时间线。

## 多端一致性

同一会话在手机、网页、终端同时打开时，交互规则要明确：谁在「驾驶」、另一个人看到什么、接管时如何交接。没有显式接管机制时，两端会互相覆盖状态，用户看到的是随机结果。

租约 + 显式接管是常见做法：一端持有写权限，另一端只读；接管需要一次确认，接管后旧端自动降为只读。

## 该盯的指标

- 任务完成率与**首次成功时间**（不是总时长）。
- **每任务确认次数**：持续上升通常意味着确认设计失效。
- **误操作率**（点了同意但结果是错的）。
- 放弃率与放弃发生的步骤分布——放弃集中在哪一步，问题就在哪一步。
- 恢复成功率：中断后能继续完成的比例。

> 判断：交互设计的目标不是「让 Agent 显得聪明」，而是**在关键处保留人的控制权，其余时间不打扰**。判断一个交互是否合理，就问一句：如果这一步出错了，用户有没有机会在造成损失前拦住它。

## 常见反模式

- 每个工具调用都弹确认，用户很快开始盲点通过。
- 把完整思考过程实时倾倒给用户，信息量不等于可控感。
- 无限 spinner，没有任何阶段信息。
- 取消按钮只是关掉界面，任务仍在后台跑。
- 错误只说「失败了」，不说是哪一步、能不能重试。
- 进度条按动画走，与实际进度无关。
- 长任务没有放弃入口，也没有后台与通知。
- 多端同时写同一会话，状态互相覆盖。
