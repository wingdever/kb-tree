# 共识与决策：当多个 Agent 意见不一致

在多智能体系统中，分歧不是 bug 而是信息——两个专家 Agent 对同一推荐有分歧，说明案例不简单。问题是如何解决分歧：选一个、投票、辩论、还是评审。

## 三种共识模式

| 模式 | 做法 | 成本 | 优点 | 缺点 |
|---|---|---|---|---|
| **投票（Voting）** | 每个 Agent 投一票，多数（或加权多数）胜 | 最便宜，约 3× LLM 调用 | 快、简单；适合答案空间小（yes/no、A/B/C） | 信息损失；同源偏差的多个相同投票会给出错误答案且虚假自信 |
| **辩论（Debate）** | Agent 各执立场、多轮互评修订，可选裁判裁决 | 最贵，3 轮约 9× LLM 调用 | 暴露双方最强论点、产生可解释理由 | 贵、可能僵持；轮数过多立场极化反而固化错误 |
| **陪审团（Jury）** | 专家各出一轮分析（无互相争论），更强的裁判 LLM 读全部后裁决 | 中等，约 4× LLM 调用 | 角色清晰、成本可预测、借力裁判推理 | 上限取决于裁判；裁判有偏见则系统继承 |

**Self-Consistency（Wang et al.）** 本质是投票用于单 Agent 的多样采样——同一 CoT prompt 采样多次 + 多数决，GSM8K 准确率显著提升，不需要多 Agent，是性价比最高的"伪共识"。

**Debate（Du et al., arXiv:2305.14325）** 显示多 Agent 多轮辩论 + 裁判能提升事实类问答准确率；开源实现可参考 AutoGen group chat 或 LangGraph 双节点互评。2026 生产版通常把辩论封顶 2–3 轮。

**实践默认**：多数生产系统用 **jury**——比投票可靠，比辩论便宜得多。

## 方差问题（最重要）

共享相同先验的 Agent（同模型、相似提示、相似训练数据）会产生**相关答案**。五个都是相似提示的 GPT-5 投票，几乎不比单次调用好。修复方式——引入异质性：

- **异构模型**：混合模型家族（Claude + GPT + Gemini）。
- **异构提示**：改变框架（一个主张"支持"、一个"反对"、一个"怀疑者"）。
- **异构上下文**：给 Agent 不同的证据子集。

没有其中一种，多智能体共识只是 theater（表演）。

## 五种有效的协调模式

1. **辩论然后投票的混合**：固定 2–3 轮辩论，分歧持续则投票。辩论的知识丰富化收益 + 投票作为防止错误共识收敛的断路器。关键是限制轮数——不加限制的辩论会因谄媚性收敛降低准确率。
2. **加权置信度投票**：按领域专长或历史准确率分配投票权重。直接解决"更强 Agent 迎合较弱同伴"的失败模式。
3. **层级目标分解与专家仲裁**：规划 Agent 分解、专家 Agent 独立处理、评估 Agent 综合。让评估者用与专家不同的模型/提示配置，打破相关故障。
4. **结构化分歧升级**：不只取多数，而是对分歧分类——强分歧（引用矛盾证据）升级人工；弱分歧（措辞不同的相似答案）置信度加权合并；模糊分歧触发额外证据收集。
5. **检查点和回滚协调**：在战略里程碑捕获完整工作流状态（Agent 消息、工具调用、共享内存），协调崩溃时回滚到最后已知良好状态，而非修补损坏的共享上下文。

## 路由决策

- 分析性任务（代码审查、数学验证、逻辑验证）→ 独立生成 + 投票。
- 综合性任务（总结研究、构建知识图谱、细致回复）→ 迭代辩论达成共识。
- 最糟的做法：对所有事用同一种协议。

成本差异：共识协议约用单 Agent 5× token，投票约 10×。

## 何时升级到人类

2026 最佳实践是设置显式置信度阈值，低于阈值即升级：

- 投票票差很小 → 升级。
- 辩论 N 轮后无收敛 → 升级。
- 裁判在理由中表达不确定 → 升级。

## 常见误区

- ❌ 多数 = 正确：模型有共同盲区，一致性高不代表事实正确。
- ❌ 辩论让观点更客观：多轮辩论可能放大执念，为辩护而辩护。
- ❌ 共识 = 价值和稀泥：迭代到"都同意"常收敛到最平庸答案。
- ❌ 把串行传递当投票：后手能看到前手答案时独立性消失，投票失效（p<0.5 时投票只会放大错误）。
- ❌ 忽略答题者水平。
