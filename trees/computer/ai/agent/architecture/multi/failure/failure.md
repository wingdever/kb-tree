# 多智能体失效模式

多智能体系统不是靠"再加几个 Agent"就能修好的——失败有结构性原因。2026 年的规范做法是把失效模式当作一等设计输入：你的架构不算"够好"，直到你能对着每个类别说出部署了哪种缓解措施。

## MAST 分类法（Cemri et al., NeurIPS 2025, arXiv:2503.13657）

基于横跨 7 个流行多智能体框架的 1600+ 条标注轨迹（MAST-Data），并用 150 条轨迹由专家标注、标注者一致性 kappa 0.88 校验后归纳出 **14 种失败模式**，聚成三大根因：

| 类别 | 占比 | 示例 | 关键缓解 |
|---|---|---|---|
| **规格问题（Specification）** | 41.77% | 角色模糊、任务欠定、隐式成功标准 | 显式角色契约、验收测试、预飞规格检查 |
| **协调失败（Coordination）** | 36.94% | 共享状态未同步、消息丢失、状态漂移 | 带乐观并发的版本化状态、显式 ACK、周期性同步检查点 |
| **验证缺口（Verification）** | 21.30% | 未校验输出、信任链、缺失涌现行为测试 | 独立验证 Agent、交接契约、结果日志 |

14 种具体失败模式（另一套按通信/协调/质量的三栏组织）：

- **通信**：消息丢失（对 handoff 载荷做哈希）、误解（要求结构化格式）、信息过载（监控 token）、上下文过时（全部打时间戳）。
- **协调**：死锁（所有操作设超时）、竞态（handoff 编号）、角色混淆（单一职责身份）、权威真空（显式决策所有者）、资源争用（共享资源加锁/排队）。
- **质量**：橡皮图章式批准（要求具体引用）、错误级联（每个交接处验证）、LCD 输出（领域质量门槛）、群体思维（专家提示多样化）、回归（已完成章节不可变）。

## 群体思维家族（Groupthink, arXiv:2508.05687）

当 Agent 同质化或互相模仿时出现：

- **单质文化崩溃（monoculture collapse）**：相同基座模型 → 相关错误。三个 Agent 共享一个 LLM，就共享它的幻觉。
- **从众偏差（conformity bias）**：Agent 向最大声/最自信的同侪靠拢，即便对方是错的。
- **心智理论缺陷（deficient ToM）**：无法建模彼此的信念。
- **混合动机漂移（mixed-motive dynamics）**。
- **级联可靠性失败**：重试风暴——支付失败触发订单重试，订单重试触发库存重试，数秒内压垮库存服务（10× 负载）——需在每个出站调用处设熔断器。

记忆投毒：一个 Agent 的幻觉进入共享记忆，下游 Agent 当作事实，准确率逐渐衰减、根因诊断困难。

## 其他关键失败

- 在更简单的模式跑通之前上多智能体，只是装饰。
- 编排器失败在没有重试逻辑时不可恢复。
- 编排器过度拆解（尤其 Orchestrator-Workers 最贵）——给 worker 数量和预算设上限。
- 动态 swarm 缺乏确定性路由 → 对话乒乓，烧光 API 预算。受监管团队通常避免完全自主 swarm。
- 层级每多一层，延迟和成本相乘。
- 多 Agent spoofing 与级联失败：被攻陷的 Agent 把坏指令传给另一个 → Agent 认证、签名消息、不盲信上游输出。
- **成本本身就是失败模式**：五 Agent 系统可烧掉单 Agent 调用 10–50× 的 token，当 API 支出超过任务价值时即失败。
- **静默正确性失败**：看似合理实则错误的输出，异常日志捕获不到。

## 诊断顺序：先查哪一类

三类根因的排查成本不同，顺序错了会白烧时间。实用的顺序是从**最便宜可验证的地方**往上查：

1. **先查验证缺口**（21.30%）：交接处有没有独立校验？结果是谁判定通过的？这一类最容易补，且补上之后能让后面两类的问题暴露出来。
2. **再查规格问题**（41.77%）：每个 Agent 的职责、输入、验收标准是不是写下来的？占比最高，但改动最贵——往往要重写角色与任务对象。
3. **最后查协调失败**（36.94%）：状态所有权是否唯一、消息是否幂等、ACK 是否到位？这类问题通常表现为"偶发""复现不了"，只有前两类干净之后才看得清。

> 判断：多数团队一上来查协调（因为日志里全是超时与重试），但协调问题常常是规格不清的下游症状——上游没说清要什么，下游只能反复试探，于是表现为重试风暴。

## 缓解实践

- **STRATUS（NeurIPS 2025）**：把检测 / 诊断 / 验证拆成专门角色，报告能提升缓解成功率。
- 独立验证 Agent + 只读的独立数据源访问。
- 显式交接契约："A 的输出必须通过检查器 C，B 才能开始"。
- 结果日志供事后分析。
- MAST 审计应每季度而非每年运行——各类别会随系统成长而偏移。
- 植入慢故障代理（一致率、重试率、输出长度分布），在漂移显化前捕获。
- 结构化制品交换（MetaGPT 的实践方向）：用固定结构的产物代替自由文本，减少误解并留下审计轨迹。

## 一句话主线

多智能体的失败大多不是"模型不够强"，而是**规格、协调、验证三处的结构性缺口**；把失效模式当作设计输入，比再加一个 Agent 有效。
