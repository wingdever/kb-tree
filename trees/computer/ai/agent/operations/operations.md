# Agent 生产运维

这一组回答「上线后怎么跑稳」。Demo 与生产的差别不在功能，而在**可观测、可恢复、可限额、可隔离**这四件事有没有做实。

## 生产环境必须有的四样东西

1. **追踪**。每一次 run 都要留下可回放的记录：输入、工具调用与参数、结果、token 与延迟、最终判定。没有 trace，线上问题只能靠复现猜。
2. **信号**。质量、成本、延迟三条线各有阈值告警；只看错误率会漏掉「答得越来越差但还没报错」这类退化。
3. **恢复**。长任务要能在崩溃后续跑，靠检查点而不是重试整个请求；重试会重复副作用。
4. **边界**。用量配额、租户隔离、并发上限、单次任务预算——缺任何一项，一个异常调用就能拖垮整台机器或整张账单。

## 三条来自实践的判断

- **成本问题通常不是模型贵，而是循环次数多**。先查「平均多少轮、每轮带多少上下文」，再谈换模型。
- **质量退化往往先出现在长尾**。均值不变、P95 变差，是提示或检索开始失配的早期信号。
- **可恢复性与幂等性是一件事的两面**。做不到幂等的工具，谈恢复就是谈重复副作用；先把写操作做成可去重，再谈续跑。

## 与相邻方向的接缝

云端运行的会话、工作区、连接三层问题属于运维；多租户与配额也属于运维，而不是架构。判断一个系统是否「可运维」，标准是：出问题时能否在两小时内定位到具体一次 run、具体一次工具调用。

## 一句话主线

上线后靠 trace 定位、靠三线信号预警、靠检查点恢复、靠配额与隔离限损；成本先查轮次与上下文，质量先看长尾，恢复先做幂等。
