# Trace 回放与调试

线上问题最难的不是修，而是**先复现**。Agent 的失败很少稳定复现：模型有采样随机性、上下文巨大、外部工具状态一直在变。没有回放能力时，排查方式退化成「看日志猜」，而日志里通常没有模型当时真正看到的那份提示。

## 回放的合格标准

一条 trace 能不能回放，标准只有一句：**只靠它，能重建模型当时看到的每一个 token**。这意味着必须记录：

- **提示原文**：系统提示、工具 schema、检索片段、压缩后的历史——是渲染后的最终文本，不是模板加变量名。
- **模型参数**：模型名与版本、温度、top_p、最大输出、是否结构化模式。
- **工具层**：每次调用的参数、返回值快照、耗时、错误；不能只记「调用了 search」。
- **判定与状态**：这一步为什么继续、为什么停、检查点内容。
- **版本锚定**：提示版本、代码版本、工具版本——旧 trace 用新代码跑，行为本来就不同。

只记最终答案或只记自然语言日志，等于把可复现性丢在了采集环节，后面补不回来。

## 三种回放，目的不同

| 类型 | 做什么 | 花不花生成费 | 用途 |
|---|---|---|---|
| 事件回放 | 把记录的事件序列重新喂给前端 | 不花 | 复现用户看到的界面过程，查交互问题 |
| 执行级回放 | 用记录的工具结果重跑决策，工具调用打桩 | 只花模型费 | 定位「哪一步判断错了」，且不产生副作用 |
| 重生成 | 同一输入重新采样 k 次 | 花 k 次 | 判断失败是「偶发」还是「稳定」，量化方差 |

执行级回放是最有价值的一种：它把「环境不确定性」固定住，只留模型决策这一个变量，于是能干净地回答「当时信息都对，它为什么这么判」。

重生成则回答另一个问题：同样的输入跑十次错几次。错一次是采样运气，错七次是系统缺陷——这两种结论对应的修法完全不同。

## 差分：把「变差了」变成「从第几步开始分叉」

回放单独一条 trace 仍然要靠人读。真正省时间的是**成对对比**：

- 拿「好的一次」与「坏的一次」按步骤对齐（同一 step 序号 / 同一工具调用位序），逐段 diff 提示、工具参数、返回结果。
- 标记**第一个分叉点**：从这里开始两条轨迹不再相似，问题通常就在这一步的上游。
- 把分叉点归类：提示缺失、检索召回不同、工具返回异常、模型版本变了、上下文被压缩掉了关键段。

产品改动前后、换模型前后，都应该跑这种成对回放，而不是等用户投诉。

## 回放的环境要求

- **外部依赖必须打桩**。回放时真调外部 API，会重复副作用（发消息、下单），也会因为对方状态变化导致复现失败。录制-回放式打桩（把真实响应录下来，回放时按请求指纹返回）是标准做法。
- **时间与随机要可控**。固定时钟、固定随机种子，否则同一 trace 每次跑出不同结果。
- **数据要隔离与脱敏**。Trace 里有用户原文、检索到的私有文档；回放环境应当是独立沙箱，权限最小，且有保留期限。
- **存储要算成本**。全量提示与工具结果体量大，按「最近 N 天全量 + 更早只存摘要」分层，别让可观测性本身变成成本黑洞。

## 排查流程（可照抄）

1. 从告警或用户反馈拿到 `run_id`，拉出完整 trace。
2. 先看终止信号与最终判定，判断是「答错」还是「没答完」。
3. 执行级回放一次，确认能否复现；不能复现先查版本与外部依赖。
4. 能复现就逐步 diff 与成功样本，找第一个分叉点。
5. 定位到具体一步后，改提示 / 工具 / 检索，再把这条 trace 收进回归集。
6. 修完用同一 trace 回放验证，并跑全量回归确认没伤到别处。

第 5 步是关键：**每次线上事故都应该变成一条回归用例**，否则同一个坑会以不同外观再出现一次。

## 该盯的指标

- **坏 case 复现率**：报上来的问题里，能靠 trace 稳定复现的比例。
- **平均定位时间**：从拿到问题到锁定具体一步的时长。
- **回放保真度**：回放结果与线上结果一致的比例（不一致通常说明 trace 缺字段）。
- **回归集增长率**：事故转用例的速度，比事故数量更能说明工程成熟度。

## 常见反模式

- 只记录最终输出，失败后无法重建提示。
- 记录的提示是模板 + 变量引用，渲染结果没存。
- 回放时真调外部工具，制造重复副作用。
- 用当前代码回放三个月前的 trace，然后得出「模型变差了」的结论。
- Trace 里存了用户隐私原文，没有脱敏与保留期限。
- 只做单条回放，没有成对 diff，排查全靠肉眼读几百行 JSON。

> 判断：可观测性不是「有日志就算有」，而是「出事时能不能在半小时内锁定到具体一次工具调用」。达不到这个标准，就还停在猜的阶段。
