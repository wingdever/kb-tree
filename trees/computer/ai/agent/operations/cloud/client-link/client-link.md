# 客户端接入与传输

云端 Agent 的客户端看起来只是个聊天窗口，实际承担着四件事：把输入可靠送上去、把事件增量渲染出来、把本地文件桥接进来、把预览/端口暴露给用户。这四件事做不好，云端能力再强也会被体感拖累。

## 瘦客户端该做什么、不该做什么

**该做**：

- 输入采集（文本、语音、图片、文件选择与拖拽）；
- 事件渲染（流式文本、工具调用卡片、状态机、产物列表）；
- 本地文件桥（用户选择的文件上传，产物下载到本地）；
- 弱网处理（重连、断点续传、离线队列）；
- 轻量本地能力（剪贴板、通知、系统级权限）。

**不该做**：

- 业务规则（配额、权限、路由、工具选择）——放客户端会导致多端行为不一致；
- 会话状态权威——客户端只是视图，服务端才是真相；
- 长期凭据——客户端应拿短期令牌，凭据续期走服务端。

## 传输怎么选

| 方式 | 适用 | 注意 |
|---|---|---|
| WebSocket | 双向高频：用户输入、流式输出、状态事件 | 需要自己设计心跳、重连与消息序号 |
| SSE + HTTP 上行 | 下行单向流、上行用普通请求 | 简单、易穿过代理；上行延迟略高，双向交互不顺手 |
| gRPC streaming | 内网、强类型客户端、双向流 | 浏览器直连成本高，通常要网关转换 |
| 长轮询 | 受限网络、老客户端兜底 | 延迟与资源开销大，只作降级路径 |

选择的关键不是技术先进，而是**这条链路上有多少中间设施**：企业代理、CDN、移动网络对长连接都不友好，能穿过才有意义。

## 事件协议的三条硬要求

1. **带序号**：每条事件单调递增，客户端记录处理位置，重连时按序号补发。
2. **可区分类型**：文本增量、工具调用、工具结果、状态变更、错误、产物，各自有明确类型；混在纯文本里会让客户端无法做结构化渲染。
3. **可终止**：明确的心跳与结束标记，避免界面永久停在"正在输入"。

## 多端接入：观察者与写者

- 一个会话允许多端观察，但同一时刻只有一个写者，靠**租约**（lease）实现，租约带过期时间。
- 切设备时走显式**接管**流程：新端申请、旧端收到"已被接管"、租约转移。静默抢占会让旧端用户以为自己还在输入。
- 输入归属要可见：界面上标明"当前由哪台设备控制"，避免两端同时打字造成交错。
- 移动端的现实约束：后台容易被系统挂起，重连要快、状态要能从快照重建，不能假设长连接常驻。

## 文件与预览

- **上传**：分片 + 断点续传 + 哈希校验；大文件不要塞进消息体，走对象存储与签名 URL。
- **下载产物**：清单（路径、大小、哈希）+ 临时签名链接，过期即失效。
- **端口预览**：云端跑起来的服务要能被用户看到。做法是网关分配一个带租户与会话绑定的临时子域或路径，鉴权在网关做，链接短生命周期；不能把运行时端口直接暴露到公网。
- **剪贴板与截图**：移动端/桌面端体验差异大，能降级就降级（无剪贴板权限时退化为文件上传）。

## 弱网下的三条细则

- **上行串行、下行合并**：同一会话的输入按顺序发，不能因为重试把两条输入乱序；下行的高频增量可以合并成批，减少渲染抖动。
- **乐观渲染要能回滚**：本地先把用户消息显示出来，服务端拒收（超限、鉴权失败）时必须撤回并提示，而不是"显示了但没发出去"。
- **离线队列有上限**：离线时缓存输入，但要有条数与体积上限，并明确"这些消息尚未发送"的状态。

## 重连为什么要重新鉴权

重连不是"把 socket 接回去"这么简单，它是一次新的接入：

- 短期令牌可能已过期，重连时要静默续期，续期失败则要求重新登录；
- 租约可能已被别的设备接管，重连要重新申请而不是默认自己还是写者；
- 旧连接不能"幽灵存活"——服务端要以租约与连接双条件判定，防止两端都以为自己能写。

> 判断：把重连当成一次全新接入来设计，能顺手解决令牌过期、租约被抢、旧连接残留这三类问题；把它当成"恢复旧连接"，这三类问题会各自变成线上事故。

## 常见失败模式

- 客户端缓存了会话状态并当作真相，服务端状态变化后界面自相矛盾。
- 事件不带类型，工具调用只能以文本形式展示，用户看不出"它在干什么"。
- 没有心跳，界面卡在"生成中"几十分钟，用户以为死了。
- 多端无租约，两端同时发消息，工具调用交错执行。
- 预览链接永久有效且不带鉴权，等于把内部服务挂到公网。
- 大文件走消息通道，内存与带宽双爆。
- 客户端持有长期 token，设备丢失即长期风险。

## 什么时候可以简单

单端、桌面浏览器、网络稳定、任务短：一个 SSE 下行 + POST 上行就够用，不必上 WebSocket 与租约。复杂度只在"多端 + 弱网 + 长任务"同时出现时才必须付。

## 一句话主线

客户端的职责边界只有一句话：**它是视图与输入口，不是真相来源**；会话状态、业务规则、长期凭据都留在服务端，客户端只负责把事件渲染得让人看得懂、把输入送达得让人放心。
