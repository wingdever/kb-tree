# Agent 产品形态

同样是"能对话、能干活"的产品，形态差别决定了三件事：任务在哪里执行、它能碰什么权限、按什么方式收钱。先把形态分清，再谈能力对比，否则会把聊天助手和云端执行体放在同一张表里比。

## 五种形态

| 形态 | 执行位置 | 典型能力 | 计费特征 |
|---|---|---|---|
| 对话助手 | 模型侧，无持久环境 | 问答、写作、检索、总结 | 订阅或按 token |
| 执行型 Agent | 用户设备或厂商云端 | 点按、填表、跨应用操作 | 订阅 + 额度 |
| 工作流编排 | 平台侧，按步骤调度 | 多节点、定时、批处理 | 按任务或按席位 |
| 嵌入式系统助手 | 设备系统内 | 语音、意图识别、跨应用调度 | 随硬件，不单独计费 |
| 托管常驻 Agent | 厂商云端独立实例 | 7×24 运行、定时巡检、长任务 | 订阅含机时或按量 |

对话助手与执行型 Agent 的分水岭是**有没有"手"**：能否在没有 API 的界面上完成操作。执行型与托管常驻的分水岭是**环境归谁**：跑在用户机器上，关灯就停；跑在云端，关机也继续。

## 形态决定的三件事

1. **权限边界**。嵌入式助手能读系统级信息（通知、联系人、位置），对话助手只能读你贴给它的内容；权限越大，合规要求越硬。
2. **失败代价**。执行型 Agent 会真的点击、下单、发消息，所以需要确认点与回滚；对话助手说错话只是答案错。
3. **成本结构**。常驻型按"机时 + 模型调用"双计费，聊天型只有 token；前者闲置也烧钱，后者闲时为零。

## 怎么按任务选形态

- 任务几分钟内完成、只处理文本：对话助手足够，别为它买云机。
- 任务要跨应用点按、且必须在你自己的账号与文件上完成：执行型 Agent，跑在本机更合适。
- 任务要跑几十分钟到几小时、你还会关电脑：托管常驻，或自带云电脑的 Agent。
- 任务要定时、批量、多步骤且需要审计：工作流编排，而不是让单个 Agent 硬扛。
- 任务发生在手机系统层（来电、通知、日程）：嵌入式助手，独立 App 做不了。

## 常见误判

- **把"能调用工具"当成执行型**。工具调用是 API 层面的动作，不等于能操作图形界面。
- **把远控本机当成云电脑**。手机连自己电脑，算力与在线状态仍依赖本机。
- **把工作流平台当成 Agent**。编排是调度，决策仍靠节点里的模型或人。
- **忽略形态对定价的影响**。同一个任务，跑在云机上和跑在对话接口里，成本差一个数量级。

## 一句话主线

形态不是包装，而是**执行位置 + 权限范围 + 计费方式**的组合；先确定任务要在哪台机器上跑，再决定买哪种产品。
