# 多智能体系统

多智能体不是默认选项。**单 Agent + 工具是基线**，是每个设计都应拿来对比的诚实起点。只有当单个工具齐备的 Agent 不够用时，才拆分。

本目录把多智能体拆成 9 个子知识点，每个自成一个目录、目录内放同名介绍 md。

## 子知识点目录

| 目录 | 内容 |
|---|---|
| `design/` | 要不要拆、怎么拆、确定性 vs 自主性光谱、判断清单、成本意识 |
| `arch/` | 五种架构（监督者/流水线/并行/网络/创建者-验证者）、补充模式、四阶段请求流 |
| `orchestrator/` | 最常用的模式：监督者/管理者变体、层级扩展、与并行化的区别 |
| `handoff/` | handoff 三要素、框架内通信 vs 跨框架、共享状态、通信可靠性 |
| `a2a/` | Agent2Agent 协议：Agent Card、task 生命周期、与 MCP 的关系、安全 |
| `building/` | 可靠系统的五大模块：角色、schema、工具注册表、上下文隔离、HITL 门 |
| `consensus/` | 投票/辩论/陪审团、方差问题、五种协调模式、升级人类 |
| `failure/` | MAST 分类法、群体思维家族、重试风暴、缓解实践 |
| `frameworks/` | LangGraph/CrewAI/AutoGen/OpenAI Agents SDK/ADK 的编排模型与取舍 |

## 建议阅读顺序

判断：`设计判断` → `架构模式` → `编排器与执行器` → `交接与通信` → `A2A协议`。工程：`构建模块` → `共识与决策` → `失效模式` → `框架实现`。

## 一句话主线

先判断单 Agent 是否真的不够（设计判断），选一个架构模式（架构模式），确定谁拥有对话与控制权（编排器与执行器），设计 Agent 之间怎么传信息（交接与通信 / A2A），用五大模块保证可靠（构建模块），需要处理分歧时用共识机制（共识与决策），并对照 MAST 提前防失败（失效模式），最后落到具体框架（框架实现）。
