# kb-tree

离线 Markdown 知识树仓库。仓库可容纳多棵树，每棵树独立放在 `trees/<树名>/`。本文件说明仓库结构与知识树的组织与维护规则；知识内容由各树内的文档承载。

## 结构

- `trees/<树名>/` — 一棵知识树，树内只放知识文档，不放规则文档。当前收录 `trees/computer/`（技术与工程知识）与 `trees/vendor-entity/`（AI 服务商经营主体）。
- `skills/` — 可直接加载的 agent 技能，属工具目录。

## 组织规则

- **每个节点 = 一个目录 + 目录内同名 md**。根节点也有同名 md。
- **知识文档 vs 规则文档**：同名 md 讲知识点本身是什么；本文件只讲组织与维护规则。二者分工不同，不要混淆。
- **命名**：所有目录与文件名一律小写英文短名 / kebab-case，中文全称放 front matter 的 `名称` 字段，不进路径。
- **front matter**：每个 md 顶部四字段 `description` / `描述` / `name` / `名称`，值用双引号。
- **节点不互链也不互引**：每份文档自足陈述，不提及其他节点——不放相对链接，不写 `> 相关：…` 引用行，也不写「见某某节点」的文字点名。层级由目录结构表达。
- **子节点**：子节点放在父节点目录下继续嵌套，层级不限；父文档不列子节点链接表。
- **工具目录例外**：`skills/` 目录存放可直接加载的 agent 技能，属工具文件而非知识节点，不适用四字段 front matter 与同名 md 规则，也不在知识文档里登记。

## 一致性巡检

- `skills/kb-tree/scripts/lint.py` 检查结构、front matter、跨节点引用、操作痕迹、可疑数字、跨页重复断言与 `questions.jsonl` 字段。
- 用法：`python3 skills/kb-tree/scripts/lint.py trees/computer/ai/agent`，`--strict` 时警告也判失败。
- 错误（E）必须修；警告（W）逐条判断——论文引用的数字可以保留，自己估的数要么标成判断、要么删掉。
- 数字警告逐条判断后，把核对结论写进 `skills/kb-tree/references/number-sources.json`（路径 + 页面上的原始数字 + 核对来源），巡检即不再报该数字；没把握核实的不要登记，改写成定性表述。
- 纯归纳、纯经验或资源索引页确实没有外部来源时，把路径登记到 `skills/kb-tree/references/no-source-pages.json`，巡检不再要求该页写「参考资料」；一旦补了来源就把它移出清单。

## 维护规则

- 新知识点按"目录 + 同名 md + 四字段 front matter"建立，放入父节点目录；父文档不放链接或登记表格。
- 扩展子节点时优先补抓权威一手资料；来源如何交代见「来源与署名」。
- 易变的数值、名称与接口形态变化快，落地前对照一手资料。

## 来源与署名

早先的规则是「第三方资料不写来源关系」。公开仓库不能靠省略来源回避版权，也不能让读者无法核对，因此改为**一律交代**。

**一、三类内容，三种交代方式**

| 内容 | 交代方式 |
|---|---|
| 官方规范、API 文档、论文 | 文末「参考资料」给链接，并写清版本与年份（如「A2A 官方规范 v1.0 及 1.x，2026 年版」） |
| 他人观点、博客、教程、厂商公告 | 写清作者或机构 + 原链接；引用具体数字或结论时写明出处 |
| 本库自己的归纳与工程判断 | 明确标出，不冒充他人结论 |

第三条最容易被忽略：大量页面是对多份资料的重组，其中的取舍、优先级、「常见误区」属于本库判断，不是某家厂商的官方口径。

**二、判断要标出来**

- 段落级判断用引用块开头：`> 判断：…`，并在其后一句话说明依据（哪类资料、什么条件下的经验）。
- 句内判断写明「按经验」「本库归纳」「多数团队的实际做法是」。禁止把判断写成「官方认为」「业内共识」。
- 官方口径与社区口径冲突时，两句都留，并注明各自来源；不要合并成一句看似无争议的话。

**三、数字必须可核**

价格、榜单分数、星标、模型名、上下文长度、限流阈值这类随时变化的值：写数字就带采集时间与来源（`2026-11 官方定价页`）。拿不到来源时，写量级与判断，不写精确数字。

**四、链接怎么选**

- 优先官方域名、规范permalink、`arXiv`/DOI；仓库用 `owner/repo`。
- 不写短链、搜索结果页、带追踪参数的链接、需要登录才能打开的链接。
- 一手资料本地区被拦截时，说明这一点，再用可访问的镜像或多来源交叉核对，不要假装直接读过原文。
- 链接失效：优先补存档或更新到新地址；确实拿不到固定链接时，退化为「机构 + 文档名」，不凭空补一个像样的 URL。

**五、位置与格式**

`## 参考资料` 放在正文最后一级，正文之后直达，每条一行：

```markdown
## 参考资料

- A2A 官方规范（v1.0 及 1.x）：https://a2a-protocol.org/latest/specification/
- DeepSeek-V3 技术报告（arXiv:2412.19437）：https://arxiv.org/abs/2412.19437
```

- 每篇 1–5 条，只列真正支撑正文的来源，不做书单堆砌。
- 条目按重要性排序，官方规范在前、社区资料在后。
- 纯资源清单类页面（正文本身就是链接表）不重复列出，避免同一条地址出现两次。
- 正文里已经嵌入的接口地址（如端点、SDK 调用）不必搬进「参考资料」。

**六、自检清单**

新增或修改页面时对着过一遍：

1. 文末有没有「参考资料」，或明确说明本页无外部来源？
2. 每个具体数字，能不能在条目里找到出处？
3. 有没有把本库的判断写成官方结论？
4. 有没有引用他人结构、措辞、图表而未署名？
5. 链接是否指向稳定的官方地址，而不是搜索结果或短链？

## 引用本库

转载、摘编或作为资料引用时，请保留仓库地址与本页最后修改时间，并注明「内容来自 kb-tree（链接）」。本库基于多份公开资料整理，其中的工程判断不代表任何厂商的官方立场。

## 新增知识树

在 `trees/` 下新建以树名命名的目录，按上述规则建立根节点同名 md、领域目录与知识点子树。
