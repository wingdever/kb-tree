# object.json — 节点的对象坐标

每个节点目录可放一份 `object.json`，用一个三元组登记"这个节点讲的对象到底是什么"。它不是知识节点，不套四字段，属 C 层附属文件，缺失合法。

```json
{
  "realm": "material",
  "kind": "thing",
  "generality": "particular",
  "canonical": "上海七牛信息技术有限公司",
  "volatility": "high",
  "verify": "国家企业信用信息公示系统"
}
```

## 三个坐标

### realm：靠什么存在

| 值 | 判据 | 典型对象 |
|---|---|---|
| `logical` | 不占时空，靠定义与推理成立；问"在哪、何时"没有意义 | 数、集合、命题、定理、类型、关系类型、过程类型 |
| `material` | 占时空，有因果作用力；能指出地址、时段或物理载体 | 人、组织、服务器、工厂、印刷册、物理事件 |
| `symbolic` | 靠符号载体存在，可复制、有版本；内容可脱离某一副本而同一 | 文本、代码、公式、符号串、图表、虚构角色 |

逻辑界与符号界的差别：**数是逻辑界的，数字"0"这个记号是符号界的；定理是逻辑界的，写着定理的论文是符号界的。**

### kind：在节点里扮演什么

| 值 | 判据 | 例子 |
|---|---|---|
| `thing` | 有同一性、能被指认的"东西" | 张三、上海七牛、这份条款、自然数 |
| `event` | 有起止或时点，"发生了什么" | 张三打李四、ANT 上市、这次发布 |
| `relation` | 必须依附两端才成立，本身不是东西也不是事 | 持股关系、雇佣关系、引用关系 |

### generality：是一个还是一类

| 值 | 判据 | 例子 |
|---|---|---|
| `particular` | 能指"这一个/这一场/这一版" | 张三、0、这一版服务条款 |
| `type` | 只能指"这一类/这种"，可被实例化或重复 | 人类、自然数、隐私政策、并购 |

三轴交叉最多 18 格，空格正常，不必填满。

## 判定顺序

1. **靠什么存在**：定义与推理 → `logical`；占时空 → `material`；靠符号载体 → `symbolic`。
2. **扮演什么**：东西 → `thing`；发生 → `event`；两端之间 → `relation`。
3. **能不能指"这一个"**：能 → `particular`；只能指"这一类" → `type`。
4. 最后填 `canonical`、`volatility`、`verify`。

## 硬规则

- **按节点回答的问题的主语判**，一个节点只给一个三元组；主语跨格就拆节点，不在同一页混写"这个东西是什么"和"这次发生是什么"。
- **符号界的 particular 指"这一版内容"，不指"这一份拷贝"**：讲文件落在哪个磁盘归 `material/thing/particular`，讲内容属于 2026 版归 `symbolic/thing/particular`。
- **组织归物质界，登记与章程归符号界**：公司有地址、人员、资产；营业执照、章程、登记记录是符号文本。不要因为"公司靠登记存在"就把公司判成符号界。
- **虚构对象归符号界**：角色、世界观、设定由文本创造并随版本变化；这是它和数据、定理的根本区别。
- **关系类型归逻辑界，具体关系随两端**：抽象的"雇佣关系"是 `logical/relation/type`；张三与某公司这一段雇佣关系归 `material/relation/particular`；两份文档之间的引用关系归 `symbolic/relation/particular`。
- **状态算发生**："账户当前欠费"有持续时段，归 `event/particular`；"降级状态"作为一类情形归 `event/type`。
- **未发生的事归 type**："计划中的上市"在发生前是 `event/type`；挂牌那一刻起才有 `event/particular`。
- **particular/type 不是类继承**：`instance-of`（0 ∈ 自然数）与 `subclass-of`（人类 ⊑ 动物）是两种关系，类层级与属性组合无法替代个体身份。

## 字段

| 字段 | 作用 |
|---|---|
| `realm` / `kind` / `generality` | 三轴坐标，值为上表枚举，全小写 |
| `canonical` | 对象的权威名称或标识（全称、统一社会信用代码、DOI、ISBN） |
| `volatility` | `high` / `medium` / `low`，决定复查频率；物质界实体与额度类通常 high，逻辑界 low |
| `verify` | 核实渠道（官方文档、登记系统、标准文本） |

## 常见误标

- **把页面标题当对象**："免费额度"是属性不是对象，先问"哪个对象的额度"。
- **把品牌当法人**：品牌是符号界的名称，签约主体是物质界的组织。
- **把载体当内容**：文件、磁盘、印刷册是载体；条款、代码、版本是内容。
- **把类型当个体**：人类、公司、隐私政策是 type；张三、上海七牛、这一版条款是 particular。
- **把关系塞进一端**：持股、雇佣、引用是两端之间的关系，不能只写在某一端节点里而不说明另一端。

## 与树结构的关系

`object.json` 只登记坐标，不建立节点间链接，不替代目录层级，也不参与"节点不互引"的约束。同一棵子树里大部分节点落在同一格是正常的——它说明该子树的对象类型同质，不代表标注失败；区分力不足时应先审视对象粒度，而不是加轴。
