# links.csv 编写与校验规范

每个知识节点目录放一份 `links.csv`，登记**本页正文里出现的词，与它所指向的另一个知识节点对象**之间的对应关系。它是 C 层附属文件：不是知识节点，不套四字段 front matter，不计入“目录 + 同名 md”自检。

它解决的问题是：正文按规则必须自足、不点名其他节点；但读者和检索程序仍需要知道“这句话里的某个词，其实是在讲另一个节点所描述的对象”。把这种对应放在独立文件里，既不破坏正文自足，又能生成对象级链接图。

## 文件形态

- 文件名固定 `links.csv`，UTF-8，首行必须是表头 `term,target`。
- 每个节点都要有；没有可登记的链接时，只写表头，空表合法。
- 一行一个对应关系，字段用英文逗号分隔；字段本身含逗号时按标准 CSV 加双引号。

| 字段 | 必填 | 说明 |
|---|---|---|
| `term` | 是 | 本页正文中**原样出现**的词或短语，大小写与空格保持原样 |
| `target` | 是 | 被引用对象所在节点的目录路径，相对**仓库根**，用 `/` 分隔，如 `trees/computer/ai/rag` |

`target` 指向目录而不是 md 文件：目录才是对象，md 只是对该对象的一份描述。校验时要求该目录下存在同名 md。

## 规则

1. `term` 必须能在同级同名 md 的正文（`## 参考资料` 之前）里逐字找到；找不到说明记录的不是“本页用到的词”。
2. `target` 必须存在、必须是知识节点目录，且不能指向当前节点自己。
3. 同一个 `term` 可以指向多个不同对象（词有歧义时分行登记）；同一对 `(term,target)` 不能重复。
4. 只登记“词 → 对象”，不登记段落、句子或主观关系断言；关系语义留在正文里。
5. `links.csv` 不替代正文的“不互引”规则：正文仍不写相对链接、不写「参见某某节点」，也不写子树导航。

## 例子

```csv
term,target
RAG,trees/computer/ai/rag
向量数据库,trees/computer/ai/rag/vdb
Seedance,trees/computer/ai/free-credit/gen-apis
```

这三行表示：本页正文出现了 `RAG`、`向量数据库`、`Seedance` 三个词，它们分别指向三个节点所描述的对象；不表示本页与这些节点存在上下位、因果或推荐关系。

## 校验

`python3 skills/kb-tree/scripts/lint.py <根>` 会检查：文件是否存在、表头是否为 `term,target`、`target` 是否为存在的节点目录、是否自指、`term` 是否在本页正文出现、`(term,target)` 是否重复。错误会阻断巡检；空表只报 0 条，不报错。
